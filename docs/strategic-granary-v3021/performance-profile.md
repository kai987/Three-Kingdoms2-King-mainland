# 性能采样

用实际观战输出来定位四个检查点，保留固定的起点状态、命令列表和天气。CPU 时间用进程时钟，墙钟受并行负载影响。详细档打开天气与战略观测钩子，累计请求编码、九旬预测、候选评估、口粮报价、路线对数和峰值内存。该档计入钩子及状态构建，完整 CSV/GZIP 导出开销以整局观战单独报告。

黄巾 212 冬季起始检查点的 cProfile 跟踪显示，一次 G1 回合中进行了 2,588 次请求编码。时间主要花在筛选过的路图中反复编码、调用和评估同样的行军路段。G2 的同一轮测得 1,458 次编码，补给路线批处理口径下的 CPU 从约 0.383 秒降至约 0.119 秒。战斗与城市预算也占据部分时间。一次分析采样不能代替四处九旬配对的 P95。

固定存档数据见 `fixed-state-performance.csv` 及 `route-cache-profile.csv`，观战 CPU、天气及计划候选比较见 `performance-comparison.csv`。
