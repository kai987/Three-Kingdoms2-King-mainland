# 接敵AIの評価と兵士戦の校正記録

基準コミット：`94f813e0d6bed3549d35f13a1e2f1dc45491bdc1`。これは現在の実装を調べた記録であり、原作AIの判断全体を復元したという主張ではありません。この調査ではROM・ユーザーのゲーム・セーブを操作していません。戦闘計算、AIの重み、保存形式も変更していません。

## 比較する時間範囲

次の三つを分ける必要があります。

1. **指定した兵隊の一撃／一撃と応戦**：誰が、どの兵種・人数で、誰を攻撃するかを固定した計算です。
2. **兵士戦の1巡**：歩兵・弓兵・騎兵・主将の実際の処理順と、騎兵・主将の2回行動を含みます。戦場の1日や、戦略の1旬ではありません。
3. **接敵から交戦終了まで**：陣形、逐隊命令、移動、城壁、撤退、単挑など、後続の操作で長さと結果が変わります。

現在の `tactical_ai.expected_attack/expected_contact_exchange` は、旧式の「全軍に対する一撃と、残存兵による一度の応戦」を評価します。現代戦場で攻撃を実行すると、最初からその損害を与えるのではなく、継続する兵士戦へ入ります。したがって、下表の異なる時間範囲を割り算して「交戦全体の予測誤差」とすることはできません。

## 共有されている実計算

- [戦闘入口](../source/remake/campaign_expansion.py)の `_execute_attack` は、隣接・機動力を確認し、対象の移動拘束解除と伏兵処理を行ってから `siege.begin` に入ります。
- [戦場判定](../source/remake/battle_grid.py)の `encounter_context` は通常の接敵を野戦、実際の原地形クラス5にいる部隊との接敵を城砦戦として扱います。都市の戦略地形だけでは城壁を付けません。
- [兵士戦サービス](../source/remake/siege.py)の `attack_base/soldier_damage/_hit` が実際の損害を計算します。最初の命中時だけ、攻守それぞれ `next()%9` を1回ずつ取り、両軍の攻基を保存します。同じ交戦の後続の命中はその攻基を使います。
- 原算式の固定証拠は[6502入出力資料](../tools/siege-original/soldier-rules-reference.json)にあります。攻基126件・損害2,080件を[既存の算術試験](../tests/test_remake_soldier_rules.py)が照合します。今回の調査はこの資料と現在のPythonサービスを読み、ROMを実行していません。
- [旧AI評価](../source/remake/tactical_ai.py)は90～110の21通りを平均します。既存の「予測と実損害が一致する」試験は、明示的にグリッドを除いた旧数値カーネルの試験です。兵士戦全体の期待値を保証する試験ではありません。

原算式の後に置く訓練度・守護、共有乱数の採用、撤退や包囲の一部は本作の既定ルールです。詳しくは[兵士戦の説明](soldier-combat.md)を参照してください。

## 有限個の実サービス入力

ローカル調査では、明示した受理値 `0..8` の組を均等に列挙しました。

- 指定した命中と任意の応戦：**16条件 × 81組**。実際の `siege._hit` を呼び出しました。
- 固定した兵士戦1巡：**7条件 × 81組**。実際の `siege._step_turn` を呼び出しました。
- 配兵構成：実際の `siege._deploy` による**4条件**。

一方の最初の一撃だけなら異なる攻基は9通り、両軍の攻基の組は81通りです。これは未来の戦役乱数を読む方法ではありません。また、原作乱数や連続する `SeedRng%9` が独立・均等であると証明したものでもありません。

以下は武80対80、訓練度70、満員100人の兵隊を基本とする制御入力です。装備ID 0にも実際の威力があります（武器3・防具2）。「未装備＝0」と読み替えていません。単独の騎兵などの入力は兵種計算の検査用であり、その兵種が原配兵表の先頭に自然登場するという意味ではありません。

| 固定した一撃／応戦 | 相手の兵損平均 | 自軍の応戦による兵損平均 |
| --- | ---: | ---: |
| 歩兵→歩兵、一度ずつ | 49 | 218/9 |
| 弓兵の近接→歩兵、一度ずつ | 29 | 305/9 |
| 弓兵の遠射のみ | 305/9 | 0 |
| 歩兵→騎兵、一度ずつ | 325/9 | 305/9 |
| 14人の歩兵→100人の歩兵 | 85/9 | 14 |
| 15人の歩兵→100人の歩兵 | 173/9 | 15 |

同じ100人・武80の旧式評価は、兵種や射程を区別せず、概ね相手23.523810人・自軍18人です。14人と15人の攻撃側も、ともに相手3人と評価します。実際の兵隊人数の段階境界とは一致しません。

実際の1巡では、さらに次の違いがあります。

| 固定した兵士戦1巡 | 相手の兵損平均 | 自軍の兵損平均 | 実際の行動順 |
| --- | ---: | ---: | --- |
| 歩兵対歩兵 | 49 | 218/9 | 自軍→敵軍 |
| 弓兵対歩兵 | 128/9 | 49 | **敵歩兵→自軍弓兵** |
| 歩兵対弓兵 | 49 | 128/9 | 自軍歩兵→敵弓兵 |
| 歩兵対騎兵 | 325/9 | 610/9 | 自軍1回→敵軍2回 |
| 騎兵対騎兵 | 650/9 | 250/9 | 自軍2回→敵軍2回 |
| 2マス遠射対待機歩兵 | 305/9 | 0 | 自軍の遠射のみ |
| 歩兵対旧混乱フラグ1の歩兵 | 49 | 0 | 自軍のみ |

同じ武80・1,000人でも、実配兵表は段階0なら歩5・弓3・騎2、段階7なら歩0・弓4・騎6です。段階0の城砦側は歩0・弓8・騎2になります。旧式評価にはこの違いが入りません。

主将への命中も「兵損」と分けます。今回の固定入力では、防具威力2→12で主将の体力損失平均が200/9→110/9に変わり、その一撃による兵損は0でした。一方、体力2の主将への命中では、体力が1になり、その配下1,000人が敗走しました。通常兵への損害に一つの係数を掛けるだけでは両者を表せません。

## 今後校正する場合の境界

最小の共有化候補は、**明示された一撃の純粋計算**です。攻基、当該兵隊の人数または主将体力、双方の兵種、射程、実装備、訓練度、守護残数、対象の人数・体力上限を入力し、体力と兵損、守護消費、主将敗走を区別して返す範囲なら、実サービスと期待値側で共用できます。保存中の攻基があれば、その一撃に将来の攻基乱数は不要です。

ただし、接敵前のAIには、まだプレイヤーが決めていない陣形や逐隊命令がありません。陣形の仮定、人間の選択の平均、評価期間の設定は別途明示する必要があります。それらを原作の損害表から自動的に導けるとは扱いません。今回、換算係数・新しいAI重み・交戦全体の予測値は設定していません。

将来の実装時も、旧数値カーネルの試験と歴史的固定出力を残し、現代戦場への接続だけを分離します。最初の実命中だけ2回抽選すること、攻基の保存継続、閲覧・候補列挙の無乱数・無変更、プレイヤーとAIの同一計算、体力1の敗走、0損害、人数境界、兵種順序、2回行動、野戦／城砦差を個別に検証する必要があります。自然戦役の途中保存も観測し、制御入力の試験を「全29劇本の交戦全体を完走した検証」と言い換えません。

今回のローカル記録は `/tmp/tk2-phase10-contact-audit/` に置き、巨大な制御入力資料をリポジトリへ追加していません。調査前後で関連8ファイルのSHA-256は一致しました。共有兵士算式の固定資料SHA-256は `3120cfc4fedc24baf87dc52f986a23823220a55960891dcdd3a24940ee9bc0b2` です。

目前AI仍用整支部隊的一次傷害與一次反擊估算，真正接敵則進入按兵隊順序結算的持續兵士戰。16×81組實際命中／應戰、7×81組實際單巡及4組配兵檢查顯示：兵種、餘數兵隊、主將體力與裝備、城砦、騎兵兩次行動均會改變結果，不能只乘上一個修正係數。以上明確區分單次命中、兵士戰一巡及整場交鋒；沒有讀取未來亂數、執行ROM、改動戰鬥規則或新增AI權重。後續若實作，應先共用單次命中的純計算，再明確定義AI評估的時間範圍。
