# 險道、季風與海路探索

目前各劇本共用下列使用者指定規則。距離使用地理座標及海陸路線，與畫面縮放無關；平地基準每天 30 公里，每旬固定 10 日，每月 30 日，抵達回合數為 `ceil(日數 / 10)`。預覽不抽亂數。

## 行軍日數與口糧

出征、友城調動與運輸隊共用按日口糧，每天依當時士兵、隨行武將及運輸預備兵計算：

```
每日人數單位 = 當天兵數 + 100 × 隨行武將數 + 當天運輸預備兵
糧足時累計耗糧 = ceil(各日人數單位合計 / 1000)
```

普通出征／調動的運輸預備兵為0。出發先從來源城備至下一座本方城，途中依友城庫存補足下一段；無可補給友城才預裝全程，空城不能補糧。預裝是庫存轉為隨軍糧，與運輸貨物分開，並非已全部消耗。小數餘額跨日繼承，兵數不變時等同按累計日數取整；例如900兵、1將且全程糧足走21日，共消耗21糧，三旬依序10、10、1糧。已付糧的部隊抵達開戰不重收出征費，重複AI或抵達請求也不重扣。

距離、地形與季風已反映於路程日數，長路、山路或逆風會增加備糧。預覽不預抽天候亂數；等待補給、滿城候位及等候會合仍每天耗糧，正常抵達的最後不足10日則只計真正路程。畫面分開顯示實際前進日數、等待日數、餘糧、缺糧及減員。

道路途中缺糧時先到下一實際節點；節點備糧不足則停止正常前進，每日各隊士兵及運輸預備兵損失1%向上取整，不殺武將。連續10日缺糧於旬末觸發實際撤退，返程仍需時間、仍吃糧，缺糧返回也可能繼續減員。餘糧不足不能變成負庫存；新的減員與撤退不額外抽亂數。

可由本方城派送糧隊，親自到達目標部隊當前或後續的同一城市節點，接觸後才交付；道路中段不瞬移補糧。押運人員保留原城席位，卸貨後自動實際返回，不占目的城武將定員。返程先使用貨物兵糧及上一程未耗口糧，途經友城依庫存補給，沒有免費遠端補糧。口糧進度、供糧來源、每日損兵及往返歷程隨當前存檔保存並驗證；仍只接受目前劇本SHA及目前補給／運輸格式。

## 出陣備糧與戰鬥耗糧

出陣時可另選「戰鬥備糧」，與首段行軍糧合計從來源城真實庫存裝載。預設備30戰鬥日，但不強迫滿額：預設值為 `min(30日需要量, 城內兵糧－首段行軍糧)`，最低為0；玩家可改值或按最大值，最高不得超過扣除行軍糧後的可用庫存及隨軍糧上限。友城調動、轉屬與運輸不加這筆戰鬥預算。預覽及反覆切換武將不扣糧，也不抽亂數。

抵達敵城時，行軍未耗完的隨軍糧及小數口糧餘額直接移交攻方戰鬥帳本，來源城不再收費。守方從戰場城現有庫存裝載最多30日所需糧，庫存不足就按實際可用量裝載。雙方共用規則，AI沒有免費糧，也不享有遠端補給。

戰術地圖上雙方行動都結束，才完整經過一個戰鬥日，依當時存活部隊實兵數計算：

```
當日口糧單位 = 當日實際兵數 + 100 × 仍有兵的武將數
需要補入的口糧單位 = max(0, 當日口糧單位－前日小數餘額)
當日取糧 = min(隨軍餘糧, ceil(需要補入的口糧單位 / 1000))
次日小數餘額 = max(0, 前日小數餘額 + 當日取糧 × 1000－當日口糧單位)
```

因此少量部隊不會每天被重新向上取整收費，傷亡後按剩餘兵數降低日耗；前進、原地等待或結束行動都按相同的完整戰鬥日計算。攻城／兵士交鋒的巡數、單挑的合數及動畫幀數不是戰鬥日，不會每次操作額外扣糧。這是本作沿用行軍核心的口糧適配公式，並非聲稱原版使用同一數式；原版「兵糧耗盡則退卻」是判退規則的依據。

當日可用糧及小數餘額不足以供應部隊，缺糧方立即撤退，不額外抽亂數。攻方缺糧為退卻，守方缺糧則攻方獲勝；雙方同日缺糧由攻方撤退，守方保城。這與道路中連續10日缺糧後返程的機制分開；不會在戰場再累加一輪行軍減員。

戰場米屋購糧沿用現有設施價格、批量與付費規則，購得的兵糧直接補入該軍隨軍糧，不增加遠方來源城庫存。火箭現在按已核對的原式扣敵軍攜行糧：`floor(餘糧 × (10..14) / 100) + floor(知 / 5)`，實扣以現糧封頂。燒失以獨立 `fire` 明細保存，不能冒充食用量，城內倉庫不因此減少。共用成功門仍保留明示的本作模型；詳見[計略效果與來源](tactic-effects.md)。

戰果接收時，餘糧只結算一次：勝方糧隨武將入實際接收城；撤退方糧隨仍有兵的將領返回實際安置的友城。原城失守不能把退款交給敵方原城，改由實際安置將領的友城接收；無返回將領的敗軍餘糧由勝方繳獲。城內庫存達上限時不能容納的部分明記為損失，不新增免費庫存。已消耗糧不退，小數餘額在入城時結束，重複接收戰果不重複返糧。

帳本與每日口糧收支一起存檔及重放驗證。同劇本SHA的既有進行中戰鬥若缺少戰鬥帳本，讀檔、查看及同步均不扣城糧、不贈送兵糧；到下一個正式且成功的戰鬥操作才從當時真實庫存建立帳本，不補算之前日數。沒有帳本的既有已結束戰鬥也不憑空退糧。新開戰鬥一律具備帳本。

## 特殊道路與海路

| 路線 | 時間 | 全程減員 |
| --- | --- | --- |
| 陰平 → 成都 | 平地基準的 2 倍；單向 | 損失三分之二，整數按原比例分配 |
| 漢中 ↔ 長安子午谷，7～9 月 | 平地基準的 4 倍，暴雨 | 50% |
| 子午谷其他月份 | 平地基準的 2 倍 | 20% |
| 海路順季風 | 平地速度的 4 倍 | 風暴損失 80～90% |
| 海路逆季風 | 平地速度的四分之一 | 風暴損失 80～90% |

季風方向依月份與航向判斷，另有無季風時段；準確月份與路線設定見 `game/config/campaigns/shared.json` 的 `travel_hazards`。普通地形與登船耗時沿用同檔案的 `travel_rules`。這些是本作玩法設定，不是歷史航海損失率。

風暴在完整航程首次結算一次，不因分段或滿員等待重複抽取及扣兵。確定性損失也只結算一次；逐將整數餘兵與總帳守恆。所有武將仍保留人物身分，兵數歸零不自動等於戰死。

只允許沿海且當時已開放的城池嘗試未知海路。成功抵達後才記錄並顯示新航線；全損、目的地關閉或行軍取消都不揭示。探索隊抵達敵城仍按實際兵力及所有權處理。

滿員目的城先等待；每旬重試接收；等待期間不再次結算同次災害。地圖海路兩端接陸地道路，圖形座標用於顯示，行軍距離採另一套地理座標。來源與編譯結果可用 `python3 -B game/build_campaigns.py --check` 重驗。

核心在 `source/remake/travel.py`、`source/remake/march_supply.py`、`source/remake/battle_supply.py`、`source/remake/route_hazards.py` 及 `crates/march-core/`。Python、原生 Rust 與 WASM 以目前路網、月份、方向、平手路徑及減員向量做差分驗證；口糧由共同戰役服務按實際日數記帳。
