# 武將屬性來源與目前轉換政策

目前採用 `campaign-officer-stats-v1`：**武、知、德分別對應SAN14武力、知力、魅力；初始體力與忠誠另按可核對的原版武將表配置。** 數值是遊戲資料及本作轉換，不是史實測量。這是新的共同政策，取代先前「原版ROM德優先」與逐人歷史德評分的執行規則。

## 武、知、德

已保留SAN14參考值的1,000人，德直接取魅力，與武、知共用最高99的尺度；來源100保存在 `profile.source_stats`，顯示及規則使用99。其餘23人沒有魅力來源，依使用者指定設德60，不用姓名相近者、原版德或舊歷史評分補值。

| 人物 | 前一版德 | 目前德 | 目前依據 |
| --- | ---: | ---: | --- |
| 嚴顏 | 86 | 77 | SAN14魅力77 |
| 劉備 | 99 | 99 | SAN14魅力99 |
| 曹操 | 97 | 96 | SAN14魅力96 |
| 諸葛亮 | 95 | 93 | SAN14魅力93 |
| 呂布 | 10 | 36 | SAN14魅力36 |

因此嚴顏現在77是政策變更的結果，不是再次漏用原版86。1,023人中983人的德改變，40人相同；其中972人來自魅力轉換，11人由先前歷史設計值改為缺來源的預設60。武、知、適性、人物ID、出生／出仕／退場年月、城池歸屬及駐城安排不因這次屬性轉換改動。

SAN14數值來源為保留的[第三方轉寫參考](../game/config/references/san14-abilities.json)，不是官方資料匯出。1,000筆與23筆缺來源分開標記，不宣稱新增人物具有來源中不存在的魅力值。

## 原版表的體力、忠誠與身分核對

參考[攻略頁附件](https://www.cnblogs.com/strick/p/10171248.html)的武將資料ZIP，保留為[離線數值與逐行證據](../game/config/references/cnblogs-officer-stats.json)。ZIP的SHA256為 `6dff28ec4bb74776de6cb6e232388e7210982e8e1761adff45a73adccc2933b0`，內文SHA256為 `231c554b6de801ecf9d2387e42b549ce49a3e12ae94dd237a8e6153f1bb18187`。這是第三方遊戲資料轉寫，並非官方原始檔或歷史測量。

237筆來源中，223人可綁定：212筆唯一姓名／既有別名、9筆逐人審查異字、2筆具上下文的身分核對。剩餘14筆保留未綁定，不按能力相似度、肖像、排序、執行期ID或模糊姓名猜配。

### 初始體力與恢復上限分開

- 223名可核對者取原表的**初始／當前體力**；其餘800人初始體力80。
- 恢復上限是 `max(轉換前本作上限, 新初始體力)`，以容納新初值，並保留既有恢復能力。這是本作相容政策，**不宣稱來源表證明了原版最大體力**。
- 本輪201人的初始體力改變，85人的恢復上限提高、938人上限不變。
- 新開局與未來首次登場都用這個初值；未來登場當月不立即再加一次月恢復。之後仍按本作每月恢復8、至上限為止。
- 查詢、預覽、存讀、調動及轉屬不會重新填滿受傷武將的體力，也不會復活已死亡或退場人物。

### 忠誠必須符合所屬勢力

原表忠誠有勢力語境。216名匹配人物有數字忠，其中180人能確認勢力ID；另7筆來源是君主標記 `--`。普通武將初始化時，只有目前所屬勢力在來源明列的 `faction_ids` 中，才使用該數字忠。只有地點說明、未能對應勢力、沒有原表或來源為 `--` 時，普通武將採80。

例如嚴顏原表忠86屬劉璋語境：劉璋開局可用86，其他勢力開局不盲目套用。諸葛亮原表最後欄是「孫策左側空城」，這是地點，不能據此推定忠97屬孫策。新登場在野者忠為0；任何本局君主內部固定100、畫面顯示 `--`，包含地方文吏繼承人。原表 `--` 不直接轉成普通武將忠100。

成功登用與勸誘仍按現有 `recruitment_loyalty()` 結算，轉屬、繼承、戰後處理與存讀保留目前規則。這次不把原表忠誠當成永久固定值。

## 新來源與既有ROM證據分開保存

[原版ROM參考](../game/config/references/original-officer-stats.json)仍保留237筆原始12位元組、檔案位移及SHA256，既有[肖像身分對照](../game/config/portrait-identity-map.json)的220個綁定保持不變。ROM的德欄位 `+4` 現在是可查證據，不再覆蓋目前SAN14魅力政策。

新表的223個綁定不是原220個綁定的改名覆蓋。兩份轉寫有身分與數值分歧，例如新表「費帏」對應費禕，舊ROM同數值記錄的姓名轉寫是潘濬；「傅婴」與舊傅巽亦分別記錄。相同數值不證明同一人物。可比較同身分的214人中有5筆來源數值衝突，保存在變更表，未靜默合併。

逐人轉換前的 `profile`、`configuration`、`virtue_design`、`initialization` 存在不可重複覆寫的 `pre_campaign_stat_policy_v1`。更早的原版德修正及歷史評分證據也保留。完整1,023人前後差異見[JSON](officer-stat-changes-v1.json)及[CSV](officer-stat-changes-v1.csv)。

[29篇開局稽核報告](officer-stat-scenarios-v1.json)另列3,169城次預覽、8,854名次駐城人物及2,320名次在野人物。逐人核對來源體力、勢力語境忠誠、魅力轉德與同版存讀；其中1,538個普通在籍人物實例的忠誠、2,925個人物實例的初始體力改變。這是跨劇本實例數，不能當成不同人物總數。

## 經驗、容量與驗證

原版「經」顯示為 `floor(原始經驗 / 50) % 1000`；合法原始值0–49999對應0–999，登場初始化為0。等級門檻1000、2000、3500、5000、7500、10000、15000不變。每城歷史武將與文吏合計99人、每方出戰10人；全部29個劇本採同一轉換政策，歷史及假想的日期、城池歸屬與人物安排維持各自設定。

下列檢查完全離線，不需要ROM、下載原附件、登入帳號或開啟既有存檔：

```sh
python3 -B tools/officer-placement/import_campaign_stats.py --check
python3 -B -m unittest discover -s tests -p test_remake_stat_policy.py
python3 -B -m unittest discover -s tests -p test_remake_original_stats.py
python3 -B game/build_campaigns.py --check
python3 -B tools/officer-placement/audit_campaign_stats.py --check
```

若另有已取得的原ZIP，可用 `--source-zip /path/to/霸王的大陆武将.zip --check` 重解析並核對釘選SHA與輸出。一般建置直接讀離線參考。建置器驗證1,000筆魅力、23筆預設、初始體力、恢復上限與忠誠語境，劇本差異不能覆蓋共同政策。

這是資料集更新，不改寫或遷移舊資料集存檔。刷新最新版本後請新建戰役；目前戰役的體力與忠誠不會在畫面刷新或讀取時偷偷重設。
