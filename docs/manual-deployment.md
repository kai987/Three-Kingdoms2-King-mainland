# 戦前の逐将配置

新しいプレイヤー参加戦の開始時に、自軍の武将を名簿順に1人ずつ配置する。進軍の最後の都市から選ぶ[原作の配置区画](directional-deployment.md)をそのまま使い、相手AIの配置は先に固定する。未配置の自軍武将はマスを占有しない。逐将操作に加え、新戦局のAIには[原作の武力比較・四組配分](ai-deployment.md)を使う。原作AIにない共通安全検査とWeb保存の境界は、本作の適応として分ける。

本書は今回の規則と根拠を記録する。CPU観測の完了と、本作の実装・ブラウザー回帰の合格は別に扱う。2026年11月6日のローカル受入結果は末節に集計する。push・リモートCI・オンライン公開は今回の範囲に含まない。

## 原作で閉じた操作

1. 人間側の配置制御は守備側、次に攻撃側へ進む。各側の制御値がAIなら、その側の手動操作を飛ばす。AIには別の事前配置処理がある。
2. 人間側は非空の武将槽を順に選ぶ。`C30E`から`C3CB`へ進み、**現在の1人だけ**に既定点を書く。将来の武将は座標`FF`のままで、既定点を全員に先取りさせない。
3. 既定点は毎将、候補表の先頭から探し直す。既に配置された双方の座標と重なる点は飛ばす。前将が城砦から移れば、次将が空いた先頭候補を使える。
4. 矢印はその場で現在将の座標RAMを書き換える。`C4B1`は表示境界、占有、`C447`の半開矩形を確認し、縦移動ではメタデータの`packed_y=15`を飛ばす。山・水の禁止や、主将を城砦へ固定する追加分岐はない。
5. 文字表示後の`C350`はAで現在将を確定して次へ進む。方向を含む入力では同時にA確定しない。B・Select・Start単独に、取消・前将へ戻る・初期化する分岐は確認できない。

占有検査`D6B6`は座標配列`0600/0614`を全20槽で比較し、`0628`の陣営マーカーや人物IDで絞らない。自然な未配置／空槽が妨げにならないのは、その座標が`FF`だからである。異常な空槽へ有効座標を手動注入した観測を、通常の空槽挙動とは扱わない。

`C218`が配置前に初日と機動力を準備し、`C2CD`は全員確定後もその残数と初日を保って攻撃側から始める。配置の矢印・A確認そのものに、機動力消費、日数追加、乱数抽選はない。新たな兵糧日を配置のために進めない。

Selectについて閉じたのは**この配置編集・確定分岐**だけである。他の画面・coroutineにまたがる全体操作を無効と認定したものではない。原作の配置途中を保存／再開する手順も未確認である。

## Web版での確定と保存

実装は[配置サービス](../source/remake/battle_placement.py)、公開命令は`battle_place`。実際の行軍到着から新しく始まる、双方に戦力があるプレイヤー参加戦だけで準備段階を作る。無守備の城は従来どおり結果へ進み、AI同士の戦闘や準備記録のない既存戦局へ新しい操作段階を後付けしない。

- AI側全員を先に置き、自軍は確認済みの武将と現在将だけに座標を持たせる。新しい行軍到着では、AIの主将を保って非主将を原武力比較で並べ、勢力slotに対応する四組の人数と游標で候補を選ぶ。これは[原作AIの初期配置](ai-deployment.md)の接続であり、戦闘中の戦術判断全体の複製ではない。原AIが行わない矩形・占有の安全検査を本作では共通に適用し、異常候補を修正する。
- 自軍は名簿順に確認する。他将選択や順飛ばしはできない。明るい合法格をクリック／タッチするか矢印で現在将を調整し、確認ボタン、Enter、Aで1人ずつ確定する。表示された既定点を動かさず確認することもできる。B・Select・Start・Escapeに準備段階を取り消す機能は追加しない。
- 画面内の未確定カーソルはローカルプレビューで、正式座標や保存データに書かない。確認すると現在将の座標を原子的に保存し、次将の既定点を再選択する。確認ごとに本機自動復元点も作る。手動保存やクラウドへの送信とは別で、容量不足時は既存の自動保存の案内に従う。
- Webのキー入力は独立したイベントとして扱い、NESコントローラーの同時押しビット判定まではエミュレートしない。
- 原作は矢印ごとにRAMを即時更新する。一方、本作は**各将の確認を保存境界**とする。これはWebの通信・保存への適応であり、原作カーソルの永続化や原作セーブ仕様の復刻とは呼ばない。
- 準備中も戦役のphaseは`battle`だが、攻撃、通常移動、計略、一騎討ち、施設、日界、退却等は実行できない。閲覧、手動保存、読み込み、主メニューは利用できる。未確定プレビューだけでは命令を送らない。
- 配置そのものは機動力、命令書、追加兵糧、日数、乱数を消費しない。守備側プレイヤーの最後の確認後は、既に初期化済みの攻撃側AIの通常先手が一度実行される。その通常行動で生じる消費・兵損・演出は、無料の配置操作とは別である。

準備の任意保存欄は`extended.placement`。フィールドは`schema: tk2-battle-placement-v1`、人間側`side`、初期名簿の文字列ID配列`order`、確定人数`confirmed`だけとする。座標は既存の`extended.tactical.positions`を唯一の正本とし、別の草稿座標や日数・機動力を重複保存しない。準備中は相手全員、自軍の確定済み全員、現在将だけが位置を持ち、全確定後は全員を持つ。

読み込みは同じ現在将・確定済み位置・AI位置・兵糧・機動力を保ち、初期化やAI先手を再実行しない。準備記録があるのに戦術座標や配置出典がないデータ、不正な順序・重複・矩形外・占有位置は拒否する。完了記録はその後の移動や籠絡を禁止せず、既存の転属台帳から初期の側を検証する。旧戦局にこの記録がなければ旧来の完成配置をそのまま使う。新AIの`auto_deployment`がない旧pending準備にも、後から新しい並べ替えやAI位置を注入しない。

## 115都市への適応と検証範囲

115都市と原作30戦場の対応、最後に通った都市からの区画選択、来向推定、候補の安全フィルターは[方向別配置の契約](directional-deployment.md)を維持する。原隣接の配対区画を優先し、それ以外の地域推定は明示する。手動格は原半開矩形と可視31×19の共通部分だけにし、`packed_y=15`を除いて16〜19を表示y15〜18へ変換する。山水は許可するが、原表の表示外・矩形外・重複の異常値をそのまま利用しない。

対応する検証コードは[純粋サービス](../tests/test_remake_manual_deployment.py)と[公開行軍・到着・保存](../tests/test_remake_manual_deployment_campaign.py)。最終のPython／Rust各6分割は138モジュール・各1387件、計2774件が合格した。初回に新しい準備段階を飛ばしていた4つの旧テスト駆動だけを公開確認へ直し、影響する分割を再検証した。実行規則やgoldenはこの修正で変えていない。以下はこの機能を個別に再実行するコマンドである。

```sh
python3 -B -m unittest discover -s tests -p 'test_remake_manual_deployment.py'
python3 -B -m unittest discover -s tests -p 'test_remake_manual_deployment_campaign.py'
```
