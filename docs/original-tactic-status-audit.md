## 對操作的實際影響

玩家命令選擇中，選項0經`A162/A167`讀取本隊`0650`，非0便拒絕進入對應操作。ROM的`A1AC`表把這個選項送往主狀態4，而主狀態4明確分派到`movement`；選項1普通攻擊、選項2計略不經這個狀態門。AI在準備移動提案時也會因本隊狀態非0而回報沒有移動提案。

因此目前可確認的是**限制戰術地圖移動**。沒有證據支持把虛兵／連環解釋成「本隊下一次普通攻擊自動失敗」，也沒有這個門禁止玩家受影響部隊施計。相鄰攻擊資格仍按原攻擊路徑檢查，不能把移動禁令擴大成全操作停擺。

這裡沒有聲稱已還原AI在所有戰況下的最終選擇順序；已證的是移動提案分支的非0狀態檢查，而不是單憑AI變數名稱推定它每次一定會反擊或改用某個計略。

### 已閉合的攻守及日界映射

這次沿名冊建立、陣營位元寫入與起戰呼叫補查，已可將原位元對應到本作攻守，無須由數值大小或變數名稱推斷：

1. `prepare_battle_departure`的`B7D9–B81E`讀取已選被攻城`0471`，把其君主寫入`0507`低4位，該城原駐將寫入`0664[0..9]`。選城路徑`AF12/AF4B`同時把該城寫為戰場城`050E`。
2. `B81F–B858`把出陣所選主將及其他出陣武將寫入`0664[10..19]`，再讀原出發城`0402`的君主，左移4位併入`0507`高4位。
3. 戰場初始化`DD31–DD71`對槽號10以上寫`0628[slot] |= 80`，槽0..9不加該位元。故原`side=0`是**守方**，`side=128`是**攻方**。
4. 起戰確認`B5DC–B61F`及對應面板路徑`CA42–CA83`把`0504`設為`80`。攻方先行；攻方結束的`128→0`只轉守方，守方結束的`0→128`才進日界並回到攻方。

因此本作若仍採`attackers→defenders→下一日attackers`，原日界掃描應掛在守方結束處。這個映射亦確定初始效果：攻方虛兵寫3、守方寫2；攻方連環寫4..5、守方寫3..4；攻方奇門高計數6..9、守方5..8。**原值是日界掃描剩餘次數，不宜直接標成對手可操作回合數**：守方施放後會先經同次守方結束的掃描，再輪到受影響攻方。被攻擊或再受計又可能提前解除，UI不能把原計數直接宣稱為固定幾回合無法操作。

`CD78`的順序為：

1. 先處理戰期及兩軍兵糧。戰期終止或糧盡分支會提前離開，並不繼續計略狀態處理。
2. 設定遮罩`0F`、步長1，由`CE40`掃描20槽。非0低半位元組減1後寫回。
3. `CF60`搜尋仍在戰場槽中的原ID109諸葛亮，人物記錄的低2位不是移除值3才寫入`052E`等欄。此前`052E`已由日界呼叫者清為0。
4. 只有`052E`非0時，改用遮罩`F0`、步長16，再掃20槽。每個符合的高狀態先減16，再對該目標執行週期兵損。最後一次由`10`減到0，該次仍會扣兵。
5. 最後才更新雙方伏兵計數等後續事項。

低狀態更新沒有傷害或額外亂數。因此虛兵2／3、連環3..5是此日界掃描的剩餘次數，和「消耗一次攻擊解除」不同。

高狀態每次命中目標後，原機抽一個接受值0..70，再加80作為要求兵損，即80..150；它不是兩次減傷，也不修改我方防禦。計時與兵損確實受諸葛亮仍在戰場且未標成移除的條件控制。原人物若已不在該戰場，高狀態這條日界分支會停計時及停週期損兵，不能擅自改述為不受施放者狀況影響的無條件5..8日效果。

原機0..70使用完整位元組棄卻71以上的樣本；連環0..1取低4位並棄卻2以上；奇門的0..3直接取低2位。將來若沿用本作`SeedRng.next()%bound`，必須明列亂數生成方式的適配，不能稱基礎抽數與原機相同。

### 需要保留界線的原始細節

- 低／高遮罩更新均把遮罩後減算的結果直接寫回整個位元組。對實驗性混合值如`52`，低狀態掃描不是保留高位的獨立減1。正常施放會覆寫狀態，不能因此設計一套原作沒有證明的疊加規則。
- 奇門扣兵原指令直接讀寫人物記錄的兵數兩位元組，且有原始高位及負號分支。正常0..999兵且高6位為0時呈現飽和減算；不將不合法packed值或別名輸入的結果當成新增功能。
- 原`0504`與攻守的映射已由實際名冊、位元寫入及起戰呼叫閉合，見上節；這不是對自然戰役全部圖形與按鍵流程等價的聲明。

### 已閉合的奇門經驗副作用

原指令`CE94–CEA3`累加每次高狀態處理後，目標人物記錄`byte8`的**剩餘兵數低位元組**。`CE09`先把16位元累加器`000B/000C`清0，全部目標處理完後，`CE14`把`000A`設為原ID109，`CE19`的`Y=2E`與`EE07`後兩個資料位元組`06 A0`呼叫physical14的`A006`，該入口明確`JMP D7FB`。這兩個位元組是跨程式入口資料，不是反組譯器顯示的`ASL 00A0`指令。

`D7FB`先以`000A`取得諸葛亮人物記錄，對`000C/000B`作一次完整16位元右移，再加到其經驗；因此正常兵數域的日界經驗增量為：

```
counter = Σ（本次實際接受高狀態處理目標的扣兵後兵數 % 256）
增加經驗 = floor(counter / 2)
```

先合計，再除2；不是逐目標各除2後相加，也不是實際損兵的一半。經驗呼叫固定授予原ID109，而非查詢「本次奇門施放者」。完整原式先把舊經驗加增量作16位元回繞，再把保存值上限設為49999；等級判定使用回繞後、封頂前的值。原等級索引0..6門檻依次為1000、2000、3500、5000、7500、10000、15000，一次呼叫至多升1級；升級後武力按原分段增加6／5／4／2／0。這些是原函式副作用，本輪未移植到本作。

`052E`通過時，即使本日沒有高狀態目標，也會呼叫一次經驗函式並執行等級檢查；只有累加值為0。若諸葛亮不在戰場槽中，則高狀態掃描、傷害抽樣及這次經驗呼叫一起跳過。

## 下一批的最小接入邊界

建議把三種新狀態作為同一個可保存、可預覽、按戰場日推進的服務處理，先有獨立原式向量，再替換這三項的效果及UI。保留已證的地形／連通目標和共用機動力；不擴大到所有計略傷害、原機全部AI決策或俘虜處置。

原陣營位元映射、諸葛亮消失時停止高時鐘及原經驗副作用已閉合，可作下一批原式對照依據，**尚未接入本作**。實作前仍需決定是否保留「按剩餘低位元組增加經驗」的原始規則、原升級副作用如何對接本作經驗上限，以及舊stunned／guard資料的相容策略；不能把已證但不直觀的原式悄悄改成實際傷害公式。一般成功門`B7BE`環境欄位及AI普通接敵清除狀態的跨程式全鏈仍未閉合。新狀態的移動禁令應只接移動資格，不放進會同時禁止攻擊、計略及其他功能的總行動門。AI可避開無收益的重複狀態，但不能把原玩家可確認的付費操作直接改成不可選。

必要回歸至少包括：
