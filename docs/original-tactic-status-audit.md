## 已確認的三種效果寫入

三者都先走一般計略成功門`B7BE`。失敗不會再抽持續值；奇門不是無條件成功。`B7BE`的環境欄位完整意義仍未閉合，故本文件沒有宣稱其成功率已適合原樣接到本作。

| 計略 | 成功後寫入對象 | 原版寫入值 | 額外抽樣 |
| --- | --- | --- | --- |
| 虛兵，ID2 | 所選敵隊的`0650` | 施放方原`0504`高位為0時寫2，為1時寫3 | 無持續值抽樣 |
| 連環，ID10 | 連通集合中，每一支實際位於水格的敵隊 | `3 + r + side`，`r=0..1`，`side`為施放方原高位0或1，即3..4或4..5 | 每個實際水格目標各抽一次接受值0..1 |
| 奇門遁甲，ID15 | 所選敵隊的`0650` | `(5 + r + side) << 4`，`r=0..3`，即高半位元組5..8或6..9 | 成功後另取隨機位元組的低2位 |

連環的非水格敵軍仍可作連通橋，但不因被搜尋到就抽持續值或寫入連環效果。這部分的空間集合已在本作處理，不能把未接入的持續效果和已接入的連通條件混為一談。

上述賦值寫的是整個位元組，不是對既有狀態加一個可疊加buff。合法施計流程又會先清除所選目標的原狀態，因此不可從低／高半位元組的外形推導出「兩種效果可自由疊加」。

## 對操作的實際影響

玩家命令選擇中，選項0經`A162/A167`讀取本隊`0650`，非0便拒絕進入對應操作。ROM的`A1AC`表把這個選項送往主狀態4，而主狀態4明確分派到`movement`；選項1普通攻擊、選項2計略不經這個狀態門。AI在準備移動提案時也會因本隊狀態非0而回報沒有移動提案。

因此目前可確認的是**限制戰術地圖移動**。沒有證據支持把虛兵／連環解釋成「本隊下一次普通攻擊自動失敗」，也沒有這個門禁止玩家受影響部隊施計。相鄰攻擊資格仍按原攻擊路徑檢查，不能把移動禁令擴大成全操作停擺。

這裡沒有聲稱已還原AI在所有戰況下的最終選擇順序；已證的是移動提案分支的非0狀態檢查，而不是單憑AI變數名稱推定它每次一定會反擊或改用某個計略。

## 計時及奇門週期兵損

`finish_side_turn`在原陣營位元由0切到128時推進戰場日數、補兩軍機動力，清除`052C/052E`，再由`BE0C`呼叫另一程式對的`A00F→CD78`。反向128→0只換行動方，不呼叫同一日重設。這是實際的日界呼叫，不是某武將下過幾次命令。

`CD78`的順序為：

1. 先處理戰期及兩軍兵糧。戰期終止或糧盡分支會提前離開，並不繼續計略狀態處理。
2. 設定遮罩`0F`、步長1，由`CE40`掃描20槽。非0低半位元組減1後寫回。
3. `CF60`搜尋仍在戰場槽中的原ID109諸葛亮，人物記錄的低2位不是移除值3才寫入`052E`等欄。此前`052E`已由日界呼叫者清為0。
4. 只有`052E`非0時，改用遮罩`F0`、步長16，再掃20槽。每個符合的高狀態先減16，再對該目標執行週期兵損。最後一次由`10`減到0，該次仍會扣兵。
5. 最後才更新雙方伏兵計數等後續事項。

低狀態更新沒有傷害或額外亂數。因此虛兵2／3、連環3..5是此日界掃描的剩餘次數，和「消耗一次攻擊解除」不同。

高狀態每次命中目標後，原機抽一個接受值0..70，再加80作為要求兵損，即80..150；它不是兩次減傷，也不修改我方防禦。計時與兵損確實受諸葛亮仍在戰場且未標成移除的條件控制。原人物若已不在該戰場，高狀態這條日界分支會停計時及停週期損兵，不能擅自改述為不受施放者狀況影響的無條件5..8日效果。

原機0..70使用完整位元組棄卻71以上的樣本；連環0..1取低4位並棄卻2以上；奇門的0..3直接取低2位。將來若沿用本作`SeedRng.next()%bound`，必須明列亂數生成方式的適配，不能稱基礎抽數與原機相同。

### 需要保留界線的原始細節

- 低／高遮罩更新均把遮罩後減算的結果直接寫回整個位元組。對實驗性混合值如`52`，低狀態掃描不是保留高位的獨立減1。正常施放會覆寫狀態，不能因此設計一套原作沒有證明的疊加規則。
- 奇門扣兵原指令直接讀寫人物記錄的兵數兩位元組，且有原始高位及負號分支。正常0..999兵且高6位為0時呈現飽和減算；不將不合法packed值或別名輸入的結果當成新增功能。
- `CE94–CEA3`累加的是扣兵後低位元組，之後有以原ID109為參數的經驗處理呼叫。這不是已可宣稱的「按實際損兵加經驗」公式；完整報告／經驗副作用應另立原指令對照測試後再接。
- 原`0504`陣營位元和本作`attackers/defenders`的起手、日界映射應用獨立原核心樣本確認。已證的初始值含方位偏移，不能只讀到數值2或3便宣稱恰好限制對手2或3個操作回合。

## 已確認的解除與覆寫時點

| 動作 | 原版行為 |
| --- | --- |
| 玩家確認普通接敵 | 先支付2機動力，`A3D2/A3E6`把**被攻擊目標**`0650`清0，然後才進入兵士戰 |
| 玩家確認計略 | `AA55`在效果成敗判定前，把**所選目標**`0650`清0 |
| AI實際施放計略 | `C09A`在效果dispatch前，把**所選目標**`0650`清0 |
| 低／高狀態到期 | 對應日界掃描減到0，而非以本人行動次數扣減 |
| 參戰部隊移除／轉入城池 | 已恢復的相關路徑清掉該戰場槽的狀態等陣列，不留下可作用於下一個人物的槽引用 |

因為清除發生在效果成敗判定前，另一次計略即使失敗，也可能先清掉所選敵隊的舊狀態。這是實際呼叫順序，不應將它改述為「計略失敗一定對所有狀態無影響」。當前剛接入的籠絡0%必敗仍屬本輪既有狀態模型；尚未一併接入這套跨計略清除規則。

普通攻擊的證據明確覆蓋玩家確認路徑。AI的攻擊畫面前置還含跨程式服務呼叫，其全路徑清除對照應再閉合，不能以玩家路徑代替整個原AI的證明。

對應現碼主要為`source/remake/campaign_expansion.py`的`_execute_tactic`、`_attack_hit`、`_duel_start`，`battle_grid.py`的移動資格，`siege.py`的`_step_turn`及`_hit`，以及`tactical_ai.py`的估值。既有`stunned`亦由偽擊轉殺及舊存檔使用，故下一階段不能把所有stunned行為一律刪除而宣稱只更改這三項。

## 下一批的最小接入邊界

建議把三種新狀態作為同一個可保存、可預覽、按戰場日推進的服務處理，先有獨立原式向量，再替換這三項的效果及UI。保留已證的地形／連通目標和共用機動力；不擴大到所有計略傷害、原機全部AI決策或俘虜處置。

需要明確選定原陣營位元映射、諸葛亮消失時的高狀態處理、經驗副作用，以及舊stunned／guard資料的相容策略。新狀態的移動禁令應只接移動資格，不放進會同時禁止攻擊、計略及其他功能的總行動門。AI可避開無收益的重複狀態，但不能把原玩家可確認的付費操作直接改成不可選。

必要回歸至少包括：

- 雙方施放的初始計數、連環每個水格目標的獨立抽樣、橋接非水格不抽持續值。
- 半回合不減、一次完整日界只減一次，最後一次奇門扣兵、過期後不再扣兵。
- 食糧不足或戰期終止先結束戰鬥，不繼續狀態傷害或抽亂數。
- 受影響部隊不能移動，但合法相鄰攻擊與計略仍可執行；查看或規劃路徑不解除狀態。
- 被普通接敵、再次被計略選中及計略失敗時的清除／覆寫順序；取消或被拒絕的交易不清除。
- 諸葛亮仍在、轉屬、退場、移除時的高狀態時鐘；人物ID使用已核對穩定綁定。
- 不多扣機動力、兵員及經驗帳一致，玩家／AI／AI對AI共用，保存讀回後同亂數與同後續結果。
- 新狀態與偽擊轉殺、舊stunned／guard存檔的分界；不刷新歷史固定驗證結果掩蓋差異。
