## 對操作的實際影響

玩家命令選擇中，選項0經`A162/A167`讀取本隊`0650`，非0便拒絕進入對應操作。ROM的`A1AC`表把這個選項送往主狀態4，而主狀態4明確分派到`movement`；選項1普通攻擊、選項2計略不經這個狀態門。AI在準備移動提案時也會因本隊狀態非0而回報沒有移動提案。

因此目前可確認的是**限制戰術地圖移動**。沒有證據支持把虛兵／連環解釋成「本隊下一次普通攻擊自動失敗」，也沒有這個門禁止玩家受影響部隊施計。相鄰攻擊資格仍按原攻擊路徑檢查，不能把移動禁令擴大成全操作停擺。

這裡沒有聲稱已還原AI在所有戰況下的最終選擇順序；已證的是移動提案分支的非0狀態檢查，而不是單憑AI變數名稱推定它每次一定會反擊或改用某個計略。

1. 先處理戰期及兩軍兵糧。戰期終止或糧盡分支會提前離開，並不繼續計略狀態處理。

低狀態更新沒有傷害或額外亂數。因此虛兵2／3、連環3..5是此日界掃描的剩餘次數，和「消耗一次攻擊解除」不同。

原機0..70使用完整位元組棄卻71以上的樣本；連環0..1取低4位並棄卻2以上；奇門的0..3直接取低2位。將來若沿用本作`SeedRng.next()%bound`，必須明列亂數生成方式的適配，不能稱基礎抽數與原機相同。

### 已閉合的奇門經驗副作用

原指令`CE94–CEA3`累加每次高狀態處理後，目標人物記錄`byte8`的**剩餘兵數低位元組**。`CE09`先把16位元累加器`000B/000C`清0，全部目標處理完後，`CE14`把`000A`設為原ID109，`CE19`的`Y=2E`與`EE07`後兩個資料位元組`06 A0`呼叫physical14的`A006`，該入口明確`JMP D7FB`。這兩個位元組是跨程式入口資料，不是反組譯器顯示的`ASL 00A0`指令。

`D7FB`先以`000A`取得諸葛亮人物記錄，對`000C/000B`作一次完整16位元右移，再加到其經驗；因此正常兵數域的日界經驗增量為：

```
counter = Σ（本次實際接受高狀態處理目標的扣兵後兵數 % 256）
增加經驗 = floor(counter / 2)
```

先合計，再除2；不是逐目標各除2後相加，也不是實際損兵的一半。經驗呼叫固定授予原ID109，而非查詢「本次奇門施放者」。完整原式先把舊經驗加增量作16位元回繞，再把保存值上限設為49999；等級判定使用回繞後、封頂前的值。原等級索引0..6門檻依次為1000、2000、3500、5000、7500、10000、15000，一次呼叫至多升1級；升級後武力按原分段增加6／5／4／2／0。這些是已核實的原函式副作用；接入保留原經驗量，但單次最多升一級及永久加武不搬入，另按下文的本作成長契約。

`052E`通過時，即使本日沒有高狀態目標，也會呼叫一次經驗函式並執行等級檢查；只有累加值為0。若諸葛亮不在戰場槽中，則高狀態掃描、傷害抽樣及這次經驗呼叫一起跳過。
