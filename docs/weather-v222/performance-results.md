# 性能验证

正式结算在原有逐日推进与旬边界之间协作。日内核对实际路权、位置、粮袋、货粮和会合。完整应急路线只在真实节点需要时建立。相同末程复用原行程，路径图与分段天气权重复用以当前结算边界为范围。城池库存、预留量和能否接收均读取当时真实值。

报表 `exports/performance-comparison.csv` 提供每局含观测统计的平均每旬 CPU 时间。 `checks/performance-observer-on-off.csv` 提供同一开局的开关对照，附结果 SHA-256、随机数计数与分位耗时。完整观测的流文件写入和不开观测时的一般回合不能直接用同一时间解释。细分热点保留在对应策略的 CPU profile。

207 年 9 月、种子 2028 的前 24 旬，211 的 J3 平均 CPU 时间为 0.428 秒（关详细观测）和 0.433 秒（开详细观测），212 为 0.642 秒和 0.706 秒。同一策略和规则下，两种观测设置的存档 SHA-256 与随机数消耗相同。

对金城滞留检查点继续执行九旬的 CPU profile 中，I3 与 J3 分别为 23.92 和 20.14 秒。J3 的完整应急审查调用 10 次，累计 3.62 秒，时间集中于路线报价及物理路段权重。该检查点及开局对照是诊断样本。
