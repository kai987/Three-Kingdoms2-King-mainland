# 性能测量

观战每旬计时包括真实战略计算、运输和战场结算，以及该旬记录器的可测工作。 `performance-comparison.csv` 保留 CPU 均值、P95、最大值、实际耗时 P95 与最大值、内存峰值以及原有和新增的路线计数。实验同时执行，实际耗时包含本机调度争抢。横向性能判断先看 CPU。

同一目标和路线条件在需求规划中使用一次批量路径计算。同旬内成交更新实物库存，读取价格复用快照。自动商业先查看缺粮、命令书、供需价差，再搜路。静态区域在初始化时按现有地图读入，交易时不会重建世界地图。

四局五年干燥配对的每局平均 CPU／旬中位数从 R0 的 0.59 秒达到 R2 的 0.67 秒。10 个五年天气配对从 1.11 秒达到 2.35 秒。这里包含各自真实战略路径、天气报价、交易和记录器，不能直接当作单个搜索函数的耗时。

浏览器样本使用真实静态产物、Worker 和 Pyodide。浏览器验证记录单次战略推进从点击到完成的等待时间，不作为矩阵或发布站点的平均延迟。设备、等待时间、控制台和浏览器交互记录见 `checks/browser-ui.log`。

静态构建在本地 Chromium 的 1,280×800 繁中及 390×844 日文样本中，从点击结束本旬、执行电脑行动到日期推进并结束加载约 2.2 秒。两者均检查了城内市场的库存与修正，真实下单、发运并在重新载入的到货记录上按现价出售。窄屏为 Chromium 触控模拟。
