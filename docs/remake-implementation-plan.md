# 独立重制版的最小范围

## 已确定的规则

- 采用现有96城地图。每城先设20名武将；战场沿用每方10槽、总共20槽，不能按驻城上限翻倍。
- 总人物库与当年可登场人物分开。出生、出仕/登场、死亡有独立年份和来源；不使用“生年+15”补出仕年。卒年当年的月份未知，需要剧本说明或明确边界策略。
- 武力、智力对应武、知，保留来源原值。德采用独立、有史料依据的设计评分。体力、忠诚、兵力、装备、经验由本作人物/剧本配置初始化。
- 新增人物的缺失字段保持待配置。示例设计值与已考证事实分开；不把1000条姓名资料称为1000名可玩武将。

## 阶段顺序

1. **人物和名册基础**：现代类型、20人容量、16位身份、年代资格、属性初始化、德评分规则；覆盖满城拒绝、原子转属、同名、卒年及缺失数据边界。
2. **独立最小闭环**：选择势力、查看/操作城市、编兵、选择相邻目标、出征、普通攻击战斗、战后归属/名册/资源结算、电脑行动、下一回合。运行逻辑不读取ROM/IR。
3. **玩法扩展**：计略、单挑、补给、招募、转属、继承与势力灭亡逐项接入；只对真正阻塞玩法的规则补做逆向。菜单、调度、存档及呈现使用现代实现。

最小闭环先使用有完整配置的少量人物和相邻城池验证，世界地图与人物总库保持完整；不以猜测的千人能力或城市分布填满所有城。未知玩法用明确标记、可替换的设计实现。

## 实际验收

必须真实操作“选势力→城市操作/编兵→出征→战斗→战后结算→电脑行动→下一回合”，并检查取消返回、连续回合、兵员资源守恒、单一归属、20人容量、出战人数和保存/恢复。分别记录通过、失败、未测。仅有构建成功、模型测试或旧模拟器回放均不能声称已完成可玩游戏。

阶段1已在本地实现并接入字段表及交互报告。阶段2现在由`source/remake/campaign.py`和`game/`接通，不另起人物实现：四城七人、选择势力、城市编兵、出征确认、可操作普通攻击、胜败/退却、一次性战后结算、电脑整备、下一回合及本地存取。

阶段2初版通过35项人物/战役测试。该版本的真实浏览器按钮完成10组流程检查，包括连续3回合和一次跨年；另在只包含9个明确运行文件的独立副本中重复整个浏览器流程，记录文件访问、加载模块与HTTP请求，未访问原项目或加载原ROM/核心/控制IR。20/21人等较大名单边界使用明确的受控模型夹具，不能冒称本局已有20个可玩人物。

随后以受控的提前死亡人物状态重现了跨寿命年份时缺少年度回执的问题。修复后只补零资源变化的年代核对回执，不再次结算死亡，严格存档校验保持不变；新增存取、重复提交及非法复活等边界检查，当前37项人物/战役测试通过。这次边界修复没有重跑浏览器流程，初版的浏览器与隔离访问记录仍对应原版本哈希。

当前试玩启动与限制见`game/README.md`。完整96城千人战役、计略、单挑、复杂战术AI、继承/外交仍未实现。本轮停在阶段2最小范围，等待后续安排，不自动启动阶段3或全面逆向。人物基础和最小演练作为独立开发里程碑提交。
