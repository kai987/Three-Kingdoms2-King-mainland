# 九十六城扩展战役规则与资料边界

本批把全部96个地图节点、陆路及地图原有7条海路关系接入独立战役，保留四城演练。新玩法位于`source/remake/campaign_expansion.py`，共用原人物模型、事务、兵员账本、随机序列和存档校验；不调用原引擎、6502或控制IR。

## 人物接入

数值事实表为`expansion/officers/data/san14-abilities.json`：1000人、九个来源表的哈希、逐行来源地址、5个特殊字形和11个同名身份对照均保留。来源为[楽しい三国志数值表](https://sangokushi-fun.com/sangokushi14/san14-bushou-list/)，不是官方能力导出，尚未逐行独立复核；不复制肖像或传记正文。

`game/config/officer-designs.json`新增46人的史料参考德评分、理由、四维及来源；与阶段1的5人合计51人。每个数值都是设计解释，史书没有给出这些评分。阿会喃沿用已核对的原游戏德。武/知直接取来源武力/智力，100兼容为99并保留原值；新增完整设计明确设置体力80与适性，已有原版体力/适性基线保留。

当前52人属性齐全，948人仍有缺项；217年11月41人仕官、5人在野，姜维等须等到自身出仕年份。未来登场没有完整配置或地点时继续留在总库。年份来自已保留的SAN14游戏设定转录，不是已认证的历史生卒年。剧本的固定地图、归属与初始分布属于试制配置。

`game/build_mainland.py`从仓库资料离线生成`game/data/mainland.json`。原`demo.json`不重建、不改哈希，旧四城存档通过`CampaignSession`原子切回对应剧本；失败的切换或读取保留当前战局。

## 人事与年代

招募成功率为`clamp(35 + 执行者德//2 + 执行者知//5 - 目标德//5,15,95)`%，每次60金。仅访问本城或相邻本方/中立城的在野人物，20人上限在扣钱或抽签前检查。

敌将转属成功率为`clamp(50 + (执行者德-目标忠)//2 + (执行者知-目标知)//4,5,75)`%，每次100金。目标必须在邻近敌城且不是君主；成功后一次修改双方名册与势力，保留个人兵员和装备。招募/转属的忠诚共用原CF3F算式的字节减法与10..90钳位，不把原溢出行为改成普通有符号运算。

调动沿本方连通道路找最短路，每人每段5粮。出发城消耗行动，人物登记当回合人事/调动回执，不能通过连续换城无限行动。死亡、复活、任职、驻地和兵员一致性由存档语义校验检查。

卒年月份不明时在进入次年清理名册并释放兵员。提前死亡的人物仅登记年度核对，不重复转兵。已死亡人物不重建。主将退出后选择本势力仍活着的最高德武将接任，德相同按稳定运行ID排序；无驻军或城池时退出。该规则是现代简化继承，不是原作完整亲族继承。

## 单挑

挑战先经过对手接受判定，成功率`clamp(70 + 对手武-挑战者武,15,90)`%。拒绝消耗挑战者行动。接受后进入独立交锋状态，可保存、恢复、突击、防守、佯攻或退出。

基础体力损伤为`max(2,10+(攻击者武-防守者武)//6+draw0..6)`。防守降低进攻与所受损伤，佯攻克制防守但易受突击。体力降至1时负伤败退，20合未分胜负则返回战场；双方同时败退时保持原城归属，不制造虚假攻城胜利。装备和原作单挑动画未纳入该新公式。

## 电脑行动与结算

电脑按确定的城市顺序逐城处理，选择本地在野人物招募、补足预备兵、给部队补兵、比较邻城强弱。具备至少150兵且兵力达到守方130%时考虑出征；一轮最多三次电脑出征，优先弱守城。无法进攻时可劝降敌将或向薄弱友城调兵。AI劝降每个全局月轮最多一次，采用与玩家相同费用、成功率和忠诚结算。

AI对AI使用同一兵损和结算账本，最多200次交锋后攻方退却；AI对玩家则保存电脑队列与游标并暂停，由玩家选择守军操作。接收战果后继续剩余电脑城市，全部处理完成才登记该月电脑回执、收取收入、推进年月和处理年度事件。

守方战败后优先退往相邻本方且未满员的城池；无处退往时转在野，余兵进入目标城预备兵。出征占位、投降兵、非出战守军、双方兵损和预备兵全部纳入守恒校验。战果和月轮回执在保存/恢复后继续去重。所有96城归本方时胜利，玩家势力退出时结束。
