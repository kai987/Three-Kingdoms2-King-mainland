# 调粮、冬季与返程

## 调粮执行

现有同势力救济、盟友援助和市场保留各自入口。最短期缺粮优先读取本地实际可买量。已出征部队继续使用既有优先补给机制。主动调拨使用九旬中尚未被真实回执覆盖的缺口。来源城须有合资格武将、余粮、可用命令书和符合方针的合法道路。独立往返口粮和来源城市最低库存都参与报价。

候选先判定是否能赶在缺粮前到达，再比较风险、净货、真实口粮机会成本与时长。迟到的货粮只有仍能支付以后到期的支出才进入候选。AI 按来源发生的真实发运防止同旬重派。已有去程队或尚未发的有效承诺由对应在途或预留记录控制，来源易主、库存被更紧急的用途消耗及预留逾期会解除尚未发车的承诺。

手动调粮先取得可重复读取的报价，再预留和发运。发运重新校验实际库存、武将、命令书、路权及路径。预留与取消免费，发运沿用现有运输的一张命令书。实际运队采用原运输状态机，战略订单引用同一个运输编号和按时／延迟／改道／部分交付／接收回执。

## 冬季

在天气规则启用时按区域常态、月份、公开路况与驻军确定冬季目标。预计积雪和结冰参与合法往返报价，运输继续由每日已发生的天气及区间影响推进。前线在预计冬季到来前仍不足的目标可以触发提前调粮。天气规则关闭时附加目标为零，AI 主动调拨可独立实验。

## 返程

原 V2.2.2 会依据实际位置、真实回路和可接收城市重新计算可走路径。启用 302 时，如果当前已完成交付、有本方空位且发现返程路线上有可见敌袭或冰封风险，可以从实际所在城市依法收容人员。当前安全回程经重新报价可用但口粮不足时，只有当地真实富余粮达到需要才拨付口粮。拨付计入粮袋凭证、城市扣减和观测。原有每日耗粮、等待、天气损失和无节点时的真实失败仍结算。

专项的 1706 终结凭证单独检视护卫饥损、实际接收城和正常终结标签。旧记录中的靠岸与护卫存亡分别记录。历史编号只用于读证据和回归用例，游戏策略按实际路线和资源判断。

## 单站中转

中转是单独开关。直接方案没有可用选择时，最多比较三个合法枢纽和三个未解决目标。线路经重复城校验，第一段和第二段均需独立武将、命令书、往返口粮及实体队伍。计划状态只记录首段真实运输。首段到账后按实际净取得粮，第二段从中转城市官仓支付。首段净到货为零时结束中转计划，首段实体运队继续处理返程。等待、取消、易主或紧急优先消耗会相应释放或扣减中转预留。每条入账记录都可以定位到具体在途编号，第二段的货粮和口粮之和受首段到账的限制。
