# v15 歸城與99人城池

25個新開劇本各為1023名人物建立完整計畫，共25575筆人物×劇本記錄。每城最多99名在籍武將，戰場每方仍最多10人。招募、調動、戰後接收與AI繼續共用目錄容量。既有v14及更早目錄保留原字節，舊存檔沿用其原容量；新版配置需新開v15戰役。

## 在籍、在野及未來

每人都有`era_assignments[person_id].planning_complete`、`placement_review`及`appearance_plan`，分別記錄當年處置、依據及出場窗口。當年可用者實際建立為在籍或具有唯一所在地的在野人物；死亡、尚未出生、未到出仕年、原資料同年月已死，以及IF明列排除分開處理。

未出生／未出仕的人具有有效的`appearance_windows`。到達生涯窗口、滿足年表且城市已開放時，以在野待訪；不強制加入計畫時的歷史勢力。新增城尚未開放時使用既有父城代理。已出場的人不重複生成，已死亡身分不復活；遊玩中招募、轉屬及城池易主仍由當局行動決定。

201年5月曹操原有兩城、60個名額另掛14人，現99人容量能容納全部74人在籍，無須增加領土或繞過定員。在野所在地不計入城內在籍定員，兩者在資料頁及人數統計中分開。

## 來源優先級與精度

1. 保留明列君主及IF人物／排除設定；假想劇本不被一般史實轉屬窗口覆蓋。
2. 採用個別復核的原典任職、轉屬或活動區域，以及可核對的同年月SAN14逐人攻略表。
3. 沿用已有本篇名冊或個別審定窗口。
4. 其餘使用本人既有SAN14歷史年代記錄及已發布劇本資料作有限連續任職／提前窗口推定；不能據此證明實際任職連續。
5. 未啟用來源勢力或缺乏當年月歸屬依據時，以本人已有來源活動區域配置為在野待訪。這是本作可玩安排，不能當作史實辭官、投靠或精確居住地。

新收集的同日期攻略表僅核實15人、360筆，位於`game/config/san14-scenario-postings-v15.json`。網站回覆HTTP429後採集停止；其餘985人標明未採集，`snapshot_complete=false`。已有千人九個歷史年代快照仍是主要逐人輸入，來源為[公開SAN14年代／狀態表](https://xgodgame.blogspot.com/2020/02/14_9.html)。不能將這些二手遊戲資料描述成官方原始匯出或史實駐軍。

原典規則在`game/config/placement-history-v15.json`，含18條生涯覆核、兩條幽州在野設計及19份來源URL／文本SHA。每條規則記錄月份為原典明載或本作月界推定。例如[《三國志》卷1](https://zh.wikisource.org/zh-hant/三國志/卷01)的張郃、高覽降曹，以及[卷2](https://zh.wikisource.org/zh-hant/三國志/卷02)的黃權222年8月降魏，與只具年份的月份推定分別標示。

鮮于銀、齊周依[卷8](https://zh.wikisource.org/zh-hant/三國志/卷08)具名記錄配置幽州活動區域；194—220年在野是本作去向不詳處理，未據鮮于輔的生涯把二人投曹當作確證。原人物庫的出生、出仕、退場年及全部能力值保持原樣；史實終年與遊戲年表的分歧保留在規則註記，不偷偷改動舊目錄。

## 駐城與領土

歸屬確定後先保留君主根據地，個別有原典任職地的紀錄在所屬及定員相容時優先。例如[孟達新城任職](https://zh.wikisource.org/zh-hant/三國志/卷03)在221、225、227年優先新城；牽招227年的雁門任職也保留，該紀錄不能跨勢力繼承。其餘先取同勢力的來源城，缺少可用來源城時均衡配置於與敵勢力接壤的城池，再使用其他有名額的本方城。不能因來源城歸敵而改投。

依[卷8公孫淵事跡](https://zh.wikisource.org/zh-hant/三國志/卷08)，249及263年的襄平、樂浪、帶方由中立修正為魏；238年1月仍保留公孫淵。除此六筆開局歸屬外，原有城市、座標、地形、道路、海路及年代經濟保持原設定。

具體城市是本作115節點地圖代理與防務配置，不保證逐將逐月駐軍已考證。人物資料頁會同時展示類型、參考年月／劇本、首次登場安排與來源連結，繁中／日文切換保留輸入及進度。

## 重建與驗證

```sh
python3 -B game/build_placement_campaigns.py --check
python3 -B -m unittest discover -s tests -p 'test_remake_placement_completion.py' -v
python3 -B -m unittest discover -s tools/officer-placement -p 'test_*.py' -v
node tests/test_remake_capacity_ui.cjs
node tests/test_remake_placement_ui.cjs
```

重建僅讀取倉庫內固定來源，不連網。採集器可另行更新已驗快取，尊重限流、保留來源雜湊，重名要求明確身分頁與年表核對；同年月不同標題不合併。配置輸出記錄輸入SHA256，便於追溯。

服務啟動只解析目前25份目錄；其餘歷史目錄依固定ID註冊，讀取舊存檔時才按需載入，避免一次解析211份人物資料。普通會話建構方式保持原預覽合同；未知ID不會被拼成檔案路徑。HTTP連線佇列也容納瀏覽器並行載入腳本與小圖的請求。

測試涵蓋99滿員後第100人原子拒絕、出戰10／11人界限、全部年代可用人物實際生成、所有未來窗口可用城市、真實月份邊界不重複／不復活、孟達據點優先及敵城回退、牽招任職地保留及跨勢力拒絕、25份存檔往返、自然短月進展，以及歷史目錄／人物能力／画像ID的字節穩定性。逐劇本統計見[歸城審計](officer-placement-audit.md)。
