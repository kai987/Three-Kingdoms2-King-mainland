# 戦役バランスの計測

`tools/campaign-balance/run.py` は、既存の長期回放の `HeadlessCampaign`・公開トランザクション・戦闘解決を再利用し、明示したプレイヤー方針を比較する観測用CLIです。通常の正しさ・Python/Rust一致・セーブ互換のリリース判定とは分けて実行します。短期間の勝率だけで難易度の妥当性を断定しません。

## 方針と比較対象

| 方針 | 実行する通常の操作 |
|---|---|
| `defensive` | 内政官の任命、募兵・訓練、人事、守備兵の編制、既存の後方輸送。自発的な侵攻は行わない。 |
| `offensive` | 共通の内政に加え、既存プランナーで実際の兵力・守備・食糧・経路を評価し、1旬に最大2回の合法な出陣。空城も対象。 |
| `transport` | 輸送を優先する内政方針と、最大3都市の通常の前線輸送設定。輸送物資を生成せず、既存の費用・人員・往復行軍を使う。 |

標準の比較対象は184年2月の何進・黄巾、217年7月の曹操・劉備、263年5月の曹魏・呉です。勢力IDはそれぞれ `han/yellow_turban`、`wei/shu`、`wei/wu`。地図・人物・忠誠・初期物資・AI規則・乱数を計測用に変更しません。公開命令は通常どおり検証・確定され、戦闘は既存回放の選択器で解決します。

この方針群は最善手を保証するプレイヤーではありません。既存AIの方針を変更する機能でもなく、攻勢・守備・補給の条件を変えて同じゲームを観測するための再現可能な入力です。攻勢方針は既存プランナーの難易度別の安全基準も参照するため、難易度が違うケースを同一のプレイヤー入力列とは扱いません。

## 実行例

```sh
# 全3年代・各2勢力・3方針を6旬ずつ。各ケースは45秒・3000命令まで。
python3 -B tools/campaign-balance/run.py --output build/balance/daily.json

# 同じ年代・勢力で2つの種子を比較。
python3 -B tools/campaign-balance/run.py \
  --eras middle --factions shu --seeds 3 2026 \
  --turns 36 --max-seconds 120 --max-runs 6 \
  --output build/balance/middle-shu.json

# 以前ダウンロードした成果物と比較する。
python3 -B tools/campaign-balance/run.py \
  --eras middle --factions shu --seeds 3 --turns 6 \
  --compare build/balance/previous.json --output build/balance/current.json
```

`--difficulty easy|normal|hard` と `--backend python|rust` も指定できます。Rustには既存のネイティブコアの準備が必要です。通常の定期計測はPython側で実行します。複数年代に `--factions` を指定する場合、その勢力が各劇本に存在する必要があります。存在しない場合は失敗として記録し、別勢力に置き換えません。

旬数は1～360、ケース数は最大72です。要求数が `--max-runs` を超えた場合、先頭だけを実行せずエラーにします。各ケースには命令数の上限と5～600秒の制限を設け、さらに子プロセスを上限＋2秒で停止します。遅い1命令も無制限には待ちません。直近の原子的なチェックポイントを残し、時間切れ・命令数制限・旬数到達は勝敗未確定として集計します。

## JSONに残る観測

- ソースcommit、エンジンソースのSHA256、カタログの原始SHA256、方針版、劇本・勢力・種子・難易度・計算側・全上限。
- 実際に完了した旬数、ゲームrevision、命令集計・命令履歴SHA256、最終セーブSHA256・乱数状態、経過秒数。
- 初期／最終の各都市の帰属、および各旬の所有城数・帰属変更。
- 各勢力が初めて敵勢力へ出陣した旬。中立城への出陣はこの「初侵攻」に含めません。まだ出陣していなければ値はありません。
- 全勢力の都市所有者が変わらなかった最長旬数。停滞の観測値であり、不具合認定ではありません。
- 前線都市に健康で行軍・戦闘中ではない武将が2人未満の都市IDと、その状態を観測した回数。
- 各勢力の都市にある資金・兵糧・予備兵の合計、最小値・中央値・最大値。輸送中物資は都市在庫に足さず、輸送の到着・帰還は既存の回執集計で別記します。

`outcome` は実際に終了した戦役だけ `win/loss`、それ以外は `unresolved` です。`resolved_only_win_rate` の分母は勝敗が決まったケースだけで、1件も決まらなければ `null`。未確定率・予算打切り件数を併記し、時間切れを敗北として勝率を水増し／過小評価しません。

同じカタログ、種子、方針、難易度、実行命令が同じなら状態と乱数を再現できます。実時間の上限で切られたケースは実行環境によって到達点が異なり得るため、直接比較の対象外とします。`--compare` は共通する条件を対応付け、カタログ・完了旬数・上限打切りの違いを `comparable` で示します。JSONの実行時間自体は一致を要求しません。

## 通常CIとの分離

通常のPythonテストには、小さな制御カタログによる `CampaignBalanceTests` だけを含めます。実カタログの行列は [.github/workflows/campaign-balance.yml](../.github/workflows/campaign-balance.yml) で手動、または毎日06:20（日本時間）に実行します。日次は3年代を別ジョブにし、各2勢力×3方針、6旬、種子3です。公開を待たせる必須ゲートにはしません。JSON成果物は30日保持し、別の日付の同じ条件をダウンロードして比較できます。
