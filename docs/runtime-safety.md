# 本機執行、安全邊界與效能

本作的 Python 服務只監聽 `127.0.0.1`，一個程序管理一份戰役。這是本機單人遊戲的執行方式；若日後需要公開連線或多人遊戲，必須另外設計帳號、戰役所有權及伺服器授權，不能直接把本機 API 暴露出去。

## HTTP 邊界

讀取、操作及載入存檔共用本機請求檢查。`Host` 必須唯一且指向實際埠的 `localhost` 或 `127.0.0.1`；有 `Origin` 時，也必須唯一且屬於允許的本機來源。瀏覽器的跨站 Fetch Metadata 會被拒絕，僅首頁的 `GET /` 可在唯一的 `Sec-Fetch-Mode: navigate` 及 `Sec-Fetch-Dest: document` 下開啟靜態文件，供郵件確認與一般連結返回。首頁可接受經長度及字元檢查的 PKCE `code` 與可選 `sb_flow_id`，其他 query 拒絕；審計記錄一律省略 query 內容。這個例外不讀取戰役、不涵蓋 API、框架、子資源或寫入，仍核對 Host／Origin。沒有這些瀏覽器標頭的正常本機工具仍可使用 API，但仍須提供合法 `Host`。因此，本機腳本存取與雲端帳號登入是兩個不同的邊界。

POST 只接受明確長度、最多 2 MiB 的 JSON 物件。重複或含糊的長度標頭、傳輸編碼、截斷內容、重複 JSON 鍵、非有限數及過深資料會在執行指令前拒絕。連線、工作執行緒與可選審計記錄均有上限；上述不合法請求不會進入戰役操作。

靜態檔案繼續使用明列 URL 白名單與實際路徑檢查，不提供目錄瀏覽。CSP 限制腳本、Worker、圖片與連線來源。雲端只公開通過驗證的 Supabase publishable key；私人存檔的真正帳號隔離仍由資料庫的 owner RLS 與 UUID／revision 條件負責。程式碼本身不變更遠端 Auth、SMTP 或資料庫設定；經管理者另行核准的回跳網址修改記錄見 `docs/cloud-save-options.md`。

## 回應與存檔

指令與載入已經由戰役核心產生完整視圖，Session 現在直接為這份回應補上地圖、年代和勢力摘要，避免重算全部路徑預覽。戰鬥演出回執只隨原指令回傳，普通讀取、載入與重複結算不會重播。沒有把可變戰役狀態或寫入結果當作跨回合的快取。

瀏覽器明確接受 gzip 時，大型 API JSON 可壓縮傳輸。解壓後內容與未壓縮回應相同，API 仍使用 `no-store`。`/api/save` 保留原始 JSON 位元組，不參與壓縮或快取；存檔版本、校驗和、劇本 SHA 與亂數規則保持原有格式。

實際 HTTP 測試的主選單資料由 4,815,900 位元組壓縮為 695,181 位元組；這只代表既有HTTP工作負載的該份回應，不代表本輪瀏覽器優化或其他場景的傳輸量。

靜態資源使用 ETag 重驗證：未修改可回傳 304，修改後重新傳送，不建立無上限的伺服器資源快取。圖片與音樂不再額外 gzip 壓縮。

## 瀏覽器內的視圖與地圖重用

靜態Web版可選用`tk2-view-v1`／`view_cache`協定。Worker在首次回應提供人物基本資料、劇本說明及固定地圖設定，前端以內容token確認後，在後續回應省略已知且不變的資料。人物目前的登場狀態、所屬、所在地及生存狀態仍隨視圖更新。未協商此協定的請求保持完整回應；前端最多保留兩份劇本資料，不建立無上限的人物／劇本快取。`source/remake/view_transport.py`只封裝Worker回應，不修改戰役狀態；`game/view-cache.js`核對token、人物ID及報價資料是否完整，全部通過後才更新快取。token只識別顯示內容，並非帳號憑證或伺服器授權，不能放寬存檔、命令或雲端權限檢查。

行軍報價的重用依資料集身分、玩家、月份、有效城池及其歸屬、發現航路的組合失效。資料集身分涵蓋道路形狀與行軍規則；城池建立或消失、易主、季節改變及探索成功，均不能沿用已失效的報價。這是唯讀報價與傳輸資料的重用邊界，不表示所有路徑計算都已快取。戰役判定仍由目前狀態執行，不改命令順序、費用、亂數抽取或保存內容。

本輪以目前25份劇本預覽、217年7月魏勢力、種子2026的新局為工作負載，在相同行軍條件且前端已知static與quote token時，BrowserRuntime完整JSON回應為21,880,743 UTF-8位元組，compact回應為767,215位元組，減少96.5%。讀取前後的`export_save()`原始字串嚴格相等。這只量測該次Worker回應的序列化體積，不代表首次載入、所有場景、網路總流量或操作耗時均改善96.5%；首次或行軍條件改變仍傳送所需資料，也不表示路徑搜尋已全部快取。

地圖以完整視覺輸入判斷是否重用原SVG與導航實例。相同日期、城池歸屬、位置、文字、路網、預覽及選中／高亮狀態時，略過道路、橋梁及整張SVG的建構與DOM替換，保留相機、焦點及手勢狀態。任一相關視覺輸入變更時安全重建；世界範圍改變仍依既有規則復位相機。處理器持續綁定目前戰役快照，避免保留舊狀態的命令入口。

## 本地自動恢復點

`game/autosave.js`在瀏覽器獨立儲存區保留最多3份自動恢復點，建立時機為新戰役、旬末或推進、戰鬥結果／戰後結算、成功載入後。保留引擎匯出的原始JSON字串，不重排存檔、不加新存檔欄位，也不覆寫手動存檔或雲端槽位。恢復點的標籤與保存時間存在外層容器，不進入遊戲狀態或亂數。

背景匯出完成前會再次核對戰役與操作版本；開始新操作、換局或載入會使延遲匯出失效。儲存空間不足時嘗試保留較少份數，仍失敗則保留既有恢復點並提示手動保存，不阻止繼續遊玩。儲存封鎖、損壞項目與過大資料不會被當作有效恢復點。

恢復必須經玩家選擇並明確確認，再由原本的載入流程驗證劇本SHA、校驗和及進度版本。未確認、過期、損壞或不相容的項目不能自動取代目前戰役。瀏覽器資料可能被清除，關閉頁面前仍應確認保存結果，重要進度可下載JSON或手動保存到雲端。

## 驗證方式

```sh
python3 -B -m unittest discover -s tests -p 'test_remake_http_server.py' -v
python3 -B -m unittest discover -s tests -p 'test_remake_session_cache.py' -v
python3 -B -m unittest discover -s tests -p 'test_remake_battle_presentation.py' -v
node tests/test_remake_autosave.cjs
node tests/test_remake_map_render_cache.cjs
node tests/test_remake_browser_client.cjs
```

自動恢復點、地圖重用及啟動介面的CJS測試分別檢查保存／確認邊界、實際渲染函式的DOM重用及失效、啟動進度與重試生命週期；這些檢查不取代正式瀏覽器與線上驗收。

HTTP 測試在獨立埠驗證不合法來源、資料邊界、壓縮與資源重驗證，並核對拒絕前後的進度及亂數。Session 測試覆蓋新局、一般指令、載入、AI／戰果冪等、演出回執及失敗回滾。

同一程序、相同 25 劇本和 217 年魏勢力的五組本機基準中，新局指令的視圖生成從每次兩份改為一份；中位耗時從 1154.600 ms 降至 616.058 ms。開局、新局、編兵、保存及載入等十份回應的原始 JSON 位元組與狀態／亂數均相同。這是該工作負載的本機量測，並非所有裝置或整段遊戲操作的效能保證。
