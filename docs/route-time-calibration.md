# 路線幾何與行軍計時

全29個劇本的已知與探索路線，由目前地圖的同源曲線重算。`game/build_route_geometry.cjs` 讀取原生道路描邊、已確認的路口修正、區域道路及海港接道，以瀏覽器實際 SVG 曲線量取弧長，輸出 `game/config/route-geometry.json`；缺失路線會失敗，不以直線默認補齊。畫面真正經過其他城標的陸路會編譯為按順序相連的實際城間路段。

本圖為藝術投影，各區比例不一致。`game/route_timing.py` 以每條路自身的地理端點距離標定，再乘以同一曲線的弧長／畫面端點直線比率。這是本作的玩法估算，不是實測古道長度。

- 每段陸路公里數＝該段城池間球面距離 × 該段曲線弧長／畫面端點直線長 × 既有地形迂迴係數。以平地30、山地15、沙漠20公里／日計算。真正經過已登場城市時以連續路段中轉，各段天數向上取整；中間城市尚未登場時，沿相同實體道路繼續前進，合計各段距離後按連續旅程計時，不憑空停城。跨分水嶺的山道分類與兩端城市地形分開。
- 航路分為「城池至港口陸路、港口間海路、港口至城池陸路」。兩端接道各以城池與該港口的地理距離及本段曲線比例標定；海段以兩港地理距離及海上曲線比例標定。原來的中間地理航點保留作參考，實際繞行改由目前水上曲線反映，不重複計算兩套迂迴。
- 平靜海況按海段70公里／日、陸段30公里／日，加2日登船時間。既有季風仍只調整海上航速，順風120、逆風7.5公里／日。
- 陰平道單向限制、平路基準2倍時間及三分之一存活、子午谷7–9月4倍／其他月2倍時間與既有減員、海上風暴減員和亂數抽取規則維持原樣。這些倍率套用重算後的路線距離。
- 同一次行軍先合計各路段天數，再按每旬10日向上取整安排抵達。橋面本身沒有另加等待天數。

共用道路只在畫面繪製一次；一支部隊仍須走完整的起點至終點路程。`city_sections`記錄真正經城的順序，`transit_variants`是連續有效城池間的不可變報價；執行時只採相鄰有效停靠點，不能以父路線或跳城變體繞過已登場城池的控制。中間尚未建置或開局已省略的城市不會截斷實體道路，也不提供城內補給。特殊陰平與子午谷路段維持既定風險結算，不被一般中轉拆散。

重建順序：先完成地圖／港口接道，若原生 PNG 有改動則先更新批准雜湊，然後依序執行：

```sh
node game/build_navigation_geometry.cjs
node game/build_route_geometry.cjs
python3 -B game/build_campaigns.py
node game/build_map_bridges.cjs
python3 -B game/build_map_presentation.py
python3 -B game/build_campaigns.py --check
```

Python 與 Rust／WASM 都讀取這批重算後的公里數、天數及風險資料；不用另寫兩套距離演算法。瀏覽器 Worker 的配置快取按劇本和「幾何＋計時公式」雜湊區分，新資料不會復用舊報價。

路線資料改變後，存檔的目錄身分也改變；不默認接受舊目錄 SHA，請建立新戰役使用修改後道路。相同目錄下的存讀繼續校驗不可變路段ID、出發年月、日數、糧食收據與風險收據。驗證按出發時有效城池和道路年代進行，不能把新成立城池倒套到已在途的舊旅程。讀檔不重新尋路、扣糧、抽風暴亂數或結算減員。程式未加入通用舊檔相容分支。

道路史料、207年盧龍修復界點、上游軍航排除與尚待考定的渠網，見[道路史料與分階段修正](road-history-upgrade.md)。耗糧按旅程實際行進、等待和返程日數持續結算；真正停靠本方城池依現有規則補給，畫面共線本身不產生補給。
