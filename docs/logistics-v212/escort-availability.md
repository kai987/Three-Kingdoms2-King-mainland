# 押运人员可用性

每次来源城候选扫描产生一行。驻城人数、技术上可用人数、轻装人数和真实排除原因分别保留。同一武将可以同时有行军、内政委任、运输冷却或健康方面的排除证据。原版检查先确定剩余命令书和同城是否已有运输，再看政策上限、留守人数和人员资格。army-requests.csv 对应实际接济报价，escort-availability.csv 记录扫描证据及候选筛选结果。

对原始原因 no_spare_officer，先分析运输权限和驻员名单。驻城人数没有超过政策规定的留守下限时，优先标为守备留员，人员全在行军时标为在途。人数足够但可用人数为零时，按战斗、在途、委任、运输冷却、体力顺序选一个有证据的主因。对策略 211，战争计划标记本身没有拦截作用。策略 212 的自动接济会实际剔除尚未发运的战争计划人员。

officer_busy 使用现有运输冷却记录。officer_reserved_for_defense 同时可反映政策留员下限和计划器的实时守军检查，两者在原始原因中有区分。no_legal_troop_reassignment 仅在实际尝试轻装评估而无法合法调整时，在 escort-assignments.csv 留痕。

21 局 F3 观战确认 30,347 次报价，其中 23,423 次为 no_spare_officer。按主因计数，22,679 次触及留员下限，720 次没有驻员，24 次驻员均在途。其余报价包括 3,364 次路线不通、3,128 次已有运输、317 次粮不足、21 次需求已有覆盖、8 次效率低，以及 86 次进入实际发运。候选报价比例不能用作独立补给需求失败率。
