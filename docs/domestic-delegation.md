# 內政委任與前線運輸

本次實作把地方文吏納入一般武將系統，再加入雙官委任、自動人事、募兵訓練及實際在途運輸。玩家與電腦共用同一組執行函式、費用、機率、城池容量與行動限制；電腦只多了合法人選和方針的預設選擇。界面提供繁體中文與日文。

## 規則的來源與範圍

「任命官員、依能力執行內政並支援前線」參考《三國志14 威力加強版》的委任概念。官方說明可參照[內政](https://www.gamecity.com.tw/manual/sangokushi14/wpk/4200.html)、[階段流程與月收入](https://www.gamecity.com.tw/manual/sangokushi14/wpk/3200.html)及[據點指令的異動與運輸](https://www.gamecity.com.tw/manual/sangokushi14/wpk/6200.html)。本文件中的百分比、費用、士氣和自動工作限制是本遊戲的設計規則，並非聲稱還原該作品的內部公式。

一旬固定10天，每月30天。每座城最多99人，出戰上限仍為10人。歷史人物使用既有整數ID；地方文吏使用獨立的 `clerk-000001` 命名空間，不占用歷史人物ID，並直接加入該城的一般武將名冊，可編兵、出戰、轉屬、運輸及繼承。都市情報提供忠誠、武、知、德、經等普通武將資料；地方文吏仍保留原始生成紀錄和每月薪俸。

## 兩名委任官

每座城分別任命一名商農人事官（`civil`）和一名募兵訓練官（`military`），兩職不得由同一人兼任。新委任時，人物必須屬於本勢力、健康、在該城且未出征。出征或欠薪時暫停履職；死亡、轉屬、調離或城池易主後撤銷失效委任。暫停中的原職及使者可以保留，修改預算不會強迫重新任命。

商農收益按實際履職累積：完整一旬計 `知×2` 點，親自登用／勸誘當旬計 `知×1` 點，未履職計0點。月初既有日曆服務先發放原本的基礎金糧，再發放上月額外收益：

```
額外金或糧 = floor(月基礎收益 × 40 × 上月履職點 / (100 × 99 × 6))
```

因此知99、三旬完整履職的增益為40%；中途任命、出征或親自出使會減少增益。月／旬收據防止讀檔或重複呼叫多次入帳。舊地方文吏的個人被動收益停止，避免和新制度重複加成；月薪仍依既有服務結算。

## 自動登用與勸誘

可分別開啟在野登用和鄰近敵方勸誘，設定本旬人事預算、最低成功率、金糧保留量及不招募名單。勸誘可另選本城高德使者。候選範圍、成功判定與扣費都沿用手動服務；目前標準費用為登用60金、勸誘100金，實際以劇本 `rules` 為準。

排序可選武、知、德或綜合；綜合依三項能力中最高、第二高、第三高依序比較，再比較成功率、距離及穩定人物ID。指定單項優先時，先比該項，再比綜合能力。一城每旬只執行一次主動城市行動，手動操作先行；同勢力同旬不對同一人重複嘗試，自動失敗後冷卻三旬。操作者已行動、在途、欠薪或無效時暫停。缺員城市有合法地方文吏候選且滿足條件時，也可用相同費用完成雇用。

方針可重排 `personnel`、`recruit`、`transport` 三種主動工作的優先序，每項恰好出現一次。持續商農和訓練本身不消耗城市主動行動。電腦前線預設優先募兵，後方優先運輸，避免同一類工作長期餓死其他工作。

## 募兵、訓練與士氣

自動募兵量上限為 `100＋武`，並受目標預備兵數、預算、城市資源保留量及資源上限限制。每100名士兵的費用為 `20－floor(武/10)` 金和30糧，不足100人的費用向上取整；無資源時不會產生負數。募得的新兵士氣50，按人數和城市現有兵力加權。

城市初始士氣70，上限100。每旬訓練增長 `2＋floor(武/25)`，每1000名實際在城士兵支付1金、2糧，兵數單位向上取整；無兵、士氣已滿或不滿足保留量時不扣費。訓練不計入已出征部隊。出征時記錄士氣，友軍調動抵達時和當地駐軍加權；普通戰鬥的士氣係數以70為基準，限制於80%至110%。

## 真正在途的前線運輸

運輸是存檔中的獨立 `convoys`，不會把後方資源即時加到前線。出發時扣除金、糧、預備兵及行軍口糧；抵達時才向目標城入帳和轉移隨行武將。兵力守恆帳包含在途預備兵，途中減員記入 `soldiers.lost`。

來源城可設定金糧、預備兵及實際留守武將的最低保留量，目標城可設定所需數量和每次運輸上限。已在途同勢力物資會從需求扣除；已出征人員不能當成留守人員。委任官預設不作為隨行人選。每個來源城同時最多一支運輸隊，抵達的人物／城池另有三旬收據，減少來回搬運。

預設只走已知、安全的陸路，允許穿越空城，終點必須是友城；會尋找較長但安全的繞路。海路與陰平道／子午谷等特殊道路須顯式允許，未知航路不作為自動補給路。玩家主動派運和電腦補給仍受相同保留量、行動和99人容量限制。

運輸口糧為既有路線的隨行武將口糧，加上 `ceil(運送預備兵×路線天數/1000)`。時間、地形、季風及危險判定使用既有行軍引擎；海難或特殊道路按既有生存率分配隨行部隊和運送預備兵的存活量，金糧也按相同比率縮減，每一段風險僅結算一次。

目標城易主或中途道路被敵軍阻斷時，建立需要實際時間的返航；優先原城，再選可達的友城。退回目前安全節點也至少花一旬，不能即時退款。滿員、資源已達上限或無安全返程時等待；等待不重擲天氣。來源城陷落、隨行人物死亡或轉屬，不會讓貨物憑空消失。勢力已無任何友城可接收時明確結算為棄置，預備兵計入損失。每次最多保留16段返航紀錄。

## 界面、事件與資料驗證

設置命令為 `set_domestic`、`set_logistics`；實際派運為 `dispatch_transport`。讀取 `catalog.domestic` 和 `catalog.logistics` 僅生成預覽，不扣費、不擲亂數、不執行行動。前端使用權威的 `marching_officers` 禁用在途人物；關閉的自動運輸方針不建立昂貴的全地圖預覽。

對玩家發出旬／月內政成果、運輸出發、抵達、返航和天候損失圖文事件；電腦使用同一結算和內部報告。月事件中的金糧是額外收入，旬事件中的金糧是募兵訓練花費，避免把收入和支出混用。

所有新存檔字段嚴格驗證型別、數量上限、人物歸屬、收益收據、路線幾何對應、出發日期／回合、抵達時間、風險快照及貨物減員鏈。布林值不接受為人物ID，無效命令保持存檔與版本號不變。這次不新增舊格式存檔的相容轉換。
