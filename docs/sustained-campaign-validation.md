## 長い命令列の四路照合

`parallel_saved.py`は既存の`replay_saved.replay_leg`を四つの独立したプロセスで呼びます。新しい戦役方針や乱数探索を追加する機能ではなく、すでに受理された**同じ命令列**を照合する時間を並列化するものです。

```sh
python3 -B tools/campaign-checkpoints/parallel_saved.py \
  --scenario 217-07 --start-save /tmp/evidence/origin.save.json \
  --journal /tmp/evidence/commands.jsonl \
  --provenance /tmp/evidence/replay-provenance.json \
  --turns 12 --max-commands 4000 --max-seconds 600 \
  --output-dir /tmp/evidence-four-legs
```

四路はPython-observed／Python-baseline／Rust-observed／Rust-baselineで、元の秒数・命令数・旬数の上限は**各legのまま**です。公開`--leg`で一つのlegだけを実行する場合も同じ入力検査と上限を使います。一つのlegのpassedは四路合格ではありません。

親は起点・catalog・命令列・独立算出したtranscript・全source指紋・roleを各workerと照合します。各命令の状態／phase／turn／RNGは従来のreplayで確認し、最後は完全な原始saveとJSONLも比較します。欠落、誤role、非object JSON、不正count／hash、部分実行やsource変更を合格にしません。worker PIDは起動ごとに記録し、超過時と親の終了処理は自分が生成したworkerだけを停止します。起動／終了I/O用60秒の猶予は、ゲーム命令の予算追加ではありません。

賞賜の公開載荷には`kind=gold/treasure`があります。検証wrapperの命令名引数も`kind`だったため、ゲームへ届く前にPythonの引数衝突が発生しました。Observer／soak／balanceの三つの工具関数で命令名をpositional-onlyにし、既存のゲームAPIへ載荷をそのまま渡します。従来の選択処理や相手AIは変更しません。金賞賜の両backend保存一致、四つの実subprocess、未知・欠損・超過workerの失敗閉鎖を工具回帰として確認しています。
