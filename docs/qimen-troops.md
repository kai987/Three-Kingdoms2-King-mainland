# 奇門遁甲：高状態の日界損兵と経験

本段階は現行の戦術格局の**奇門遁甲ID15だけ**を接続する。従来の自己`guard=2`を新施放に使わず、敵隊に保存可能な高状態を付ける。[虚兵](phantom-troops.md)・[連環](chain-troops.md)を保ち、旧保存の出所不明な`guard`や`stunned`は変換しない。自由布陣、一般成功門の未確認環境、原AIの完全再現は別課題である。

## 原版で確認したこと

未変更の使用者所有ROM（SHA-256 `26c8d921ff5c208191f136480bcd8d7e89c2e4ed40a0ac7b51482bcb52fe2b82`）と既存研究アーカイブを照合した。追加観察は宣言したRAM条件で独立6502が真の`CD78/CE40/CF60→EE07→A006/D7FB`を実行したもので、自然な一戦のUIを全再現した証拠ではない。根拠の共通部分は[状態監査](original-tactic-status-audit.md)を参照。

| 原入口 | 確認した規則 |
| --- | --- |
| physical12 `B5A6`／一般門`B7BE` | 成否を先に判定。成功時のみ低2bitを取り、高状態を攻方6..9・守方5..8に設定 |
| physical9 `CD78→CE40` | 戦期・食糧終止が先。低状態の走査後に高状態へ進む |
| `CF60` | 原ID109が20槽のどちら側にいても有効。人物状態低2bitが3なら除外。兵0・体力0はそれ自体で除外せず、原資格値の武0では高分岐が止まる |
| 高`CE40` | 原slot順にカウントを1減らし、各隊80..150兵を飽和減算。最後の1→0にも損兵。低状態のような無傷害時計ではない |
| `CE94–CEA3→D7FB` | 処理した全対象の扣後兵数の低byteを合計し、最後に半分を切り捨てて固定ID109へ経験を加算 |

守方slot5、攻方slot15、陣営sign反転のいずれも同じ資格結果だった。諸葛亮が不在／除外なら低状態3→2は進むが高状態20は止まり、傷害抽選と経験呼出も止まる。日界ごとに資格を調べ直す。走査開始後に諸葛亮自身が0兵になっても、その日の残りを途中で取り消さない。

真日界は0兵になった目標をその場でslotから除かず、人物除去flagや残高カウントも消さない。次の日界でも、その保留0兵slotがあれば傷害抽選する。**その後の原版UIがいつ正式移槽するかは未確認**であり、原版が0兵即時除去すると書かない。本作では戦場名簿に残る隊をslotに対応させ、0兵でも高状態を保持する。実際の名簿除去・投降記録は除外し、戦闘終止後は更新しない。旧低状態の0兵除去規則はこの変更で広げない。

## 明示する本作の適応

一般成功門`B7BE`の環境対応は未確認のため、成功率は既存の`clamp(60 + floor((知−相手の知)/2),10,95)`。成功判定は`SeedRng.next()%100`を一回、成功後だけ`next()%4`を一回使う。各日界の各高対象は`80 + next()%71`を一回使う。原機の0..70棄却抽選・NMI列と同じ生抽数とは主張しない。プレビュー・AI評価・イベント再生は抽選しない。

原高走査のslot順は損兵乱数の配分に関わる。一方、本作の過去の籠絡は隊をリストから外して別側へ追加し、旧保存には元slot番号がない。座標やIDから原slotを推測しない。**初めて奇門が成功した時点**の現守方順→現攻方順を`high_order`へ保存し、以後の籠絡や保存読込で並べ直さない。新しい原slot復元の主張ではなく、本作の固定処理順である。

原経験増量はそのまま残す：

```text
counter = Σ（本日処理した高対象の扣後兵数 % 256）
増量 = floor(counter / 2)
```

実損兵の半分ではなく、目標ごとに先に割らない。固定の諸葛亮へ授与し、現所属陣営や施放者IDで付与先を変えない。20隊の正常兵数域でcounterは最大5100、増量最大2550。旧経験49999を足しても52549で、原16bit回り込みは起きない。

原`D7FB`は一回で最大一級、永久武力増加を伴う。本作はSAN14由来profileと戦場武力の一致、`tier == experience_tier(experience)`を検査するため、ここは既存成長契約を使う：`min(49999, experience + 増量)`後に本作tierを同期し、基礎武力・戦場martialを増やさない。原CPUの20隊各扣後255、旧経験999の例は3549となり原tier0→1、武75→79だった。本作同値はtier3になる差を明記する。自然な新施放は現在諸葛亮tier6以上のみだが、低階保存境界を隠さない。零増量の原関数呼出は不整合tierを補上げ得るが、本作合法保存にはその不整合を許さない。既存の戦後経験報酬は別途従来通り結算する。

## 支払、時計と兵員帳

合法な確認は10機動力を支払い、成否前に実際の対象の旧状態を解除する。失敗は成功門一回のみ。成功すると虚兵／連環／奇門の単一記録を上書きし、護盾は新設しない。普通接敵、再施計、帰順・名簿除去の解除は共用規則、直接単挑の開始だけでは解除しない。既定の「支払確認→実対象解除→本作伏兵→生存時だけ成否」の適応を保ち、原伏兵調度全体まで再現したとはしない。

攻方→守方→次の日の攻方で、両者の行動終了後だけ更新する。戦闘糧・30日終了を先に結算し、継続時に低時計、諸葛亮資格、高時計・損兵・経験の順に実行する。日界再呼出は二重処理しない。無諸葛亮なら高時計と損兵が止まり、日同期と低時計は進む。

損兵は`battle`の現在兵だけを減らし、体力・訓練・装備・旧護盾倍率を掛けない。`officer.troops`と`unit.start`は開戦保留量のまま、既存戦果結算で一度だけ損失を全体帳へ計上する。日界後には勝敗判定し、全滅済みの側へAI行動を続けない。双方が当該走査で0兵なら既存の双方敗退規則を使う。

## 保存、表示とAI

任意のv1条件帳簿に`qimen`の残数1..9を追加し、高状態がある場合だけ`high_order`を必須にする。各隊一状態、順序は全名簿IDを一回ずつ、総容量20。既存の3欄のみの虚兵／連環保存はそのまま受理し、読取りだけで新順序や奇門を補わない。高状態を消しても順序は保持し、未知kind・重複／不足／余剰順序・壊れた現在座標は拒否する。

画面は敵隊の奇門カウント、移動禁止理由、施計成功率と日界損兵範囲を表示する。日界図文イベントは実際の隊別損失と実際の経験増量の確定済み記録を再生し、追加機動力や乱数を消費しない。既存の像素素材・対象側の粒子演出を使い、自軍護盾を描かない。この演出を原奇門動画の実キャプチャとは表記しない。

AIも同じ資格・支払・抽選・損兵・経験・存読サービスを使う。四持続値を平均し、残戦期で切った日損と移動封鎖を推定するのは本作のヒューリスティックで、原AI選択順位ではない。既に奇門の対象や無利益の施計を避け、普通攻撃の反撃を取り消す効果としては数えない。計画中に抽選せず、対象ごとに追加経路検索しない。

## 繁體中文摘要

奇門15改為敵隊高狀態：成功後攻方6..9、守方5..8，限制移動而不禁止合法攻擊／施計。諸葛亮仍在任一方戰場名冊時，日界先減1再扣80..150兵，最後一次仍扣兵；0兵但未除名仍保留高計數並抽樣。缺席／投降記錄時暫停高時計，低時計照走。原日界本身不移除0兵槽，後續原UI清理時點仍未閉合。

保留原扣後低byte合計再除2的經驗量，但採本作49999上限、同步等級、不永久加武；B7BE知差成功率、SeedRng餘數抽樣及首次施放時固定當前名冊順序均為明示適配。舊guard／stunned不推定轉換。圖文、動畫與預覽只呈現已提交結果，不重抽或重扣。自由布陣和未確認成功率／原機RNG／部分AI差異仍是後續範圍。
