# 進軍経路の来向に応じた初期配置

新しい戦闘の配置を、既存の都市別戦場と[原版30都市の配置資料](../game/config/references/original-battle-deployment-v1.json)から純粋に計画する。都市座標、道路、兵数、機動力、乱数を変更する処理ではない。実装は[独立モジュール](../source/remake/battle_deployment.py)、根拠の抽出・検査方法は[原版資料の説明](../tools/battle-deployment-original/README.md)に分けている。

## 原版資料と本作の地域対応

固定ROMのSHA256は`26c8d921ff5c208191f136480bcd8d7e89c2e4ed40a0ac7b51482bcb52fe2b82`。目標都市の原隣接表から出発側の原都市番号を探し、同じ隣接レコードの攻撃側区画と守備側区画を組にして使う。番号は都市ごとの表索引で、NESWの方角コードではない。

原隣接は128本、攻撃側の辺縁区画は91、守備側の中央区画は53ある。守備側主将の先頭候補は、それぞれの原戦場の城砦に一致する。双方に同じ区画・地形の根拠を使う。新しいプレイヤー参加戦では[逐将の手動配置](manual-deployment.md)を重ね、AIは[原作の武将比較と四組の配置](ai-deployment.md)から先に計画する。原AIにはない矩形・占有の安全検査を本作では共通化しており、その差は原式と分けて記録する。

現行115都市の[戦場対応表](../game/config/battlefield-city-bindings.json)は、原画像の地域利用・同名ラベルの対応を含む。全都市のROM名字形を同定した表ではない。したがって保存値`policy: native_pair`も「対応した二つの**原テンプレート**に、本物の原隣接レコードがある」という意味であり、現代の拡張ノードを原都市そのものと認定する値ではない。画面や説明でも既存の地域利用・同名対応の出典ラベルを残す。

## 経路の最後の都市を使う

複数都市を通った行軍では、戦闘開始時に実際の経路`quote.path[-2]`を`arrival_city`として渡す。戦略的な出発都市`battle.source`と取り違えない。直接の出征で省略した場合だけ`battle.source`を使う。

1. `arrival_city`と目標の原テンプレートが原隣接表にある場合、記録された攻守両区画をそのまま選ぶ。現在の地図座標による推定より優先する。
2. 原隣接がない場合、現在の戦略地図上の「目標から最後の都市へ戻る」ベクトルを求める。画面の右が正のX、下が正のYで、進行方向とは逆向きの来向ベクトルである。
3. 原城砦から各攻撃側辺縁矩形の中心へ向かうベクトルを比較し、来向との角度が最も小さい区画を選ぶ。その隣接レコードに対になる守備側中央区画を採用する。
4. 同じ矩形や同角度なら原隣接都市番号の最小値を選ぶ。座標がない、またはベクトルがゼロの場合も、この決まった順序を使う。浮動小数点の角度計算は行わず、符号付き内積と長さの二乗を整数で比較する。

2以降は`policy: regional_direction`と明示する本作の地域適応である。原ゲームに115都市分の配置表が存在すると主張しない。また、この段階は最後の**都市間**来向であり、海岸の上陸点や道路曲線の最終接線まで再現するものではない。

## 原候補の安全な利用

原`C3CB`は順序付き候補から占有点を飛ばすが、手動配置用`C447`の矩形や現行表示枠は検査しない。証拠には表示外、矩形外、重複の計13記録があるため、参照JSONの値は消したり丸めたりせず保存している。

本作の新配置では、原候補を元の順序で読み、次を満たすものだけ使う。

- 上限を含まない原合法矩形内にある。
- 現行31×19の表示範囲内にある。原メタデータ行`packed_y15`は除き、`packed_y16..19`を表示`y15..18`へ変換する。
- 同じ候補や、先に配置した別部隊と重ならない。

山・水も原作の合法配置に含まれるため、地形0・1・2・5だけという旧自動配置の制限を使わない。この純粋な既定配置計画は守備側を先に置き、主将の城砦候補を保ってから攻撃側を置く。各区画は安全な原点を少なくとも攻撃側13、守備側14個残し、128組すべてで各10部隊・合計20部隊を重複なく置ける。範囲外の候補を境界へ押し込む補正や、新しい点の創作はしない。

プレイヤー参加戦の手動配置段階では、この全員の既定計画を人間側の占有点として先取りしない。AI側を先に固定し、人間側は確認済みと現在将だけを配置する。新しいAIの候補順は武力比較後のグループ游標によるため、この純粋な全員の既定計画と混同しない。現在将の手動既定点は毎回表の先頭から占有点を飛ばして再選択し、自由格は原矩形と表示範囲から求める。主将は城砦から移動でき、後続将は空いた点を使える。手動確定と保存の境界は[別の契約](manual-deployment.md)で管理する。

この安全フィルターは原版の証拠と分けた本作の適応である。選択順は入軍時の武将順序を保ち、勝手に武力順へ並べ替えない。配置だけで兵数・体力を変えず、機動力を支払わず、乱数も抽選しない。

## 純粋APIと保存値

```python
planned = battle_deployment.plan(catalog, battle, field, arrival_city=last_city)
# planned == {'positions': {'人物ID': {'x': int, 'y': int}, ...},
#             'provenance': {...}}
```

`field`には既存の原戦場の`classes`と`camp`を渡す。既知の目標都市なら、その原テンプレートの城砦との一致も検査する。未知のテスト都市IDは`None`を返し、呼出側の既存アンカーfallbackをそのまま使える。新しい軍勢は各軍10人まで、部隊IDは両軍を通じて一意である必要がある。

`provenance`は次の閉じたフィールド集合だけを持つ。

| フィールド | 意味 |
| --- | --- |
| `schema` | `tk2-battle-deployment-v1` |
| `arrival_city` | 行軍経路の最後の隣接都市。直接出征時は出発都市 |
| `target_map` | 目標の原戦場テンプレートID |
| `arrival_map` | 来向都市の原テンプレートID。対応がない場合は`null` |
| `paired_source_map` | 選択した原隣接レコードの原出発側テンプレートID |
| `attacker_zone` | そのレコードの攻撃側区画索引0〜3 |
| `defender_zone` | 同じレコードの守備側区画索引0〜1 |
| `policy` | `native_pair`または`regional_direction` |

`validate_provenance(catalog,battle,field,record)`は、型とフィールド集合を検査し、この来向から区画選択と出典情報だけを再計算する。現在の位置、残機動力、兵損、現在の軍勢構成は参照しない。従って移動後や籠絡による19対1になった後でも、保存された出典を確認するために軍勢を再配置しない。正常時は`None`を返し、矛盾時は`ValueError`を送出する。

`plan`自体も、既に`extended.tactical`を持つ戦闘への再配置を拒否する。旧戦局に新しい出典記録を後付けしたり、読込時に位置や機動力を補充する用途には使わない。現在の位置は既存の戦術状態で保存し、配置出典は任意の`extended.deployment`として分ける。新出典、計略の新状態、手動準備記録のいずれかがあるのに戦術座標が欠けたデータは、破損した新戦局として拒否する。旧アンカーへの自動置換で座標や機動力を再発行せず、読込前の進行を保つ。これらを持たない真正の旧形式だけ、従来の一度限りのアンカー移行を使う。

`placement_zone(catalog,battle,field,side)`は保存された出典を検証し、その側の可視合法格`cells`、表示座標の半開範囲`bounds`、安全な順序付き`defaults`を返す純読取APIである。現在の軍勢を再配置せず、乱数やAPを変更しない。

## 検証

[純粋規則の10項目](../tests/test_remake_directional_deployment.py)では、原都市の異なる二つの来向、最後の都市の優先、128原隣接の20部隊配置、115都市の地域fallback、原表異常の安全除外、山水、ゼロ来向の平手、純読取、移動・転属後の出典検査、閉じた型境界及び未知テスト都市を確認する。[実際の戦役開始・保存読込の検証](../tests/test_remake_deployment_campaign.py)では、公開行軍・到着の実兵糧、初期配置とAI先手、移動後の保存、旧戦局、19対1／20対0の帰順編隊、不正出典の原子拒否を扱う。方向選択だけを接続した段階の成果を保ち、今回追加する逐将配置の検証は[手動配置の範囲](manual-deployment.md#115都市への適応と検証範囲)として分ける。今回の全体回帰とブラウザー結果は同文書に集計し、従来の検証説明とは分けて記録する。

```sh
python3 -B -m unittest discover -s tests -p 'test_remake_directional_deployment.py'
python3 -B tools/battle-deployment-original/build.py --check
```

## 繁體中文摘要

新戰鬥優先按最後經過城池與目標城的原模板真實鄰接，選同一記錄配對的攻守區；其餘115城地域重用按最後來向選最接近的原邊緣區，明標本作區域適配。索引不是東南西北。原點依原順序去重，限制原矩形與可見格，允許山水；全128原鄰接均能放置20隊且不重疊。新玩家戰鬥另有[逐將布陣](manual-deployment.md)：AI先以[原武力比較與四組游標](ai-deployment.md)計畫，本方未輪到者不占位，每將重掃手動預設首點。原AI不做矩形／占位檢查，本作玩家與AI共用安全條件仍是適配。部署不扣機動力、不抽亂數。未知測試目標回傳`None`保留舊fallback；來源驗證只重算元資料，移動、歸降與舊戰局讀檔都不能因此重新布陣。
