# 观战数据与口径

生产观战命令提交后才导出流水。观测工具以只读包装记录结算结果、真实候选返回值和实际运输回执。D 与 E4 的观测开关对照都使用每旬紧凑存档和内含随机数状态的校验值。

| 表 | 一行所指 |
| --- | --- |
| `monthly.csv` | 开局及每三旬采样一次，含累计实际口粮、兵员、市场与战斗 |
| `factions.csv`、`cities.csv` | 同时点逐势力、逐城快照，现役的登记与实驻口径分列 |
| `capture-recovery.csv` | 每次占领至该城再积一个月口粮或观察期结束 |
| `shortages.csv` | 一次真实驻城粮食欠付，实际应付、已付、缺粮、减员及周围余粮 |
| `supply-requests.csv` | 调粮、采购或援助请求，按渠道区分，不把一个请求内的候选视为独立发运 |
| `convoys.csv` | 一次运单发出、卸货、改返或返抵，沿 `convoy_id` 对账 |
| `troop-flows.csv` | 各类实际募兵、自然预备兵、发队、兵力损失和人员转移 |
| `battles.csv` | 实际战斗结果与战场粮账 |
| `war-quotes.csv` | 一次实际报价、候选或复核，失败原因可并列 |
| `war-quote-groups.csv`、`war-plans.csv` | 报价按旬、势力、目标汇总，与实排独立计划分别计数 |
| `route-changes.csv` | 一次改道或中止等实际操作，附同一时点的新旧路程与预计路粮 |
| `action-capacity.csv` | 每个已归属势力的旬末状态与连续阻塞长度 |
| `run.json` | 引擎提交、规则、种子、难度、寿命、剧本哈希、配置、流水行数与计时 |

每千城旬同时给出所有城市和实际已归属城市两个分母。观察窗口内送达率以同期实际装载粮和交付粮计算。已结束批次只计已交付、实际返抵或已物理放弃的运单。返回命令本身不会关闭批次。

缺粮有余粮比例使用当旬实际缺粮记录和对应潜在余粮。在途可能赶上缺口的数据以已知截止日为准。三旬缓解率是已有缺粮的可观测到货案例中后续三旬均无再次缺粮的比例，同时发生的购粮与自然收入也会影响它。

独立战争计划按势力、计划创建旬和目标识别，重复报价只作为评估计数。每活跃势力年交战指标以全局交战数除以活跃势力旬数再乘 36。小势力抽样单位为每局开局掌握 1–3 城的势力，期末仍控至少一城即存续。

货运保留源城、目标、发运日、计划到货日、交割日、路线天数、发运及交割量。统计的挡关理由可同时成立。展示替代路线的报价和实物账分别使用 `route-changes.csv` 和 `convoys.csv`。同一负担发生在不同阶段时，以实际结算流水为准。

`0` 代表实测零值。 `not_applicable` 代表组别未启用对应机制或指标没有可计算分母。 `not_collected` 代表当前导出无法严格还原。原始 JSON 选填处的 `null` 代表该行无可用值，例如尚未交付。字段覆盖的具体例外见已知问题。
