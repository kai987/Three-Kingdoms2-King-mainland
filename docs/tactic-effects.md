# 火箭・籠絡の原版算式と本作への接続

この段階で変更するのは、火箭の軍糧損失と籠絡の成功判定だけ。他の14計略の効果、一般計略の成功率、既存の士兵戦・単騎討ち・即時転属・99人の都市定員をまとめて置き換えない。

この文書は火箭・籠絡の接続範囲を記録する。後続の単項実装で接続した虚兵の移動封鎖は、[独立した原式・保存・AIの説明](phantom-troops.md)に分けている。一般成功門の未確定部分は引き続き本作モデルを保つ。

## 火箭

共通の空間・習得・機動力判定を通った後、機動力8を支払い、まず成功判定を行う。成功した場合だけ0〜4の値をもう1回抽選する。敵方の現在の随軍兵糧を`G`、施放武将の知を`I`、抽選値を`r`とする。

```
要求損失 = floor(G × (10 + r) / 100) + floor(I / 5)
実損失 = min(G, 要求損失)
残兵糧 = G - 実損失
```

二つの項を別々に切り捨ててから足す。例えば兵糧11・知9・抽選値4なら、`floor(11×14/100)+floor(9/5)=1+1=2`。要求損失が在庫を超えても0未満にしない。兵糧0でも成功判定を通れば百分率の抽選を行うが、実損失は0。空の損失明細は保存しない。

対象は従来どおり敵方の主将で、範囲は5マス以内。成功しても兵数・体力・経験を変えない。都市倉庫と自陣営の随軍兵糧も変えない。焼失後の食事・不足撤退は、既存の日次補給処理が実残量と食事済みの端数信用から判定する。

### 今回は保持する本作の成功率

原版の共通成功門`B7BE`には距離、知の正の差、等級の正の差と、`050F/6F02`による分岐がある。後二者の意味と本作の天候等への対応を、この調査では確定していない。そのため火箭を含む一般成功率は次の既存モデルを保つ。

```
成功率 = clamp(60 + floor((施放者の知 - 相手の知) / 2), 10, 95)
```

これは原版の共通成功率を完全再現した式とは表記しない。

## 籠絡

忠71以上は、合法な対象を選んで確認した後の**効果の必失敗**。対象選択の禁止条件ではない。原版の確認経路は先に機動力10を引き、その後に`B72B`を呼ぶので、本作も10を支払い、失敗を表示して操作を完了する。この必失敗では成功率の乱数を消費しない。

忠70以下では、施放者の知`I`・德`V`・等級コード`L`、相手の忠`C`・等級コード`T`から求める。

| 相手の忠 | 基礎値 |
| --- | ---: |
| 0〜30 | 60 |
| 31〜50 | 30 |
| 51〜70 | 10 |
| 71以上 | 必失敗・抽選なし |

```
成功率 = 基礎値 + floor((I + V) / 10) + 2 × max(L - T, 0)
成功 = 0〜99の抽選値 < 成功率
```

旧版の最小5%・最大80%は使わない。知・德0〜99、等級0〜7の範囲では最大93%。等級コードは既存の`experience_tier()`と一致する0〜7を使い、画面の経験表示「経」と取り違えない。君主の内部忠100も必失敗側として扱うが、既存の「君主を籠絡できない」資格は引き続き先に確認する。

成功した後は従来の`battle_allegiance.convert`を共有する。人物・兵数・位置を保ったまま戦場の陣営と実際の帰城先を変え、受入君主の德による忠再設定と、確認済みの親族・信頼関係の下限を適用する。受入側の都市が全て99人なら、従来どおり対象選択時に拒否し、支払い・抽選しない。

プレイヤーには必失敗の0%を表示する一方、確認自体は可能とする。AIは同じ成功率を純粋計算し、0%の籠絡を候補から外す。候補探索や効果プレビューが未来の乱数を先取りしない。

## 火箭のAI評価は本作の適配

都市倉庫向けだった旧評価`平均焼失糧 / 12`を、小さい携行兵糧にそのまま使わない。30日分の通常の備糧では評価が常に機動力費用の減点を下回り、AIが有効な火箭を使わなくなるためである。以下は**本作のAI方針**であり、原版AIを復元した式とは表記しない。

0〜4の各抽選結果について実際の飽和損失を計算し、`(残兵糧×1000 + 食事済みの端数信用) / 一日の必要口糧単位`で維持可能日数を求める。焼失前後の日数は残り戦期`31−戦闘日`で頭打ちにし、戦期中には使い切らない過剰備蓄を焼いても架空の戦闘利益を与えない。減らした日数の割合を敵軍の兵力・部隊行動価値に換算する。

焼失前は翌日の食事を賄え、焼失後に賄えなくなる抽選結果だけ、敵軍全体を撤退させる追加価値を与える。敵方がすでに行動を終えていれば全額、まだ行動できるなら補給や戦闘終了の余地を見込み35%に割り引く。両軍とも不足する場合は既定の「攻方が退却」を適用し、攻方に偽の勝利価値を付けない。元から不足していた軍や空の袋を繰り返し焼く追加価値はない。

5結果を平均してから、既存の成功率と機動力費用の減点をそのまま適用する。効果の判定・実損失・実行時の乱数消費は変えず、AIの比較だけを改善する。実際に1000兵が3糧・端数信用900を持って到着した境界では、AIが火箭を選び、成功後に不足200単位で攻方を退却させる公開コマンド経路を回帰テストする。

敵方がすでに行動を終え、実残糧と端数信用で次の食事を賄えず、両軍不足の優先規則を含めても自軍が確実に勝つ場合は、AIは待機してその日を終了する。余った機動力で不要な兵士戦を開き、確定している兵糧勝ちを失うことを避ける。これは現在の戦術地図における本方の行動中だけの純粋な判断で、単挑中・兵士戦中・結果確定後・相手の手番・旧非グリッド戦闘には適用しない。10機動力の初期状態と20機動力を保有した状態を両方検証し、追加の乱数抽選や効果の事前実行は行わない。

## 乱数と保存の適配

原版は固定置換表の1バイトを使う棄却抽選。0〜99の成功判定では100以上を捨て、0〜4の百分率抽選ではバイトの下位4ビットを取り5以上を捨てるので、受理される抽選が1回でも基礎バイトの消費は複数回になり得る。

本作は既存のシード付き`SeedRng`を保ち、`next()%100`／`next()%5`を使う。原版と同じ乱数表、棄却回数、NMI時刻への依存まで再現したとは主張しない。

| 操作結果 | 本作の乱数消費 |
| --- | ---: |
| 火箭失敗 | 成功判定1回 |
| 火箭成功（敵の残量0も含む） | 成功判定1回＋百分率1回 |
| 忠70以下の籠絡 | 成功判定1回 |
| 忠71以上の籠絡 | 0回 |

視聴・プレビュー・言語切替・保存・読込は0回。原版計算を新たに接続した二つの計略について、旧版と同じ戦果や乱数消費数になる保証はしない。同じ更新後ルール・同じ状態・同じシードなら、プレイヤー、AI、保存復元後で同じ結果になる。

随軍兵糧の保存スキーマは`tk2-battle-supply-v1`のまま。既存の`journal`に正の実焼失だけを`{kind:'fire', day, grain}`として記録する。`burned`という重複保存カウンターは増やさず、閲覧時に明細の合計から求める。

```
loaded + received = consumed + remaining + burned
```

日付順に食事・市場受入・焼失を再生し、超過損失、負値、不正な日付、残高不一致を拒否する。既に食べた糧から生じた`credit_units`を火箭で減らさない。戦後は実際に残った兵糧だけを既存の帰城・鹵獲・溢失処理へ渡し、焼失分を払い戻さない。古い焼失明細のない保存データは従来の表現を保ち、随軍糧節がない古い戦闘も、閲覧だけで再搭載や初期化を行わない。

## 次段階に残す項目

原版の両軍別伏兵スロット、100兵の設置費、5日カウンターは確認したが、この段階では未接続。虚兵・連環の移動封鎖と奇門の条件付き周期損失は[状態処理の調査記録](original-tactic-status-audit.md)に分け、残る陣営・経験処理の不確定点と次段階の回帰範囲を示した。状態バイトの書込先や名称だけから奇門遁甲等を再定義しない。原版の捕虜配列と戦後の配置／解放経路も、取得条件・君主・部下の処遇を含めて別途確認する。現在の自動帰城・在野化を、原版の捕虜処置選択が完成したものとは表記しない。

## 繁體中文摘要

火箭改燒敵方隨軍兵糧，公式為`floor(隨軍糧×(10+r)/100)+floor(知/5)`，成功後才抽`r=0..4`並依實存量飽和扣減，不燒城內庫存、不傷兵、不扣體力。一般成功率仍採本作現有模型。籠絡對忠71以上是支付10機動力後必敗，成功判定不抽亂數；忠70以下改用已確認的忠、知德和等級差公式。AI與玩家共用，AI不嘗試0%籠絡。燒糧獨立於食用量記在可重放帳本，預覽及舊存檔純讀不扣糧、不抽亂數。
