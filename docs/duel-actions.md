# 單挑招式與捨命一擊

Web單挑提供突擊、防守、佯攻、捨命一擊和退出。每合由伺服器同時結算雙方實際招式；圖片、兵器與坐騎選項只負責呈現，不參與命中、傷害或亂數。

## 捨命一擊

原ROM bank23的`$B8D3..$B9A4`（第6類`すてみのこうげき`）在命中品質值小於30時令傷害加倍；否則不傷對手，自損10～30點體力。失手自損以低5位取樣，拒絕21～31後加10，並非直接把數值對21取餘數。依據為封存的原ROM反組譯與`source/recovered/battle.py`之`duel_strike_sample`、`duel_strike_effect`恢復紀錄；本次沒有聲稱重新完成原模擬器逐幀驗證。

本作保留這個風險結構，接入現有Web單挑：

- 本方和AI都使用同一個結算函式。品質判定`next()%100 < 30`；先取得本作原有的基礎傷害，成功時乘2，再套用本作既有的防守減傷。
- 失敗時該次攻擊造成0點對手傷害，自損10～30點；對手在同一合的攻擊仍會按本作現有的同時結算規則發生。
- AI在自身體力不高於30時，可將原本選中的突擊改為捨命一擊；沿用該次招式選擇亂數，不為策略判斷額外抽取亂數。其他選項仍為防守、佯攻。
- 本作體力以1為負傷敗退界線，該部隊兵數歸0，沒有新增直接死亡規則。二十合未決或退出時照原有流程回到戰場。
- 沒有任何一方使用新招式的既有四種操作，其狀態、亂數和回執保持不變；新增風險招式才會增加實際判定所需的抽樣。

本作繼續使用現有的武力差、傷害幅度、裝備模型、32位戰役亂數及體力邊界，沒有把NES武器／防具表、8位溢位或原抽樣器整套移植。因此這是原版風險招式在Web規則中的接入，不宣稱所有數值都與ROM逐位相同。音效優先重用已提取的原版單挑交鋒音，沒有另造一段音效冒充原版捨命招式錄音。

## 回執與驗證

動作名稱為`desperate`，使用原有`tk2-battle-presentation-v1`暫態回執；本方失手時`success=false`，實際體力損耗保留在前後快照。沒有為外觀或新招式增加存檔欄位。

`tests/test_remake_duel_desperate.py`覆蓋29／30的成功邊界、10／30的自損邊界、拒絕取樣、雙倍後防守減傷、AI體力30／31的選擇邊界、同合雙方敗退、二十合結束、重複／錯誤命令的原子拒絕，以及錄影資料啟閉／存讀檔的狀態與亂數一致性。

`tests/fixtures/duel-pre-desperate-baseline.json`從提交`eea539c579af3f72c130c160a00fe9ccaa28e6e0`的凍結程式擷取32組既有招式回歸向量。兩方初始體力80，AI不會選擇新招式；驗證完整戰役狀態雜湊、亂數及完整演出回執，而不只檢查畫面文字。
