# 运输统筹与回合结算

| 原入口 | V3.0.4.1 启用时 |
| --- | --- |
| `strategic_ai.run` | 任命与政策准备之后、首次势力行动之前，执行 P0–P2。回合游标和阶段完成标记共同支持中断。 |
| `domestic.prioritize_grain` | 保留盟友援助、储备刷新及内政恢复。 |
| `StrategicAI.support_frontline`、`support_endgame`、`prepare_checkpoint` | 提交实际战略库存目标，目标与同旬回合进度一起保存。 |
| `domestic.finish_faction_turn` | 军事行动后重检 P0–P4。内政行动后处理剩余请求、季节储粮和常规粮运。之后按原命令处理非粮调拨和自动商业贸易。 |
| `logistics.dispatch`、市场、粮仓、既有中转 | 核验并提交实际资源操作。普通运队卸货、前线会合和返程结算各自使用原有时钟。 |

城市的普通调粮、地区采购、本地买粮与战略粮仓共享九旬缺口。粮食在同旬到货前扣除该旬开支。当前缺口、后续缺口、可靠到货和条件到货从同一时间线计算。行军部队和运队会合使用真实队伍 ID。季节和农业备粮以同一官仓的增量目标比较。既有中转批次保留真实货权，转入中转仓记录为途中交割。

优先级依次考虑紧急人员损失、近期伙食、三旬内需求、作战准备、较远城市缺口、季节储备和常规优化。每阶段按紧急程度和原始期限最多比较 12 个目标，每目标保留至多 5 个完整候选。效率排序比较实效净到货、命令书和完整占用周期，并对争用同一来源的紧急需求搜索替代来源。实际发运重新计算受影响的存量、人员和到货。阶段内复用路线和相同人员的天气报价。

复合采购调用真实市场规则。购粮成交而运输失败时，保留购入粮及已支付的市场命令，另记运输失败。城池到货通过运队编号与请求对照。归队、货物易地接收和已取消的需求保留自己的结算凭证。观察器从成交、实际发运和到货事件读取结果。
