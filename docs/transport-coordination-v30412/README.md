# 运输调度 V3.0.4.1.2

V3.0.4.1.2 是默认关闭的运输调度实验。新战役可以选择 3041、30411 或 30412。D2 是单独的实验配置，每城最多两支活动运队，每旬至多实际发运一次。原来的无调度及旧版存档仍由对应版本执行。

候选把能赶上近期实际扣粮的城市运输优先放在紧急阶段。较晚的运队进入后续报价，保留普通储粮、已批准出征、实际防御准备等各自的用途和有效期。行军补给、返程运队救援和本地合法采购仍可按各自的需求执行。

AI 军队在友城途中补粮时，先履行同一行军、同一路线节点的有效承诺。其余补粮取自扣除其他承诺及最近一期城市口粮后的可用余额。对于暂时无法启程但还有随身粮的 AI 军队，真实可供养的等待日期也用于计算运队会合。遇到已启用的季节预报时，使用现成的保守备粮估计。玩家行军继续使用原有手动及自动补粮入口。

每个势力、每个调度阶段复用物理线路查询与逐日货粮损耗权重。每次资源写入后重新检查库存、运位、可用押运人员、命令书和目标缺口。缓存的损耗权重由方向、分段、天数和起算位置确定，数量及上笔小数余量仍逐笔结算。

固定回放、资源审计和归档数据由 `tools/economy-balance/v30412_replays.py` 与 `v30412_acceptance.py` 生成。24 个月、五年、二十年与保留种子使用 `v30412_campaigns.py`，每个阶段读取上一阶段的实际准入记录。
