# 目前的 AI 與事件畫面

目前電腦勢力使用本作獨立編寫的 Python 規則式 AI，沒有呼叫大型語言模型，也沒有執行 NES ROM 的 AI 程式。判定使用戰役的種子亂數；相同初始資料、種子及操作順序可重現結果。

## 電腦勢力如何行動

每旬為一個10日回合，玩家結束本旬後，按「執行電腦行動」處理 AI。系統依勢力 ID、城市 ID 排序，逐一處理非玩家、非中立且尚未行動的城池；遭遇需要玩家防守的戰鬥時，會停下等待操作。

| 順序 | 目前規則 |
| --- | --- |
| 招募在野武將 | 城內有武將、名冊未滿99人、有可訪問的在野者且金錢足夠時，選德最高者尋訪第一名候選人。使用與玩家相同的成功率及忠誠規則；成功或失敗都花60金，該城本輪到此結束。 |
| 徵兵與補兵 | 未先招募時，若預備兵少於200且有20金、30糧，徵募100人。再按帶兵量由少到多補兵，每將每次最多補80、補至600上限，每次花4金、8糧，並受預備兵存量限制。 |
| 出征 | 選健康、有兵且未行動的武將，按兵力取最多10人。相鄰非己方城市（含空城）按全城帶兵量由少到多排序；本軍須達到 `max(150, ⌊目標全城帶兵量 × 1.3⌋)`，並有足夠糧食。所有電腦勢力合計每旬最多發起3次出征。 |
| 勸降敵將 | 未出征且城內有空位、有100金及可勸降的鄰城敵將時，由德最高的可用武將勸說忠誠最低的候選人。所有電腦勢力合計每旬最多嘗試1次。 |
| 調將 | 未出征且未勸降，並有至少兩名未行動武將時，向名冊較少、仍有空位的相鄰己城調動1人，優先調動兵力最低者。 |

每城可容納99人，但出戰仍最多10人。AI 的出征比較目前使用目標**全城名冊**的帶兵總量，而非實際出戰10人的兵力，因此面對武將很多的城市會偏保守。

戰場上的正常反擊由敵方存活部隊中兵力最多者執行。其智力至少80、氣力至少6時，有25%機會消耗6氣力以「要撃」反制；否則普通反擊。伏兵、擾亂與減傷狀態仍會影響結算。AI 對 AI 的戰鬥使用普通傷害自動交換，最多200次，未分勝負則攻方退卻，沒有完整的16計略決策。單挑對手在突擊、防守、佯攻三種招式中按種子隨機選擇，傷害仍依武力及招式計算。

目前沒有長期戰略規劃、外交同盟決策、季風與減員風險的戰略評分，也不會主動探索未知海路。既有路徑搜尋與行軍時間計算仍然生效。

## 事件會如何顯示

| 事件或操作 | 目前畫面 |
| --- | --- |
| 招募、轉屬、武將登場 | 招募／勸降有玩家手動開啟的操作對話框；結果及到期登場主要寫入文字紀錄，沒有自動肖像事件彈窗。 |
| 死亡、年度更新、君主繼承、勢力滅亡 | 主要以戰報文字及狀態更新呈現。 |
| 城池依年代開放、天候減員、海路發現 | 寫入紀錄並更新城市、兵力或地圖航路，沒有事件插畫彈窗。 |
| 出征、退卻、讀檔等確認 | 玩家操作時開啟確認對話框；這些是操作確認，不是自動歷史事件演出。 |
| 普通戰鬥及單挑 | 使用專用戰場／單挑畫面與靜態像素肖像，顯示兵力、體力及文字交鋒紀錄。 |
| 戰果、勝利或敗北 | 在右側面板顯示結果與後續按鈕。 |

底部戰報目前顯示最近5條紀錄，戰鬥面板顯示最近8條戰鬥紀錄。系統雖保留 AI 行動紀錄，前端沒有逐條事件播放介面。現有圖片主要是地圖與武將肖像；**尚未實作事件插畫佇列、自動事件彈窗或過場演出**。

畫面依據：[遊戲前端](../game/app.js)、[肖像載入與顯示](../game/portraits.js)。
