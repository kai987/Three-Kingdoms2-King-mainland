# 交通設施節點 V3.0.4.2

本輪開發基準為 `d8b507ec813cc50f890c74bafbdc9a1586738621`。獨立工作樹保留主工作區的肖像稿。遠端引擎、工具、歸檔與實驗輸入的完整身份見[凍結清單](protocol.json)。穩定調度與 D2＋30412 是兩個獨立對照，每對只切換設施開關。30412 的固定專項通過，24 個月共 16 個正式及 5 個補充戰役，兩個背景均未經濟凍結，五年、二十年及 2047／2048 從未執行。

舊 V3.0.4 地圖審查的 64 個河流幾何點、57 處河運與 20 處海運接岸、0 個可收貨非城市節點見[舊審查](../transshipment-network-v304/physical-transfer-terminal.md)。珠江及蒼梧對照是舊城市中轉經濟結果，保存在[舊報告](../transshipment-network-v304/intermodal-route-planning.md)。

核查沿用[項目測試門檻](../testing.md)以及原 30412 的檢查點、軍事保護和逐局警戒。歷史輸入因版本或保管原因無法加載時單獨記錄阻塞。新建樣本保留獨立身份。

工作流 `remake.yml` 會在 main、PR 或驗證專用手動選項運行。開發分支推送後可在該分支執行驗證專用工作流。`pages.yml` 的自動發佈限 main 的通過推送，開發及歸檔分支與其分離。

## UI 與規則入口

在劇本選擇頁的實驗規則中啟用「河港接駁」，開局後在地圖點選菱形河埠。兩端城池及河埠必須由同勢力控制。面板顯示歸屬、實存、保留倉容、裝卸位及押運人員，並可輸入一或兩筆來源糧、查詢基於當前狀態的報價。陸路與河路分色，裝卸與排隊時間另外列出。確認後由 `infrastructure_order` 提交，與自動觀戰共用發運、裝卸、交割和返程結算。

正式規則與舊檔的設施預設關閉。啟用時使用獨立版本 `3042`。普通及緊湊存檔保留獨立的設施庫存、批次、有效計畫、日結算位置與最近收據。沒有啟用的存檔維持原資料規格。

河埠位置採用已繪製的接岸幾何，設施是實驗設計。原路段及方向保持原資料。新線將同一方向原有的陸地接近、登船／河段及離岸路程切開，工作量與登船階段都留在原方向。每日處理依既有天氣結算後的實況擇速；負責推進的是行軍口糧日迴圈，持久日游標防止重複結算。每旬正常推進十日。相關入口可於發運當旬看到已提交的運位、預留與人員變化。

每點一個裝卸位，現行糧食尺度下倉容 16,000、每個裝卸日最多 4,000 糧。同一鏈至多一名真實押運武將、兩個來源批次、兩處設施及三個分段。設施鏈與舊城市中轉共用每勢力兩條、全局十二條的活動計畫上限。同一來源及同一旬的實際發運與現有運隊共用一次機會，D2 只增加可同時在途的位置。各段使用一本命令書；返程使用剩餘口糧。無建造、維護或金錢收費，無預置人員、運力及糧食。

押運者的行政名冊保留歸隊歸屬，任務期間在城內命令及其他行軍中排除。完成裝卸後可在日帳看到實體存量與父子批次；目的城實收才算交付。已扣命令書、已吃口糧、已走的路程及已繳獲的貨糧均保留。船段封凍、道路中斷、無合法接收權或倉容不足時先等待，按實際位置與路權退出。原型可沿原線返程，缺乏合法過境或收容時保留原因；遇到敵方控制及完全失去糧道的通用救援留給 V3.0.5。

報價讀取當前城主、倉容、在途人員、運位、天氣、貨糧及命令書。路段分拆結果只在當旬日結算共同使用，貨糧與權限逐日讀取，有關報價與人事的中間結果只在單次查詢／決策共用。觀戰策略在既有軍事、調糧與市場動作之後，只有來源安全且可在原期限前提供額外有效糧時才選接駁。直運繼續參與比較。

本輪完成河陸開閉環專項。海陸設施、港口建設／升級、全面多級中轉、跨勢力共享與路權救援都在本輪範圍之外。

## 讀法與復放

`controlled-lines.csv` 的到貨日採劇本開始後的日偏移，原期限以 `actual_day < original_deadline` 判定。武將日由實際發運至返抵，`officer_reuse_days` 另計入原運輸規則的接收冷卻。運位日由發運至運隊完成。相同糧食在兩個河埠分別卸入，累計作業量可以大於最終交付量。失敗報價的實績留空。無來源或無合格武將的樣本保留真實原因。

```sh
MARCH_CORE_BACKEND=rust python3 -B tools/economy-balance/v3042_mechanism.py all build/v3042/mechanism
MARCH_CORE_BACKEND=rust python3 -B tools/economy-balance/v3042_experiments.py fixed build/v3042/fixed \
  --inputs ORIGINAL_INPUT_ROOT --reference replay-inputs.json --baseline INDEPENDENT_MAIN/results.json
MARCH_CORE_BACKEND=rust python3 -B tools/economy-balance/v3042_checkpoint_probes.py \
  PRIOR_BUILD_ROOT PRIOR_ARCHIVE_CHECKS build/v3042/probes
python3 -B tools/economy-balance/v3042_verify.py build/v3042 --lines mechanism
```

固定復放的基準用原 main 的引擎工作樹執行，使用同一份原始檢查點及 30412 驗證工具，分別比較 K0 與 L2 的每旬完整狀態及 RNG。原用例及哈希見凍結清單與 30412 的 `checks/replay-inputs.json`。新樣本 R01／R02 由 227 年開局實例建立，與舊檢查點、自然觀戰及舊珠江／蒼梧中轉證據分別標註。
