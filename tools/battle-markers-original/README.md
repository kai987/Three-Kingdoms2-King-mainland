# 原版の戦術部隊旗

`game/assets/battle-markers-original/` には原寸アトラス、厳密な4倍アトラス、インデックス、出典の4ファイルだけを置きます。原ゲームのCHR page138と部隊旗選択手順を使い、ブラウザーのフォント、補間、AIによる描き直しは使いません。

- 原寸：176×192。16×16を11列（隊数0–10）、12行に配置。
- 4倍：704×768。各画素を縦横4個に複製。
- 行：平／山／水の味方3行、敵3行、続いて同順の指揮官6行。
- キー：`friendly:0:1`、`enemy:2:10`。指揮官は`:commander`を付ける。
- `source_rect` は4倍アトラス上の `[x, y, width, height]`。各部隊は64×64。

元の部隊図形は`23:A983–AAE3`が出力する4枚の8×8 CHRです。上半分の数値表は`23:AAE4`（ROM位置`0x2EAF4`）の66バイト。指揮官スロット0／10は左上を専用図形に差し替え、10隊には数字と指揮官記号を組み合わせた専用図形があります。132通りすべてを独立NMOS6502で原ROMの命令を実行して照合しました。命令列やROM自体は配信しません。

灰白の味方は原controller0、赤地の敵は原controller2以上の図形と同じパレットです。Webでは実際のプレイヤー所属で味方／敵を選びます。原人物の軍種コードは12バイトレコードの **byte11 bits2–3** です。byte8／9は兵数で、軍種ではありません。コード0が平、1が山、2が水。未命名の3は公開しません。Webの隊数は今回の指定に従い`ceil(現在兵数/100)`を渡します。この変換を原ROMの兵数キャッシュの丸め規則と混同しません。0の図形も原表から保持し、敗走表示はゲーム側で別に重ねます。

原コアの完全な256×240フレームは既存の`battle-original/witness-tactical.png`をそのまま参照します。山／10隊／指揮官の16×16領域（32,98）はアトラスと全256画素が一致します。原ゲームは走査線でCHRバンクを変更するため、フレーム末尾のPPUバンク値だけでは図形を再現できません。ここでは実際のコールバック画像との一致によりpage138を特定しています。捕捉は隔離された元のテスト状態であり、自然戦役や実機録画とは表記しません。原画像、原ROM、プレイヤーのエミュレーター保存状態は変更しません。

```sh
# 通常の確認はPython標準ライブラリーのみ。ROM、core、py65は不要。
python3 -B tools/battle-markers-original/check.py
python3 -B -m unittest discover -s tests -p 'test_remake_battle_markers.py' -v

# 任意の読み取り専用再抽出。CPU照合に限ってpy65が必要。
python3 tools/battle-markers-original/build.py /path/to/original.nes --verify-cpu
```

チェッカーは固定CHR／表／132 CPU入力出力、パレット、フレームの型と座標、原画像一致、4倍の全画素を検証します。ハッシュだけを付け替えた偽の図形、違う軍種オフセット、余分な状態ファイル、シンボリックリンクは受け付けません。
