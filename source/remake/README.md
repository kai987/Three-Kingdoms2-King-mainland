# Web 戰役規則層

獨立 Python 規則：29 個劇本、最多 115 城、每城 99 人、每方出戰 10 人及 1,052 名人物。只讀目前 `game/data/campaigns/`，不執行 ROM、原 CPU 或控制 IR，也不註冊歷史目錄。

| 模組 | 職責 |
| --- | --- |
| `campaign.py` | 戰役狀態、亂數、原子指令、兵員守恆、驗證與存檔 |
| `officers.py` | 屬性、出生／出仕／退場、名冊、忠誠、容量與出戰 |
| `campaign_expansion.py` | 招募、勸降、16 計略、單挑、戰後處理、AI 與簡化繼承 |
| `travel.py` | 當前路網、在途部隊、到達、探索航路及 AI 行軍 |
| `route_hazards.py`、`march_core.py` | 路線風險與 Python／Rust 行軍計算 |
| `session.py` | 當前劇本切換、存讀、預覽、勢力資源與人數 |
| `map_presentation.py` | 年代城名、原版城標與可辨識的勢力配色 |
| `garrison_postings.py` | 同勢力駐防分配工具 |
| `city_development.py` | 土地、產業、人口與統治度、月度生產調整及統治不穩 |
| `battle_supply.py` | 真實隨軍備糧、戰場日耗、補給與缺糧結算 |
| `battle_grid.py`、`siege.py` | 逐格戰術、接敵與逐隊兵士戰 |
| `events.py` | 59類結構化事件、嚴格快照與保存驗證 |
| `cloud_config.py` | 雲端存檔公開設定與內容安全策略 |

總庫與當年登場分開；非連續 ID 有效，1005 保留空槽，執行期容量 1200。指令在副本執行並驗證，成功才提交；失敗保持資源、人物、兵員、亂數與版本。存檔校驗目前劇本 ID、資料 SHA 與狀態 checksum，不做舊版本遷移。

本次原版核對先接入三種開發：`develop_land`土地開墾、`develop_industry`產業發展、`develop_population`城町人口開發。設資金費用為G、執行者知為I，先計`q=max(1,floor(floor(G×I/100)×R/10))`，R為10–17；土地、產業增加q，人口增加`100×max(1,floor(q/2))`人。費用依知分檔抽取五個偶數：知≤50為10–18、51–80為14–22、81以上為18–26。字段截到土地／產業999、人口999900後，以實際增加單位計統治度+1；增加至少31單位時+2，統治度上限100。人口的1單位是100人。

以上金額表與整數順序來自本機固定《三國志2超級版》ROM及只讀恢復碼的BA70、A570、A690，並非原作者源碼。該ROM初始資源超正常開發上限，不複製其開局值。本作通常／大／巨大都市採土地與產業150／300／450、人口50000／100000／150000、統治度70，皆屬本作適配。收入以原版普通難度的人口、土地與產業及統治稅率形成全難度共用的相對開局生產係數，維持已定劇本月收入與10日一旬，沒有改成原版4月收金、10月收糧。低統治的候選門檻及三類損失沿用已核算法；每月掃描與6次月檢冷卻為適配。詳見[都市開發規則與來源](../../docs/city-development-rules.md)。

戰鬥開始使用實際扣除的隨軍兵糧，雙方行動完成後結算1日；精確日耗沿用本作行軍的`(現有兵數+100×有兵武將數)/1000`，保留分數餘額，並非已證原版配給式。米屋補糧直接進入隨軍糧；火箭仍按既有公式燃燒敵方戰略城市兵糧，與隨軍台帳分開結算。攻方斷糧撤退、守方斷糧失守。查看、預覽、事件播放不補糧、不推日、不抽亂數；缺少新台帳的現格式戰局只在首次實際寫入時初始化，扣除真實庫存。城市開發資料亦只在正式交易初始化，不在查看時改寫存檔。

逐格戰術移動、接敵後的野戰／城內逐隊兵士戰、單挑及59類繁中／日文圖文事件已實作，事件只播放已提交的結果。AI是確定性的規則決策，玩家與AI共用開發和戰場補給服務，詳見[AI與事件](../../docs/ai-and-events.md)及[戰鬥畫面](../../docs/battle-scenes.md)。完整外交與強制歷史勝敗劇情仍未實作；本次是原版對齊的首批改進，不表示後續階段或原版全部機制已完成。
