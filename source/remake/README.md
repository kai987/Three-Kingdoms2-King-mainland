# 独立重制版的人物与名册基础

`officers.py`是现代人物模型，`campaign.py`在其上接入单一战役状态、城市操作、出征、普通攻击、战后结算、电脑整备、回合与存档。它们不读取ROM、不调用原CPU或模拟器、不解释控制IR。旧`source/recovered/`保持原样，供规则证据参考。可运行的四城七人演练见[试玩说明](../../game/README.md)，这不等于完整游戏已恢复。

## 已实现的规则

- 每城最多20人；每方出战最多10人，第一位为主将，包含在10人内。
- 转属先检查整个名单与目的城容量，再一次写入；满城、重复或非法ID均不修改双方。选择出战名单是只读操作，取消没有资源副作用。
- 独立人物身份、16位运行ID、任职状态分开；255是有效新ID，空引用用`None`，不沿用原FF空槽。当前预留1200人的容量，可配置。
- 出生、出仕/登场、死亡分开判断。卒年当年列为待核；没有精确剧本覆盖时，在进入次年后移除。年度事件不会自动招募、补齐能力、重复创建人物或复活战死者。
- 武、知直接对应SAN14武力、智力，兼容上限99，来源100保留在`source_stats`。尚未采集的来源能力保持空；已核对原版人物的属性可作有明确来源的基线。
- 德评分由四项史料参考设计构成，独立于魅力。详见`expansion/officers/virtue-rubric.json`和首批5人的`virtue-designs.json`。评分是作者的游戏设计，不是史书给出的数值。
- 新登场人物：体力为明确人物基准满值，0兵，原作基础短剣/絹巾，经验0、等级档0。在野忠诚0，君主100哨兵，普通仕官忠诚须由剧本指定。招募和俘虏忠诚分别使用原CF3F和D00C算式。
- 新人物必需的体、武、知、德、适性缺失时拒绝运行初始化，并列出缺项；不拿统率、魅力或年龄当填充值。

死亡会清理城池名册，并产生带原城池和释放兵数的结算事件。`campaign.py`已将本演练的释放兵员归入原城预备兵，并通过兵员账本检查守恒。若人物此前已经死亡，跨过其寿命年份时只补一次年代核对回执，不修改人物或再次释放兵员；回执随战役年份一同提交和去重。君主继承和复杂势力灭亡仍未接入；不能将本演练的自然退休处理称为原作完整死亡流程。

## 使用

```sh
PYTHONDONTWRITEBYTECODE=1 python3 expansion/officers/build_remake.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_remake_officers.py' -v
```

构建脚本读取已经保存的候选资料和已转写的8条原版身份对照，不读取ROM。输出的1000份人物配置始终保留未知项和来源。基础属性齐全与“可玩剧本中已配置任职城/势力”是两个独立条件。
