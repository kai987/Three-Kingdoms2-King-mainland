# Web 戰役規則層

獨立 Python 規則：29 個劇本、最多 115 城、每城 99 人、每方出戰 10 人及 1,052 名人物。只讀目前 `game/data/campaigns/`，不執行 ROM、原 CPU 或控制 IR，也不註冊歷史目錄。

| 模組 | 職責 |
| --- | --- |
| `campaign.py` | 戰役狀態、亂數、原子指令、兵員守恆、驗證與存檔 |
| `officers.py` | 屬性、出生／出仕／退場、名冊、忠誠、容量與出戰 |
| `battle_conditions.py` | 獨立虛兵移動封鎖、日界與清除；不推定舊stunned來源 |
| `battle_deployment.py` | 新戰局依最後途經城選擇原版陣區、純規劃與部署來源驗證 |
| `battle_ai_deployment.py` | 原AI非主將武力比較、固定勢力family、四組候選與共用安全修正的純規劃 |
| `battle_auto_deployment.py` | 新到達戰局AI初始輸入回執、玩家逐將階段整合與純讀說明 |
| `battle_placement.py` | 新玩家戰局逐將布陣、未來將不占位、原子確認與可選準備存檔驗證 |
| `tactic_effects.py` | 已核對的火箭損糧、籠絡機率及純預覽；一般成功門保留本作模型 |
| `campaign_expansion.py` | 招募、勸降、16 計略、單挑、戰後處理、AI 與簡化繼承 |
| `travel.py` | 當前路網、在途部隊、到達、探索航路及 AI 行軍 |
| `route_hazards.py`、`march_core.py` | 路線風險與 Python／Rust 行軍計算 |
| `session.py` | 當前劇本切換、存讀、預覽、勢力資源與人數 |
| `map_presentation.py` | 年代城名、原版城標與可辨識的勢力配色 |
| `garrison_postings.py` | 同勢力駐防分配工具 |
| `city_development.py` | 土地、產業、人口與統治度、月度生產調整及統治不穩 |
| `battle_supply.py` | 真實隨軍備糧、戰場日耗、補給與缺糧結算 |
| `battle_grid.py`、`siege.py` | 逐格戰術、接敵與逐隊兵士戰 |
| `events.py` | 59類結構化事件、嚴格快照與保存驗證 |
| `cloud_config.py` | 雲端存檔公開設定與內容安全策略 |

總庫與當年登場分開；非連續 ID 有效，1005 保留空槽，執行期容量 1200。指令在副本執行並驗證，成功才提交；失敗保持資源、人物、兵員、亂數與版本。存檔校驗目前劇本 ID、資料 SHA 與狀態 checksum，不做舊版本遷移。

本次原版核對先接入三種開發：`develop_land`土地開墾、`develop_industry`產業發展、`develop_population`城町人口開發。設資金費用為G、執行者知為I，先計`q=max(1,floor(floor(G×I/100)×R/10))`，R為10–17；土地、產業增加q，人口增加`100×max(1,floor(q/2))`人。費用依知分檔抽取五個偶數：知≤50為10–18、51–80為14–22、81以上為18–26。字段截到土地／產業999、人口999900後，以實際增加單位計統治度+1；增加至少31單位時+2，統治度上限100。人口的1單位是100人。

以上金額表與整數順序來自本機固定《三國志2超級版》ROM及只讀恢復碼的BA70、A570、A690，並非原作者源碼。該ROM初始資源超正常開發上限，不複製其開局值。本作通常／大／巨大都市採土地與產業150／300／450、人口50000／100000／150000、統治度70，皆屬本作適配。收入以原版普通難度的人口、土地與產業及統治稅率形成全難度共用的相對開局生產係數，維持已定劇本月收入與10日一旬，沒有改成原版4月收金、10月收糧。低統治的候選門檻及三類損失沿用已核算法；每月掃描與6次月檢冷卻為適配。詳見[都市開發規則與來源](../../docs/city-development-rules.md)。

戰鬥開始使用實際扣除的隨軍兵糧，雙方行動完成後結算1日；精確日耗沿用本作行軍的`(現有兵數+100×有兵武將數)/1000`，保留分數餘額，並非已證原版配給式。米屋補糧直接進入隨軍糧；火箭按已接入的原式燃燒敵方隨軍兵糧，留下獨立fire收據，不減城內庫存。攻方斷糧撤退、守方斷糧失守。查看、預覽、事件播放不補糧、不推日、不抽亂數；缺少新台帳的現格式戰局只在首次實際寫入時初始化，扣除真實庫存。城市開發資料亦只在正式交易初始化，不在查看時改寫存檔。

逐格戰術移動、接敵後的野戰／城內逐隊兵士戰、單挑及59類繁中／日文圖文事件已實作，事件只播放已提交的結果。AI是確定性的規則決策，玩家與AI共用開發和戰場補給服務，詳見[AI與事件](../../docs/ai-and-events.md)及[戰鬥畫面](../../docs/battle-scenes.md)。完整外交與強制歷史勝敗劇情仍未實作；本次是原版對齊的首批改進，不表示後續階段或原版全部機制已完成。

連環ID10は水格ごとの移動封鎖として接続し、[適応と保存境界](../../docs/chain-troops.md)を分離して記録する。

奇門15は敵の高状態へ接続し、[日界・経験・固定順序の契約](../../docs/qimen-troops.md)を使用する。旧guardは推測変換しない。

## 戦前の逐将配置／戰前逐將布陣

実際の到着で始まる新しいプレイヤー参加戦は、AIを先に配置し、人間側を名簿順に1人ずつ配置する。現在将と確認済みだけが`tactical.positions`を持ち、未来将は占有しない。`battle_place`の確定時に次将の手動既定点を表の先頭から再選択する。原矩形と表示範囲を守り、packed行15は飛ばすが、山水や主将の城砦移動は禁じない。配置で日数・AP・命令書・追加兵糧・乱数を消費せず、守備側の最終確認後だけ既存の攻撃側AI先手を開始する。

`extended.placement`は任意の準備記録で、既存戦局に後付けしない。未確定プレビューはWeb側だけ、各将の確定を正式座標と本機復元点の境界にする。これは原作の矢印ごとの即時RAM更新・未確認の原作セーブとは分けた本作適応である。読込は部分配置と残数を保ち、再配置やAI再実行をしない。準備記録があるのに戦術座標・配置出典がない新保存は拒否する。公開命令の準備中gateは戦術・退却・日界等を止めるが、別経路の保存・読込と主メニューを妨げない。[原指令、27例のCPU観測と保存の適応](../../docs/manual-deployment.md)を参照。先行段階のローカル回帰結果と、後続のAI初期配置の追加検証は分けて扱う。

繁中：本方逐將確認、未來不占位，AI先固定安全候選；A進下一將，編輯分支未見B／Select／Start取消。Web逐將確認存檔是明示適配，非原版即時RAM光標或原作存讀復刻。115城來向模板與安全過濾保留，既有虛兵／連環／奇門不因布陣改動。

## 原作AIの初期配置／原AI起戰配置

新到着戦局では主将を保ち、非主将を原作の隣接武力比較で並べる。同値も交換するため安定ソートではない。固定勢力slot・攻守・非主将人数から原108byte表の四人数を選び、機械ID1〜4の独立游標で原座標を読む。魏／蜀はfamily2、袁紹／劉璋は1、呉／董卓／馬騰は0。原継承は同じ勢力レコードの君主byte0だけを変えるため、現任君主でprofileを再選択しない。孫堅・劉焉の系譜別名と追加勢力family0は明示適応とする。

原AIは矩形・占有を検査しないが、本作はプレイヤーと共通の可視原矩形・重複禁止・山水許可を使う。異常な元候補を出典から消さず、安全修正を分ける。任意の`extended.auto_deployment`は新規到着時だけ作り、既存戦局・旧pendingへ後付けしない。座標、AP、日数、RNGや既存計略を読み込み時に再発行しない。[925例のCPU観測と実装・検証境界](../../docs/ai-deployment.md)を参照。戦闘中の原戦術AI全体の復刻は宣言しない。今回追加分のローカル受入結果は同文書に記録し、公開とは分ける。

繁中：AI主將固定，非主將同武照原相鄰交換，再按勢力slot與四組游標取點；策略ID不猜戰術名。原AI沒做的矩形／占位安全條件由本作與玩家共用，13次矩形外／9次重複是768個10將CPU向量中的發生次數，不是去重原表數；新回執不補到舊戰局。
