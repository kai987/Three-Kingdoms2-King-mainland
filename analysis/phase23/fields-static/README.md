## 新方法及17项收窄

以前的模型跟踪寄存器字节集合和完整指针对，但普通`LDY $24`等加载会丢失内存计数器的界。本轮增加must标量单元及`当前寄存器 == 当前物理零页单元`的关系：

- 合并只保留所有前驱都存在的单元；值取并集，寄存器等式也必须在所有前驱成立。
- 只有**完整有效地址集合的每项都归一到同一个物理零页地址**，才可创建must单元。单例may-write零页投影不够，例如`STA $00FF,X`可能写`$00FF`或`$0101`；间址集合也可能混合零页和IO。两种情况只失效旧事实，不能建立“肯定写入”。多个RAM镜像确实指向同一物理单元时则允许。
- 所有可能的部分写、直接/索引/间址写、RAM镜像、16位索引回绕及callee写效果，都清除相关单元和所有旧代寄存器引用。未知调用清除全部相关事实；不以同一个调用PC恢复关系。
- `LDY $24 / CPY #27 / BCC`只在寄存器仍等于当前单元时把分支约束回传到该单元。紧邻加载/传送的N/Z分支另要求唯一实际前驱、原操作确实产生对应标志；零位移的共同后继不作真假筛选。
- 标量集合超过32项时退回未知；完整指针对的lo/hi关系仍沿用冻结模型，未拼接独立跨代字节。

新增排除全部位于银行11：

## 不能省略的调用前提与反例

新事实针对可信有界控制流内、无插入IRQ/NMI或外部改写的普通执行；不是函数任意中间入口或中断原子性定理。裸`$CDB9/$CE1B`并不会验证`$36`的字段选择器。新验证器保留10案原CPU反例：直接给这些helper输入`$36=1/28/29/30/31`时，原代码确实可读写目标辅助字节。因此不能把“完整父调用选择的字段不交”写成“helper从来不碰辅助字节”。原来的无界首FF扫描、原始selector和裸后缀反例也没有被删除。

本次实际精化跑了**两轮**，第二轮没有新增写效果事实；程序最多允许三轮。`complete_analysis_fixed_point_proven=false`，不宣称全程序完备固定点。
