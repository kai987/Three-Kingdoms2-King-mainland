## 阶段0／1与原调用栈

`BAC1` 先设置原CHR影子，再用507高4位索引势力记录。记录+3整字节等于3才进入AI；其他字节走原玩家分支并保存到6F44。正常玩家编码与任意原字节的机械分支分开，测试全256值不等于全256值都是合法玩家。

玩家分支把0500交给13／14、清0501，并设050B=17；`BB3D` 使用507低4位，玩家分支的050B=2。两个入口对战果零／非零采用原分支次序，不自动替玩家界面完成处置。

AI分支保留0504侧别字节与6F91模式：攻击侧0／2，防御侧1／0。真实JSR位置是 `BB36 → BC46 → BB39` 与 `BB8C → BC46 → BB8F`，正常返回后才INC0501。旧高层说明中的BB37／BB8D不是这些JSR地址，本轮在新文档更正，不修改冻结文件。

## 分配算法的机器边界

`BDCD` 检查active侧别字节0628是否FF，active军官ID本身的FF仍可写入临时表并使后续消费提前结束。20+20最大收集及末尾至少一次FF填充采用原字节计数。`BE55` 查找20槽，FF洞不会终止查找。

`BD96` 从实时指针、游标04及偏移03开始，原程序先写一次再比较Y是否到27。裸helper的异常偏移不能继承完整父调用的名单域。逃将匹配时052C更新先于名单写，PHA/PLA和实时别名保留。

`BE90..BF09` 对9D72+X取值，以负值终止，X按8位递增；eligible计数16也保留字节递增。它不是固定八项for。后续消费042C／0550的实际CPY#8上限单列。模式2的源城已满路径不会把04强制清零，可能保留EADE目标高字节BD；溢出释放后02被city×8覆盖，下一轮比较不能缓存原leader。
