# 第29轮：战后阶段3、城市归属及君主名单收尾

本轮恢复物理8/9的 `BBA0 → BBB8 → BC00` 精确调用协议，并以新统一工厂组合冻结阶段2和已有 `CC29/D4F0` 正文。城市 `+1`、`+28..31` 的正式含义仍未知，整体逆向没有完成。冻结账本仍为1526＝1198条件不交＋81可能＋247未知，剩余328；raw345仍为104操作数／13数据／228未证控制窗口。本轮没有新静态排除；未用测试数或候选数计算完成率。

## 实际游戏行为

`BBA0` 每次新回调读取 `$87`。非负立即在 `BBB7 RTS` 返回；负值才调用 `BBB8`。返回后写 `$7A=1/$0400=13/$0401=0`，**不会清除或递增 `$0500/$0501`**。`ECEE` 的同步初始化与后续NMI推进仍分开：它立即RTS且不写 `$8A`；当前两个母档中local2..20有19次门控返回，local21原 `EC95` 写87=FF后放行。这不是固定21帧规则，也不是悬挂的ECEE等待。

`BBB8` 先用原F25F/F2AF选择数据页与当前城。战果字节514为0时，城市归属字节保留高4位，低4位改为507高4位；其他战果不写归属。随后对当前城和邻接表中的各城调用 `BC00`。邻接表从bank16:9D72取值，起始Y为三次8位ASL后的city×8，只以精确FF停止，Y按8位回卷；未插入“最多8个邻居”的限制。

`BC00` 先保存实时城市指针至0A/0B，再允许F368把00/01改成势力指针。它使用归属低4位，只有7提前返回。正常势力编码为0..6；raw8..15越过合法七项指针表，机械寻址单列。raw8读5F20时必须有明确设备输入，缺失则停在真实PC/SP依赖，不能伪造数值或RTS。

君主ID暂存在02；在城市偏移17..26的全部10个名单槽查找第一个匹配值。先出现FF不会终止，找不到则不写。找到后按原顺序把君主ID置于17，把原17值写回匹配槽；即使原本已经在17，也保留两次真实同值写入。所有指针、暂存别名和栈操作按原时序处理。

正式原机两路线中，各有6次BC00调用，城市顺序为4、2、12、11、3、1；最后两个城市没有匹配君主，无名单写入。共观察77次城市逻辑读、12次邻接ROM读、12次君主读、15次城市写入：自然8次／受控6次名单同值写，受控另有6080归属1→2。STA的15次dummy读独立列出。这两条Native路线没有证明非平凡君主换位；受控CPU模型对照与实际Native观察分别记账。

## 可读源码与对照

本轮新精确协议有81个原指令位置、166字节，Source对照执行覆盖81/81位置；这是该有限正文的位置覆盖，不是全ROM覆盖。

新增 [PostbattleCompletionServices](../../source/recovered/postbattle_completion_services.py) 继承冻结28阶段2，实现新5入口A006/BAB3/BBA0/BBB8/BC00中的阶段3闭包；阶段0/1仍保持原分派依赖。缺少明确硬件读输入时保留同一generator、caller和PC/SP，供入声明设备值后才可继续。

新增 [统一工厂](../../source/recovered/postbattle_completion_integration.py) 仅将pair8/9的新5入口交给新owner；其余沿冻结父层。待处理调用持有真实call对象，重复依赖不重启，新正常RTS才移除owner，reset清理所有新缓存。已有 `promote_city_leader/finalize_city_ownership` 玩法算法与旧512 SRAM对照不重复记首次恢复。

已有 `CC29` 绘制正文、`D4F0` 全父路径和D4F5远调用桥均保留冻结源码。本轮新增的是实际输入的完整组合对照，不复制算法。EE07恢复E2代码pair后返回D4FA，但不保存或恢复E1；8000数据窗口的实际副作用保持。N163及设备端口是共同显式CPU夹具，不冒充瞬时Native设备快照。

统一工厂正式115例＝110个正常RTS＋1个继承非局部返回＋4个阶段0/1依赖前缀，另8个guard；其中80例继承回归、34份新现场输入（自然17／受控17）及1个新增受控ECEE回归分列。34份分别为A006/BAB3/BBA0各4、BBB8为2、BC00为12、CC29/D4F0各4；子服务使用其中26份，完整CC29/D4F0另8份用于Root组合。

子服务正式2853例＝2847个正常RTS＋6个严格前缀，另9个guard；原2825个受控矩阵案、2个新增阶段2同generator回归（A006/BB93）及26份现场输入分列。6前缀分别为阶段0/1两案、明确缺失5F20一案，以及故意不给F25F/F368服务的三案；预置5F20设备值的rawowner8与缺设备案已区分。正式分类以 [子服务回执](completion-services/validation.json) 及 [统一工厂回执](source-integration.json) 为准。新增ECEE回归实际运行本轮Completion owner：先缺服务，再连续两次假returned但PC/SP未返回，RAM/SRAM/寄存器/银行/IO和原call/owner/generator身份均保持；接回真实Shared后，ECEE仅执行一次，原父调用记录一次，整父链与原CPU一致。它是新受控CPU案，不是新的Native输入。

所有对照检查完整2048RAM（含空闲栈）、8192SRAM、AXYP/SP/PC、四PRG映射、交错逻辑IO和共同N163。正常RTS、继承非局部返回、严格依赖前缀、模型guard及失败分别记账；生产具名源码没有CPU或IR回退。子服务和统一工厂对同一输入的测试不能累加成更多Native现场输入。
