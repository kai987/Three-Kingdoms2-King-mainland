# 战斗、计略与单挑数值逻辑

本目录恢复了可读的战斗计算源码，并用 **原 ROM 的实际 6502 指令**差分验证。输入 ROM SHA-256 为 `26c8d921ff5c208191f136480bcd8d7e89c2e4ed40a0ac7b51482bcb52fe2b82`。这不是原始游戏源码，也不是完整战斗引擎。战场动画、整局流程、NMI/IRQ 时间和单挑最终 SRAM 回写尚未完整恢复。

可读实现：[battle.py](../../source/recovered/battle.py)。验证入口：[verify_battle.py](../../scripts/verify_battle.py)。已标记内联指针/数据区的 18 段汇编在 `routines/`，原始字节、文件偏移、SHA-256、调用点在 `routines.json`。REA 对 bank12/13、14/15 的辅助分析位于 `../rea/pairs/`；6502 的内联地址不能直接当作普通指令流，所以本报告以原始字节和执行差分为准。

## 入口与状态关联

固定 bank31 `$E1A7` 写入 selector `$2C` 并调用 `$F237`，把物理 bank12/13 映射到 `$A000/$C000`，随后调用 bank12 `$A006`，其 `JMP $C766` 进入战术初始化相关代码。bank12 `$A000` 跳 `$A009`；`$A028` 根据 `$0500` 调用 `$EADE` 状态分派。

战术效果执行点 bank12 `$AA9B` 调用 `$B02B`。后者按 `$0543 & $0F` 分派 **16 个有效表项**，内联地址表为 `$B042..$B061`；其后 `$B062` 立即开始第一个 handler。目标依次为：

```text
index  0 B062   1 B0DD   2 B155   3 B17A
       4 B1D5   5 B243   6 B062   7 B2CD
       8 B31C   9 B3B6  10 B3D0  11 B42A
      12 B466  13 B4B8  14 B50C  15 B5A6
```

`$050A` 为施动 slot，`$0509` 为目标 slot；`$0664[20]` 联接武将 ID。`$0600[20]` 与 `$0614[20]` 为两个坐标轴，`$0628[20]` 高位标记两方；`$0501` 是战术子状态，`$042C/$042D` 是伤兵计数累积器。计略的菜单中文/日文名称尚未全部与这 16 个 index 联接，不能仅凭熟悉的游戏规则给它们冠以“火计”“落石”等名称。

武将字段名称来自另一份 [字段/UI 证据](../officer_fields/fields.json)：byte0 体、1 武、2 知、3 忠、4 徳，+6/+7 経験，+8/+9 的低 10 位用于兵数显示与下述战术减兵 helper，byte10 低5位武器、高3位防具。+8/+9 在其他代码中也可能按完整 u16 读取，本模块没有把整个内部字段定义为永远只有 10 位。byte11 中2位显示“平/山/水”，地形适性是强推断，不称作兵种；本模块只按已证明的高4位等级和低2位状态处理。

## 距离与成功概率

bank12 `$B860` 的距离为 `max(abs(dx), abs(dy))`。两个 y 值分别在 `>=16` 时减1，映射跳过的第15行；异常 y=15 仍按15计算。该函数使用 **BCS 判断减法借位**，所以能得到完整无符号字节差的绝对值；它和别处使用 BPL 的有符号差不能混用。已验证 14,641 组代表性 byte 边界组合，包含 0、15、16、127、128、255。

bank12 `$B7BE` 是多个计略共用的成功 gate。距离 `>=6` 立即失败，不消耗随机数；否则：

```text
dK = max(施动知力 - 目标知力, 0)
dL = 2 * max(施动等级index - 目标等级index, 0)
distance byte = [15, 10, 5, 0, 251, 246][距离]
bonus = 10
若 $050F==3：$6F02==1 -> 10；==2 -> 20；其他 -> 5
p = u8(distance byte + dK + dL + bonus)
若 p 的 bit7 为1：p = 0
p = clamp(p, 5, 95)
反复取原 ROM RNG byte，直到 r<100
成功当且仅当 r<p
```

`251/246` 是原始表的 `$FB/$F6`。三个加法均以字节 wrap 执行；不能先用无限精度整数求和再普通 clamp。`$050F/$6F02` 的界面含义尚未确认，文档保留实际地址。

bank12 `$B72B` 是 `$B31C→$B32A` 阵营转换路径的 gate：成功后 `$B333..$B338` 执行 `$0628[target] ^= $80`，并调用 bank10 `$A006` 更新归属相关数据。距离 `>=6` 或目标忠值 `>=71` 直接失败，不取 RNG。忠 `<31/<51/<71` 的基数分别 60/30/10，加 `u8(施动知+徳)//10` 与正等级差×2；随后取 `r<100`，比较 `r<p`。此 gate **没有**共用 gate 的 5..95 截断。概率计算已恢复；后续完整归属列表和政治关系更新未复制进本模块。

## 六段实际效果数量公式

下表是各 handler 成功后的计算前段；共用概率 gate 另行验证。`L` 为 byte11 高4位，`W` 为武，`K` 为知，`R(n)` 完全遵循原 ROM rejection sampling `[0,n)`；小于15的 bound 先取随机 byte 低4位。所有除法均为无符号整数向下取整。

| 物理 bank12 入口 | 已恢复的实际数量 | 目标后处理 |
| --- | --- | --- |
| `$B070` | `u8(10*L + u8(K*(R(5)+9)//10)) + 30` | `$B68B` 减兵 |
| `$B0EB` | `u8(u8(L+u8(W+K)//10)*(R(3)+5)//10)` | `$B5D8` 减体 |
| `$B188` | `W*(R(7)+14)//10` | `$B68B` 减兵 |
| `$B1E3` | `K*(R(7)+20)//10 + L + 7` | `$B68B` 减兵 |
| `$B4C6` | `R(200)+150+(u8(W+K)>>1)` | `$B68B` 减兵 |
| `$B55C` | `K*(R(6)+30)//10` | `$B68B` 减兵 |

每段 512 个 actual-ROM case 均核对了数量和 RNG 游标。计略名称目前用 CPU 地址命名；这保证公式来源可查，而不猜测名字。

`$B68B` 对目标 `byte8 + ((byte9&3)<<8)` 做饱和减法；损失超过当前兵数时，实际损失就是剩余全部兵数。写回 byte9 时原先高6位会被清除，这是代码的实际行为。实际损失累加到 `$042C/$042D`，以 u16 wrap 保存。随后通过真正 `$EE07` 跨 bank14 `$A006→bank15 $D7FB` 给施动者加经验，最后 `$EE4D` 恢复原 bank12/13。**经验按新的累积计数/2，每次 helper 调用都重新授予，而不是只按本次损失/2。** 这一点对范围攻击等多次调用很重要。

已分别验证 189 个不同 ID 和 189 个同 ID/同 SRAM 地址情况，包括 byte9 高位异常数据。Python API 的默认 actor/target 为不同记录；同地址情况必须显式 `same_record=True`。同地址时减兵和加经验共同改写同一份记录。若使用另行提供的 C 辅助实现，其 distinct-record contract 不能默认为支持这一 alias 情况。

`$B5D8` 对体力进行饱和 byte 减法；变为0后把武将 byte11 OR `$03`，随后进入地图移除和跨银行结果处理。本次只恢复并验证 `$B5D8..$B610` 算术/标志前段；不能仅从 OR03 推断所有后续情形都永久死亡。

## 经验增长

bank15 `$D7FB`（文件 `0x01F80B`）把 `floor(累积伤兵/2)` 加到 u16 经验；**先 wrap 16 位，再截断为最大49,999**。等级 index `<7` 时，经验阈值依次为 `[1000,2000,3500,5000,7500,10000,15000]`；每次调用最多升一级。与阈值比较使用未经最大值截断的 wrapped sum。

升级时武力增量为：原武 `<51` 加6、`51..70` 加5、`71..80` 加4、`81..89` 加2、`>=90` 加0；保留 byte11 低4位。等级高于或等于7不继续升。5,000 个病例包含阈值前后、u16 overflow、等级15及所有武力增量边界。

## 单挑已恢复的数值链

单挑的武将 ID 位于 `$04AD[2]`，当前行动方为 `$04AA`。bank23 `$B160` 将两名武将 byte0 体力复制到 `$04B1[2]` 临时体力。后续一般打击更新该缓冲；本目录不声称已经完整恢复单挑结束时写回永久记录的全部规则。

bank15 `$C926` 对 `$0560/$0561` 两名武将分别调用 `$C991`，把返回 A/Y/X 存入 `$04C1/$0570/$056E` 对应的一方缓冲：

```text
武力 W <65 / <80 / <87 / <92 / <97 / 其他
系数 c = 45 / 50 / 55 / 60 / 65 / 70
attackBase = floor(W*c/100) + 9 - R(9)
weaponBonus = bank15[$CA1F + (byte10 & 31)]
armorModifier = bank15[$CA37 + (byte10 >> 5)]
```

实际武器名称与防具名称见字段/UI 图；不是“马”字段。正常武器 ID 为0..23，但代码低5位还能索引24..31，这时会读到相邻防具 modifier；API 对异常输入保留相同读取行为。武力分段及全部256种装备 byte 的 4,352 个病例通过。

bank23 `$BA15` 每击先取 `r100=R(100)`，再算：

```text
d = u8((u8(attackBase + weaponBonus)>>1) - 对方armorModifier)
d = u8(d + R(11) - 5)
若 d 的 bit7 为1，d=0
```

它输出命中质量 roll 与暂定伤害；不能省略后段直接把 d 当最终扣体。

bank23 `$B8D3` 的完整数值部分随后根据 `$04BF` 类别、`$04B5[actor]&7F` boost 和 `$04C5[actor]` 阈值处理：类别0把有效 d 除3；类别6按 roll 分支，有时双倍伤害，有时反向扣自身随机10..30体；其他类别按阈值拒绝。boost 的 ASL/ADC 中间结果按 u8 wrap，所以增幅不能直接替换为普通 `floor(1.3*d)`。成功伤害饱和扣对方临时体力，并选择消息 `$22`；无有效伤害选 `$39`；未成功/反向扣体路径选 `$25`。类别与 boost 对应的菜单名字尚未完全确认，源码保留结构参数。1,024 个完整数值 case 核对了两方临时体力、消息、报告损失和 RNG 游标。

另一个实际结果函数 bank23 `$BB5B` 直接从对方武将 SRAM 的 byte0 扣 `R(10)+5`，报告伤害仍为5..14。它使用 **BPL sign test**，不是普通无符号饱和减法：`u8(体力-伤害)` 的 bit7 为1时归零。体力全部0..255与六个游标共1,536例通过；异常体力128以上的行为也被原样保留。

`$B230` 还构造两名武将的内部单挑参数：`u8(u8(体+武)//10 +20 -(weaponCorrection+armorCorrection))`，再加各自的 `R(11)`，比较两个随机化值选 `$04AA`。它使用另一个 bank23 `$B2C0` 的24+8修正表。文档称其“参数构造”，不把它误称最终伤害公式。

## 验证与复现

当前 [validation.json](validation.json) 为 **35,699 个 CPU 差分病例全部通过**。oracle 直接执行原 ROM 指令及固定 bank 数学/RNG helper，使用 mapper19 CPU 银行模型；全路径减兵也执行了真实跨银行经验函数。没有补丁 ROM、替换依赖函数或伪造画面。部分算法明确限定为前段，遇到尚未恢复的依赖之前停止，避免借 stub 把未验证部分算作成功。

```sh
.venv-trace/bin/python scripts/analyze_battle.py '/Users/paulasmith/Downloads/三国志2超级版.nes'
.venv-trace/bin/python scripts/verify_battle.py '/Users/paulasmith/Downloads/三国志2超级版.nes'
```

`oracle_executed_locations.json` 是本组函数 harness 实际访问的物理 bank/CPU 地址/ROM 偏移，供进一步 CFG 校验。它们的覆盖属于人工输入的函数级试验，不能当作一次真实游戏 session 的完整动态轨迹。

后续尚需确认：16 个计略 index 的菜单联接、普通战场攻击完整调用链、地形/天气名称、单挑类别/boost 的 UI 语义、永久体力回写、完整死亡/俘虏/归属流程及动画/IRQ 时序。这些限制已写进源码和 JSON。
