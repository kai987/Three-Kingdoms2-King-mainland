# 阶段24：配兵界面的完整指针生命周期

本轮只选择一个有原机入口的未知生产者子链：城市配兵时，城市名册指针如何变成武将指针、被除法临时借用，再恢复后读写兵数。新增了具名可读源码，并用原CPU和原Nestopia普通输入分别核验。城市 `+1`、`+28..31` 仍没有足够证据确认正式含义；本轮不宣称全ROM语义恢复完成。

分项回执已通过。最终总审计、浏览器验收和增量包状态分别以 [verification.json](verification.json)、[browser-validation.json](browser-validation.json) 和 [package-receipt.json](package-receipt.json) 为准；这里不预先声明它们已经通过。

## 可读源码及精确调用协议

新增 [PointerLifecycleServices](../../source/recovered/pointer_lifecycle_services.py) 为物理27/28银行的配兵链提供具名函数，覆盖 `D64A、D773、D7A8、D94E、D96F、D987` 六个入口。原选择、输入、兵数编辑及数字packet正文379条指令位置、913字节；39字节选择/光标表另列。阶段5已有的配兵和库存归一算式继续复用，没有重复称为首次发现。

`D805` 先通过 `F2AF` 得到城市记录，从实际行游标读取名册ID，再经 `F2D7` 得到完整武将指针。`D987` 保存 `00/01` 到 `10/11`，暂时将 `01/02` 用作数值参数；`EA7C` 自身只写 `01/02/05/06/07`。恢复原指针后才进行武将 `+8/+9` 读写。后续格式化又会重用 `00/01`，因此“整个D805始终保存同一指针”不成立。结束行确认后，原父菜单重新取得城市指针，将工作库存写回城市 `+12/+13`。

生产源码不运行原6502、旧控制IR或运行时生成代码，不伪造ready、PPU完成或caller返回帧。缺失依赖严格停在真实前缀，实际调用与续程保留PC/SP所有权。

| [具名服务](lifecycle/validation.json) | 1038 | 1036真实caller RTS，2缺依赖严格前缀 | 5 |
| [协调器与父流程整合](source-integration.json) | 42 | 41真实caller RTS，1非局部返回 | 3 |

这些对照按各回执比较全部2048字节RAM、8192字节SRAM、AXYP/SP/PC、有序IO、四个PRG页及N163，不排除闲置栈。379个新增位置实际命中379个，表示声明输入域的位置覆盖，不能等同所有路径或输入穷尽。四份被动观察核心导出的实际软件callee状态另外标记；它们的N163是CPU/Source双方共享的显式夹具，原机没有捕获该瞬时硬件状态。详细范围见 [lifecycle/README.md](lifecycle/README.md) 和 [cpu-lifecycle/evidence.json](cpu-lifecycle/evidence.json)。

[独立静态验证](fields-static/verification.json) 实际执行10757个原CPU合同病例：10240个D987有类型输入正常caller返回、512个D805完整局部调用正常返回，以及5个裸指针反例；另有14个模型guards。这里恢复Source病例为0，与上表1080个源码对照分开。裸 `FFF8` 只执行到第一次环绕写坏指针后的明确前缀；`01E9` 会改坏caller栈，不能把全部10757例称为正常返回。

## 原Nestopia：普通输入完成一次配兵往返

本轮导入阶段14自然冷启动流程产生的配兵母状态；祖先和本轮数值准备均为0，每run导入一次，不称重新冷启动。普通输入向下两行选中ID30，右加100、左减100，再移到End确认，182帧回到世界/城市光标状态 `0400/0401=0/1`。

原兵数 `800→900→800`，工作预备兵 `9999→9899→9999`，提交后完整SRAM与起点无净差。工作缓冲退出后会复用，末值不能继续当城市预备兵解释。没有注入已选结果、ready或ack。

固定原核心和独立被动观察核心各用fresh进程双跑：每run182帧，共728控制帧。初始及逐帧完整RAM、SRAM、RGB、48kHz PCM和完整未归一化serialized state五类缓冲精确相同；1157份非空复跑文件检查、26张原PNG、2份完整WAV均有对应证据。

只有观察核心具有内部日志：32745个原始事件、123份稀疏完整2K/8K快照、四份实际callee输入导出，关联两个实际D987保存/恢复实例。原核心本身没有内部指令trace；观察记录也不是新的源码病例或全局核心等价证明。原机未捕获瞬时N163，不能把后续共享夹具补称原机硬件快照。来源和逐帧范围见 [runtime/README.md](runtime/README.md)、[runtime/evidence.json](runtime/evidence.json)。

## 整体目标与交付边界

[整体逆向验收清单](acceptance/README.md) 将用户明确请求、现有证据及未决项逐项对应；源码服务缺口要按实际bank/entry/caller判断，未知服务总数仍未定义。候选数、字节重建和CPU病例衡量不同，不能相加为完成百分比。
