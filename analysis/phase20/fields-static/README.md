## 新方法

此次没有继续增加旧的独立高低字节分析轮数，而是增加了三类合同：

- 611个连续原始常量word构造前缀与80个同索引不可变ROM word构造前缀。保存完整16位地址集合；中途进入前缀不能获得配对能力。四个 `$8000` 数据窗口构造前缀包含真实 `LDY# / JSR F25F或F266`，没有猜测入口DE/E1值。其余未知 `$8000` 映射继续拒绝。
- 330个完整pair返回合同与290个仅标量返回合同，共620项。入口数据状态未知，合同包含每个本地RTS出口；未解析计算出口不产生合同。只在已有独立合同基础上增加输出不变量，不以递归或相同调用PC作为证明种子。这些是冻结有界分派、正常RTS路径条件下的静态合同，不是终止或全部损坏selector输入的证明。
- A/X/Y及有限PHA标量域最多32个值，超过后放宽为未知。只有分支的唯一实际前驱是相邻立即数CMP/CPX/CPY时，才按原标志关系限制路径；零位移分支的共用目标不作真假过滤。它能说明某些返回Y为0或名册范围的上下文；指针低高字节仍不独立重拼。

新增完整pair非零页store证明用于两次保守callee may-write闭包更新，最后另跑一次输出。最终没有再次搜索全部新store，不声称整个分析求得完整固定点；`finite_proof_refinement_rounds` 最后一项的新增store数为null。所有未知调用、部分写、索引回绕、RAM镜像和半指针跨代失效规则继承阶段19。50个未从初始根到达的位置仍以未知入口补入，没有用不可达推论删除它们。

## 对字段真正有用的根源清单

[city-field-root-inventory.json](city-field-root-inventory.json)完整列出380项及原bank/CPU/file offset、producer、近邻bytes、旧caller/定义切片索引。分类为：274项未知、79项城市对齐基址加动态索引、24项其他完整指针域可能相交、1项专用错位word读取、1项批量SRAM清零、1项完整城市模板复制目的写入。邻近FF比较或CPY#1B只作为诊断，不自动当作所有路径的名册上界。

`10:$BD97` 的Y为1，其后读取Y=2，形成 `LE16(city+1,city+2)`，并在AI补兵流程使用门槛300。正式金字段在 `+2/+3`；这不构成 `+1` 的正式资源名称，也不能仅根据错位形式就猜作者意图。

三段原始循环则给出了确定的批量生产者：

| 原入口／访问 | 精确地址与次数 | 意义与限制 |
|---|---|---|
| `30:$DD8F`，store `$DD9A` | 4096次，清零 `$6000..$6FFF` | 包含全部城市字节，但没有专用字段标签 |
| `30:$DDCD`，read `$DDED`／store `$DDEF` | 960次，physical bank16 `$8C00..$8FBF` → `$6000..$63BF` | 30×32完整城市模板，实际覆盖每城 `+1/+28..31` |
| `30:$DE12`，read `$DE32`／store `$DE34` | 2880次，physical bank17 `$8000..$8B3F` → `$63C0..$6EFF` | 武将及邻接模板，与城市区不相交 |

[structured-loop-contracts.json](structured-loop-contracts.json)核对每段初始化区域的所有冻结CFG外来边只进入initializer，保存全部原bytes与唯一计数合同。没有把任意中途跳入循环、未知中断破坏或隐藏入口纳入证明。

一个不能贸然收紧的反例是 `11:$C71A..$C762`：指针每轮加12，但 `$C732` 调用的固定 `$E89A` 会从RNG游标 `$0054` 加载X。因此随后 `INX / CPX#ED` 不能单独证明“恰好237条武将记录”的界限。本轮继续保留该指针算术的不确定性，不据此断言自然游戏已发生越界。

结论是：这些字节有真实的整块清零、模板复制和部分索引扫描用途；仍未发现足以为尾部四字节命名的独立专用消费者或原UI标签。有限原机不变化、初值为0以及本轮排除其他指针，都不足以证明正式保留含义。阶段19确认的 `+16` 宝／タカラ不与这五个未决字段混同。
