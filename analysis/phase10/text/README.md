# 阶段10：独立文本服务与真实 PPU 命令消费

`source/recovered/text_services.py` 根据原 ROM 独立重写文本数据解析、字形缓冲构造和 PPU 端口写入。它解析游戏的文本命令，不执行 6502 指令、不解释控制 IR，也不是原始源码。消息仍由真实队列和消费状态推进；模块不生成 NES 帧，不替玩家按键，不合成硬件 ready 或文本完成信号。

当前回执为 **893 次原 ROM CPU 对照、7 项源 guard / 暂停恢复检查、0 失败**。其中 83 次使用阶段9已经冻结的原核心 RAM/SRAM 快照作为 CPU 输入，`native_field_comparison_count=0`：这不是新增的完整核心录像或逐帧图像验证。

## 调用接口与真实入口

构造 `TextServices(shared_memory, TextData.from_rom(rom))`。涉及端口读取的消费函数应使用 `ServiceMemory`，由调用者提供实际 `$2002` 样本。表与字节数据仅从 SHA256 为 `26c8d921ff5c208191f136480bcd8d7e89c2e4ed40a0ac7b51482bcb52fe2b82` 的只读 ROM 提取。

| 方法 | 原入口 | 恢复的作用 |
|---|---|---|
| `produce_text(budget=4096)` | physical29 `$A003 → A154/A158` | 从实际 `$0310` 队列和 `$A6/$A7` 数据指针生成一段文本；在消息结束、换行、重新定位等原边界返回 |
| `consume_text()` | physical29 `$A000 → A048` | 普通逐字或 burst 输出到 `$2006/$2007`，保留重音行和原 cadence 条件 |
| `consume_map_commands(budget=256)` | physical29 `$A006 → A11B` | 消费 `$0380` 的长度、地址高低字节及 tile 包；执行原 PPUCTRL 更新 |
| `cancel_text()` | physical29 `$A10A` | 明确执行原取消路径：`$0300/$0304=FF`，清 `$007E` bit0 |
| `text_ready()` | physical13 `$DF27` | 只检查 `$0304==FF && $0300==FF`，返回原 carry 谓词，不改队列 |
| `draw_actor_panel()` | physical29 `$A027 → A830` | 将 `$0509` 所选武将的名称构造成上下两行 nametable 命令，设置 `$007E` bit2 |

CPU 对照覆盖每个方法到原 RTS。语义方法本身不模拟调用者的栈弹出；完整 NMI 的调用者返回协议由独立 `BattleNMIServices` / `BattlePresentationServices` 负责，并另行验证。

## 文本数据命令

原 `$A208` 分发表恰有32项，合法命令为 `$80..$9F`；若干编号共享同一处理器。普通字形字节为 `<$80` 或 `>=$C0`。`$A0..$BF` 没有被当作合法命令扩展，源 guard 会拒绝这些表外输入。

| 数据编码 | 原行为 |
|---|---|
| `$80` | 结束当前消息、写行末 `$80`、请求 text job，并移动实际 `$0310..$0313` 队列 |
| `$81` | 换行，PPU 起点加 `$0040`，保留当前脚本继续位置 |
| `$82/$83` | 切入嵌套消息 / 恢复先前消息及数据指针 |
| `$84/$85` | 设置 / 取消 burst 模式 |
| `$86,$8A..$8F` | 读取新的位置参数并在原边界返回 |
| `$87/$88` | 设置 / 取消单行模式 |
| `$89` | 设置 tile 偏移字节，保留8位加法回绕 |
| `$90..$97` | 读取相应 `$042C` 报告槽中的武将 ID，再插入名称符号 |
| `$98..$9B` | 将对应的24位报告值转成原 packed BCD 六位数字，保留去前导零规则 |
| `$9C` | 读取参数所选报告槽中的城市 ID；负值占位，城市索引乘8先按字节回绕 |
| `$9D` | 参数选择报告槽中的武将 ID，输出固定宽度符号及原重音占位 |
| `$9E` | 输出 `$044C` 字段值，保留高字节 `FE/FF` 占位和8种宽度规则 |
| `$9F` | **参数是报告槽索引**；经该槽读取武将 ID，不能把参数本身解释为字面武将 ID |

名称符号 `$39/$3A` 写重音行而不推进普通字形列，固定宽度路径另保留原补空格行为。数字格式、列偏移、嵌套消息和队列移动均使用实际字节状态，没有按现代字符串规则改写。

`select_message_window()` 按原 `$A690` 选择数据窗：消息编号低于32时使用 mode0，其余读取实际 `$007A`。原表只有15个 mode，source guard 拒绝15及以上。消息指针高字节在 mode3..8 加 `$40`，其他 mode 加 `$20`；数据窗请求保持原 `$E1/$E000` 写序。

## 命令消费与暂停恢复

生产者与消费者分别有实际返回边界。生产者的 `waiting` 是原来的早退 RTS，例如已有 text job 或 `$0300==FF`；它不代表硬件输入缺失，也不会清消息完成标记。完成一个脚本后，仍须消费者写完缓冲，才能由 `text_ready()` 的双条件判断真实就绪。

`consume_text()` 先检查 `$007E` bit2，map job 保持原优先级。普通模式分别输出字符与重音行，只有原行末路径才清 `$007E` bit0 并置 `$0304=FF`。burst 仍执行实际端口写入。cadence 条件成立时，原 tail `$EE72` 实际调用 fixed `$E70E` 上传调色板；此路径保留 text job，不伪造逐字输出或完成。

`consume_map_commands()` 以 `$0380` 包的 count、地址、tiles 写 PPU；count0 具有原来的256字节含义，`FF` 结束。它不会清除自己选中的 `$007E` 位：原 `$EE53` 分发器在进入服务前执行该操作，不应由语义消费者重复或清除其他 job。

缺少 `$2002` 输入时，消费者返回 `dependency` 并保存 generator 内的准确位置。调用者必须保留**同一 `TextServices` 实例和同一共享内存**，补充明确的输入后再次调用同一种 consumer。先前已经发出的 `$2006/$2007` 写不会重播；调色板 cadence 也保留其内部 `BattleNMIServices` 实例并从暂停点继续。另一种 consumer 在当前暂停任务尚未结束时会被拒绝，避免抢占未完成的端口序列。

7项源检查中，3项是非法 mode、命令和宽度；另外4项是逐字、burst、调色板 cadence、map consumer 的输入缺失与恢复。后4项比较暂停恢复结果与连续执行的独立源参考，包括 RAM/SRAM 和完整写序，并检查重复等待不重复写入。它们**单列为源检查，未计入893次原 CPU 对照**。非法或无终止符数据的预算异常不是模拟出的成功返回；本模块不保证非法输入调用具有事务式回滚。

## 武将名称面板

`draw_actor_panel()` 完整恢复 `$A830` 的59字节 `$0380` 模板及两次 fixed `$F308` 名称读取。raw selector `$30` 映射到 physical16，名称地址为 `$901A + 10*officer_id`。以排除 `$39/$3A` 后的符号长度查 `$F35F` 居中表，上行放重音，下行放名称，并设置真正的 map job。

该方法构造名称的 PPU 命令缓冲，不生成完整头像或 framebuffer。24次原 CPU 对照覆盖 slot0/1/10/19 与6个合法武将 ID。周围的 `$3D` EE07 程序银行包裹属于 presentation 调用者，基础 text API 不额外虚构外层 farcall。面板实际 buffers 和 `$0000..$0002` 寻址值在这些专门病例中比较。

## 比较范围与字节证据

每次原 CPU 对照比较完整 **8,192B SRAM**，基础声明 RAM 为 `$007D/$007E/$00A6/$00A7/$00E1` 和 `$0300..$0374`。数字病例另比 `$0007..$0009` packed BCD；map 包另比 `$0000/$0001`；名称面板另比 `$0000..$0002` 和 `$0380..$03BF`。所有病例比较实际 IO 写入顺序及最终 PRG 银行；`text_ready()` 另比原 carry。其他 CPU 寄存器、栈与临时算术 scratch 均不属于这个语义契约。
