母存档是原 ROM 进入战场后的 `analysis/runtime/phase3/attack-intro-7.state`，其全局 / NMI 状态为 4 / 3。每个案例只在开始前准备明确列出的武将数值、战场坐标、单位 ID 和少数 RNG 游标；之后不写内存，全部选择与确认由真实手柄输入完成。每条改动的地址、旧值、新值和原因都在各案 `validation.json` 的 `RAM_preparation` / `SRAM_preparation` / `rng_preparation` 中，准备后的完整 RAM / SRAM / 核心存档也保存为 `initial-*`。

施放者为槽 10，原槽 ID131 改用原武将 ID109。其原知 99、武 62、体 71 保留；普通 8 案和死亡案准备经验 15000、等级编码 7、兵 1000。升级案准备经验 3490、等级编码 2、兵 1000。`byte11` 原低半字节保持不变。一般目标体力准备为 99、兵 1000、知 0；ID9 改用目标知 10，ID8 目标忠准备为 0。死亡案在同一 ID1 场景将目标体力准备为 1。相邻目标的准备也逐条记录，未把阵营、计略成功、死亡状态或奖励直接写成结果。

## 回执结构与复跑

每个正式目录包含 `validation.json`、`repeat-validation.json`、`checkpoints.json`、`frame-fields.json`、`input-plan.json`，以及各检查点的原 PNG / RAM / SRAM / 核心存档。标准 8 个检查点为 `menu-built → tactic-selected → target-cursor → cast-confirmation → effect-before → effect-generated → result-message → final`；升级案额外保存 3 个通知检查点。`effect-generated` 是原 AP 首次变化帧的帧末抓取，不声称它代表效果函数入口的指令瞬间。

逐帧日志包含全局 / NMI / battle 控制状态、AP、轮次、`$0543/$0544`、报告、粮 word、十面缓存、AI request / proposal / RNG、固定 RNG、全部六战场数组及关键武将原 12 字节。`troops_raw_u16` 与 `troops_low10` 同时保留，`$063C` 明确为百兵量缓存。本次 1000 兵起点两个视图相等，但报告不把所有原存档兵 word 一律解释为 10 位。

在工作区根目录，用现有 Pillow / ctypes 的 `python3` 即可运行；此脚本不需要 py65：

```sh
python3 scripts/capture_remaining_tactics.py '/Users/paulasmith/Downloads/三国志2超级版.nes' --death-case --levelup-case
python3 scripts/capture_remaining_tactics.py '/Users/paulasmith/Downloads/三国志2超级版.nes' --death-case --levelup-case --out analysis/phase9/runtime-repeat --compare analysis/phase9/runtime
```

`--ids` 可以选择这 8 个 ID 的子集；`--death-case` / `--levelup-case` 另加对应结算场景。复跑需本机现有母存档与 `.toolchain/nestopia/nestopia_libretro.dylib`。正式脚本冻结 SHA256 为 `c71d863b5825e9e1db175907ca5fbf60f66042cfaf23743054bef7da831f4c7d`；Nestopia 为 `2.0.0 135dfa6`，核心哈希 `924191ebb41b863993a96cf461321058b391c507a6fed2f1203df44eaa5a539a`。原 ROM SHA256 为 `26c8d921ff5c208191f136480bcd8d7e89c2e4ed40a0ac7b51482bcb52fe2b82`，脚本执行前后均检查。
