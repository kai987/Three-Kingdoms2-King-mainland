# 第8阶段：可读战术策略、退却补给治疗与真实计略触发

本阶段把八种战术策略和 A02D 合作扫描从控制 IR 改写为独立 Python 玩法源码，并补齐计略施放的数据流程、十面埋伏的完整缓存生命周期。原 ROM 保持只读；重建 ROM 仍与原文件逐字节一致。指定 REA 项目此前取得的 bank8/9、12/13 证据继续作为机器码来源，本轮没有重复生成同一份反编译。

请打开 [交互式证据页](index.html)、[策略源码](../../source/recovered/tactical_strategy_ai.py)、[施放与效果源码](../../source/recovered/tactical_effects.py) 和 [GameEngine 统一接口](../../source/recovered/game_engine.py)。这些是从机器码重新整理的源码；完整图形、音频和场景初始化仍有显式依赖。

主体 **5,779项原ROM CPU对照、11项源码guard，0失败**；统一接口另有 **46项原CPU对照、2项guard、5项原核心字段核对**。策略2,217项中2项明确止于调用预算前缀，其余2,215项到真实routine返回；效果3,562项包含明确的前缀/后缀和未恢复入口边界，不能全部当成整段施放。两组原核心回放共4,168帧、24个检查点，102个非空回放产物重复一致；独立CPU请求/到期证据另有6个重复产物，合计108项hash核对。不同证据域分开计数。

## 这次补齐的源码

| 模块/API | 恢复内容 | 比较与调用边界 |
|---|---|---|
| `TacticalStrategyAI.step()` | 完整 A02D 扫描、八策略、普通/特殊计略选择、退却及资源处理 | 完整 SRAM 与声明的玩法 RAM；不承诺 CPU 寄存器、栈和 mapper 写入等价 |
| `run_strategy(0..7)` | 下表全部策略编排，调用已经独立恢复的移动、邻居、候选排序和随机算法 | 不解释IR或执行原ROM；不提交坐标/AP/施放，保留补给和治疗的原提前副作用 |
| `TacticalEffects` | 施放费用、效果分派、成功判定、兵损/状态/经验、部署、过期、触发及确认清除 | `after_*` 要求真实前序服务已执行；返回的图形/音频依赖不能当成完成信号 |
| `GameEngine.tick_tactical_strategy()` | 共享内存的完整可读 AI 更新 | 原 `tick_global()` / `tick_tactical_ai()` 保留独立 CPU 控制模型以验证真实调用栈协议 |
| `GameEngine.commit_tactical_retreat()` | C91E 队伍数/低10位总兵结算，再执行 BC2D 名册收容和战场清除 | 调用者先提供原 0509 退却槽和 050B 目的城；不代替选择/文本/确认 |

全局状态4调用的游戏决策现在可以直接用可读策略模型运行。既有 CPU 控制 IR 仍作为独立的精确协议模型；两者承担的比较合同不同，不能以纯玩法内存一致声称 CPU 寄存器或完整 NES 帧一致。

## 八种策略的实际次序

数字是原表索引，以下文字是行为说明，没有给它们编造正式菜单名称。策略 0..4 共用退却优先、特殊计略随后；是否立即尝试普通攻击按原分支区分。

| ID / 入口 | 可读控制流程 |
|---|---|
| 0 / A0B1 | 退却→特殊计略；非负侧直接基础计略。负侧先相邻攻击→基础计略，失败后随机低2位非0靠近 slot0，否则不行动 |
| 1 / A105 | 退却→特殊计略；AP至少2且相邻有对侧首槽0/10时攻击，否则向对侧首槽或城市坐标移动 |
| 2 / A166 | 退却→特殊计略→相邻攻击；以自己为中心 radius2 最近敌军，有则靠近，无则用对侧首槽/城市坐标 |
| 3 / A210 | 退却→特殊计略→相邻攻击；以本侧首槽为中心 radius2 找敌军，目标附近有非首槽友军时尝试基础计略，否则靠近；没有目标时基础计略→本侧首槽 |
| 4 / A2AD | 退却→特殊计略→相邻攻击；自己 radius3 最近敌军→靠近；没有目标时基础计略→本侧首槽 |
| 5 / A329 | 向城市特殊坐标索引0生成移动；预计下一格到达时低 nibble 置7并执行补给算术 |
| 6 / A507 | 向索引2生成移动；预计下一格到达时低 nibble 置7，检查钱≥50、扣钱、随机治疗并封顶 |
| 7 / A606 | status3，不提交行动 |

普通计略先按「知」分档1/3/5/7/9，以 radius5 筛选敌候选，读取原始16位兵数排序，然后按原行动优先序、AP、持续状态和16项环境条件选择。特殊计略要求知≥92、packedbyte11 高 nibble≥3，再按武将白名单、各项等级/AP/兵数/环境条件选择 ID10..15。目标相等交换和调用者给定的 002F 排序轮数被保留，不能替成稳定的完整排序。选择出 status2 只是提案；后续施放仍要经过真实战场状态与效果判定。

[策略原字节与数据表](strategies/evidence.json) 和 [策略验证回执](strategies/validation.json) 列出完整入口、前置输入、原指令执行地址及范围。游戏语义不会把失效选择修成成功。

## 退却、补给与治疗的数值规则

AF0D 按角色判断：君主需原始兵 word<301 且体力<51；slot0/10 的非君主首将在本方原始总兵<1757 且本方+3499<敌方时直接允许退却，否则需兵<101且体力<41；普通武将需兵<201且体力<100，再抽取0..99，低于70才允许。原始兵 word 包含 byte9 高6位；不能替成界面低10位兵数。负侧目的地直接来自052A；非负侧按八项邻城顺序选第一个同君主且名册有 FF 的城，没有则保留最后一个中立城，目的地符号位为负则不提交。

真正提交退却时，C91E 按单位0628的符号位减少051E/051F队伍数（u8回绕），总兵051A/B或051C/D减该武将低10位兵数，借位则归零。BC2D之后将武将插入目的城首个 FF、清六组战场数组及匹配缓存槽；首槽0/10保存逃离武将/目的城052B/C，中立城按该路径的 F0 掩码改归属。高层组合保留此前归属源码的不同掩码与名册副作用。

补给使用双方资源 word：粮0522/24、钱0526/28，侧偏移0/2。总兵是双方 raw16 加总后回绕；需求量先计算 `floor(4*本方总兵/1000)`，再乘 `(30-回合)&255`。不足量为 `(需求-现粮)&65535`，没有负数钳零。预算为 `floor(钱*7/10)`；以城市原报价换算费用，够预算买全部不足量，否则用预算购买。所有原16位回绕保留，尤其现粮充足时的减法下溢。它发生在预计移动到达的判断中，坐标及移动AP仍由后续战场消费阶段提交。

治疗先把策略低 nibble 置7，即使钱不足也不会撤销。钱≥50时扣50，拒绝抽样得到0..10，加35形成35..45治疗量；体力先按 u8 加法回绕，再和原初始武将记录体力比较封顶。移动中的AP扣除与50资金费用是两条独立路径。

## 计略施放与十面埋伏

本轮独立恢复效果 ID **0、2、3、4、6、11、13、15**：火計、虚兵、要撃、乱水、偽撃転殺、十面埋伏、連弩、奇門遁甲。其中 ID6 原分派复用 ID0 的 B062 效果；保留原别名。其余八种效果在 B02B 清工作区后返回实际效果入口依赖，不能当成成功施放。16项名称、选择条件和费用表已确认，不等于16项效果全部独立恢复。

普通效果使用真实成功门槛：距离至少6直接失败且不抽样；其余路径按知差、等级差、距离表与050F/6F02字节规则计算，门槛夹至5..95，然后原固定随机表拒绝≥100。火計/要撃/乱水/偽撃転殺/連弩继续处理原伤害量、兵损、同记录别名写入与经验；虚兵写持续状态，奇門遁甲抽样持续码。AI和玩家有各自AP表；费用按u8减法，成功失败都必须遵守各自施放时机。[效果证据](effects/evidence.json) 明列每个真实图形、音频、文本等待边界。

十面埋伏的完整链如下：

1. 玩家 AF73 检查原始兵word至少100、地形类0、本侧缓存空。AI 由特殊选择的 ID11 条件和专用 C1AF 施放。
2. B42A 在本侧 `04D8..04DB` 或 `04DC..04DF` 写 `[部署槽,x,y,5]`，原始16位兵数减100。**玩家施放扣10 AP；AI跳过普通扣费分支，扣0 AP。**
3. 全回合的实际 CE20 尾部处理两组TTL，TTL等于FF才跳过，否则减1，1→0才清槽号；0→FF下溢后保持有效槽，XY和TTL不是一并清空。即使槽号已经FF，只要TTL不是FF也会继续递减。
4. 移动后 A51F 在请求标志FF时写1和移动槽，global4 A02D 调 B933。它读取敌侧缓存、radius2候选和地形类0；保留原精确坐标捷径中读取 `0614[group]` 的索引行为。被覆盖的知差/第一次0..100抽样仍实际消耗随机游标。
5. B933 用第二组0..10抽样、部署者知和整个packedbyte11的带carry运算扣移动者低10位兵数；这个扣兵路径保留 byte9 的高6位。042C/D记录实际兵损，状态回0；部署槽尚未清除。
6. A535 数据后缀给部署者结算损失相关经验、刷新百兵缓存，然后进入真实头像/消息流程。实际文本与确认通过后 A5F5 才清敌侧缓存槽号，XY与剩余TTL保留。

## 使用与复现

```python
from pathlib import Path
from source.recovered.game_engine import GameEngine

rom = Path('/Users/paulasmith/Downloads/三国志2超级版.nes').read_bytes()
game = GameEngine.from_snapshot('analysis/phase7/runtime/natural-turn/ai-request',
                                rom=rom, mapped=True, data_window_bank=6)
result = game.tick_tactical_strategy()
print(result['after'])
print(game.tactical_bridge_rules().proposal())
# 这是玩法数据更新，不是视频帧；此例原提案是slot1向右、费用3。
```

读ROM地图描述时，mapped内存每次公开调用读取当前物理数据银行；flat内存必须提供真实银行上下文。方法内部只跟踪逻辑数据读取，不冒称已经写mapper或等待过NMI。`tactical_effect_rules()` 与 `commit_tactical_retreat()` 共享同一内存，具体前置字段和服务边界见各方法 docstring。

```sh
.venv-trace/bin/python scripts/verify_tactical_strategy_ai.py '/Users/paulasmith/Downloads/三国志2超级版.nes'
.venv-trace/bin/python scripts/verify_tactical_effects.py '/Users/paulasmith/Downloads/三国志2超级版.nes'
.venv-trace/bin/python scripts/verify_phase8_integration.py
python3 scripts/verify_phase8.py '/Users/paulasmith/Downloads/三国志2超级版.nes'
```

原模拟器需要项目内 Nestopia 动态库；纯原CPU验证需要 py65。本轮不把尚未独立恢复的八种计略效果、PPU/音频/IRQ与全游戏场景初始化计为完成。
