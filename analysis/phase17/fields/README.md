# 城市未命名字节与原始记录访问合同

城市 `+1` 和 `+28..31` 的正式游戏名称仍未证明。本轮把原来的 647 个可能别名访问缩小到 **589 个**，并补出可直接执行的记录指针、容量检查、提名与显式扫描边界。没有把零值、初始布局或没有发现专用消费者写成“保留字段”或“不使用”。阶段16源码、Native、HTML及旧版本归档保持原字节。

生产代码为 [city_field_contracts.py](../../../source/recovered/city_field_contracts.py)，不执行6502、控制IR或原CPU helper。所有原CPU指令只在验证器运行；分析器的CFG和数据流只用于生成证据。

## `+1` 的真实消费者

物理bank10 `$BD95..$BDA1`（file `$015DA5..$015DB1`，包括16B头）从 `$20/$21` 指向的城市记录先读 `+1`，再读 `+2`，两次 `SBC` 判断该小端字是否至少300：

```python
overlap = city[1] | (city[2] << 8)
passes = overlap >= 300
```

已确认的金字段是小端 `+2/+3`，所以这个门槛并非正常金数。若 `+1=0`，金255会通过，而金256会失败。源保留这种错位复合读取及实际A/Y/P；没有把 `+1` 命名为第二种资源，也没有擅自修正原算法。1024个原CPU前缀用全部256种 `+1`，分别配金低字节0/1/2/255，并独立改变金高字节。

## 10人名册、终止符和通用扫描

城市的十个名册槽是偏移17..26。**合法满10人时可以没有FF终止符**。原27 `$AD41` 同势力迁移以9+1的合法容量输入实际生成 `[0,1,2,3,4,5,6,7,8,196]`，`+27..31` 保持0；随后原26 `$C21D` 提名读取恰好17..26十字节，未读取任何尾字段。两步原CPU与独立源码对照已经包含在6548例中，[legal-full-roster-origin.json](legal-full-roster-origin.json) 是该CPU链的证据，并非原Nestopia影片或自然战役到达满员的证明。

| 路径 | 原始边界 | 已证实的作用域 |
|---|---|---|
| 玩家迁移容量前置27 `$A71B..$A741` | `$A721 CPX #10`，满员跳 `$A777`；可选数=min(10−目的人数,来源人数) | 满目的城先拒绝；允许填至10，不能据后面无界helper声称正常UI溢出 |
| AI战争迁移前置10 `$A208..$A230` | 目标数加3后夹10；现有人数≥目标则跳过 `$A303` | 正常目标人数上限10 |
| AI和平迁移前置10 `$B144..$B171` | 对实际平均人数构造目标；现有人数≥目标则跳过 `$A303` | 原0..10均值域得到目标4..10；raw大于10是另外的边界输入 |
| 提名26 `$C21D..$C25C` | FF提前结束，或者cursor比较27结束 | 最多十槽；按武将 `+4` 徳选择，平局保留原后者优先行为 |
| 迁移插入前缀10 `$A442..$A44F` | 从17寻找FF，本地没有26上限 | 独立前缀在绕过正常容量前置时可读/写 `+27..31`、下一城市及其 `+1`，不产生正式字段含义 |

`A442` 的256个显式FF位置输入逐一与原CPU比较，包括四个尾字节和下一城 `+1`（原城相对偏移33）。整256字节没有FF时，原Y循环会回到同一偏移；源返回 `waiting`，保留PC/SP及原循环寄存器。恢复只会重新读取调用方实际提供的内存，验证用明确新增的FF输入后继续；不会制造ready、ack或假RTS。这个边界测试不是正常容量受保护的迁移发生越界的证据。

因此，四个尾字节目前只能描述为：原始记录复制/清零涵盖它们；通用无界记录扫描在明确边界条件下能够别名访问它们；尚未找到可靠的专用字段消费者、专用生产者或正式标签。没有证明它们是padding或unassigned。

## 全银行扩域与647候选复核

[dispatch-bank-inventory.json](dispatch-bank-inventory.json) 保留32个物理PRG银行全部262144字节的调用字节样式检查，并从八组实际连续JMP入口向量中的87个槽，以及可信far/direct入口扩展CFG。可信指令位置从46518增到 **47968**（新增1450），间接访问从1463增到 **1481**（新增18）。155个全PRG `JSR EE07` 字节样式中有4个仍未获得可信控制入口；它们保留为原始样式，未被自动提升为代码。207个可信映射/远端调用记录保存调用原字节、selector上下文及inline目标。

银行0..7和16..22没有通过本次已解析入口链得到可信执行位置；这不等于这些银行在任意外部mapper/间接跳转条件下绝不可能执行。161个computed dispatch、映射上下文或其它实际控制屏障仍明确保留。8000数据窗没有默认猜银行，也没有将数据布局直接解读为指令。

[alias-refinement.json](alias-refinement.json) 从旧647条逐项复核：58条在明确合同下排除，589条继续保留。11条来自准确局部上界/指针公式等；47条来自固定 `$F368` 的实际16槽指针表加可证明Y范围，枚举低/高字节独立交叉集合，**不假定**输入一定是0..6合法君主或两个指针字节仍有相关性。新增18条间接访问另列，均有非城市记录或实际ROM指针的地址证明，未把新未知项漏出总数。

`F368` 只有前七个槽是君主记录指针，raw索引7..15实际读相邻机器字节。其中raw索引8得到 `$5F20`，较大的Y可以跨入城市0，说明“凡F368就一定是君主”不成立。本轮只排除有效地址集合确实与 `$6000..$63BF` 不相交的具体读写点；未知/宽Y仍保留候选。589条是**可能影响城市辅助字节的尚未解析别名**，不是589个已确认消费者。

原字节证据为 [raw.asm](raw.asm)、[static-catalog.json](static-catalog.json)、[instruction-atlas.json](instruction-atlas.json)、[pointer-accesses.json](pointer-accesses.json)。每个排除带原bank、CPU、包含16B头的file偏移、原字节及指针/索引合同。阶段16四份探索种子只读取其已归档的精确portable副本，不依赖被排除的探索目录。
