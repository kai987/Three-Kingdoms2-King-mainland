城市 `+27` 只在符合原代码条件的扫描调用中递减。年份字节为 89 且月份索引小于 4 时，整个扫描直接跳过；`owner_byte & 15 == 7` 的城也跳过。计数从 1 减到 0 的当次不会重新抽取，下一次合格扫描才可检查。因此“写 6”不等于未经证明的“六个月”。原中立判断使用低四位，不能替换为通常归属的低三位。

计数为 0 时，原代码读取城市 `+11` 统治度，按下表选择阈值；调用原 `E862(A=100)` 的独立源码，接受字节严格小于阈值才形成候选，并把计数写为 6。E862 依赖 ROM 排列表和随机游标的拒绝采样；这里不把阈值宣称为独立、无偏的百分概率。

| 统治度原字节 | 候选阈值 |
|---|---:|
| 0..19 | 50 |
| 20..29 | 30 |
| 30..39 | 10 |
| 40..49 | 5 |
| 50..255 | 不抽取 |

`AB25` 只生成三十城候选列表。后续 `ABA9` 在原代码中选择类型 1/2/3，分别经 `ACCD / ACE9 / AD14` 扣人口 `+6..7`、金米 `+2..5`、土地产业 `+8..9 / +14..15`。这些原字节作为用途参考列出；本轮没有重新恢复或对照整个消息、动画和损失结算，也没有给三类事件强填官方灾害名称。

`+27` 还有真实边界别名：bank27 `ACF0` 经 `DC6B` 统计十个名册槽中非 FF 的数量，在 `AD01` 写到 `17+count`。满十槽时会写到 `+27`，覆盖冷却；有空洞时也按数量插入，未必找到第一个空洞。原人类菜单另有容量限制，本轮满城和空洞调用是明确的边界实验，不表示正常菜单接受第十一名武将。`+28..31` 在该最大十槽计数的插入中仍不会成为目标。

`6F06` 的检查只在文字 `0300/0304` 均为 FF、PPU 请求 `007E` 为 0 时进行。锁非零就写 `0401=2`；锁为 0 时置 1，月份索引 3 写阶段 6，索引 9 写阶段 7，其余写阶段 15，并清 `0402`。月轮前序 `A041` 的扫描索引从 6 增到 7 才清锁并推进月份；初始 FF 增到 0 不推进月份。年末年份按原字节回绕。

既有自然、无内存注入的 phase14 原 Nestopia 逐帧资料支持这一用途：首月第 1943 帧锁为 1；第 11283 帧月份 0→1，同时锁清 0；第 11301 帧锁再置 1。这里复用已冻结的 [逐帧记录](../../phase14/runtime/cold-city-domestic-cycle/frame-services.json) 和原双跑回执，没有新增 Native 运行，没有内部 CPU 指令追踪，也没有从这些画面声称观察到了成功灾害。

新 API 位于 [record_fields.py](../../../source/recovered/record_fields.py)：

- `CityAuxiliaryFields.from_memory(memory, city)` 返回只读补充视图，公开 `byte1_unresolved`、`assignment_gate_word_01_02`、`assignment_gate_at_least_300`、`adverse_event_cooldown`、`unresolved_tail` 和名册插入边界属性。
- `RecordFieldServices(memory, rom, services).run_entry(A2BC/AB25, registers=actual)` 恢复两个完整局部过程，要求实际 bank25/26、调用者寄存器和已有 RTS 栈。固定 `F2AF/E862` 必须通过独立源码真实返回；未提供时保持严格依赖。
- `assignment_word_gate_prefix(registers)` 是 bank10 `BD95` 到 `BDA3/BDEE` 的显式前缀，不包含资源截顶、名册选择、分配或 RTS。
- `calendar_turn_scan_prefix(registers)` 是 bank25 `A041` 到 `A068/A06B` 的前缀，不调用后续外交计数递减、君主选择或 RTS。
- `recruitment_append_prefix(registers)` 是 bank27 `ACF0` 到 `AD03` 的前缀，包含独立 `DC6B` 计数和纯 `F2AF`，尚未修改武将状态、忠诚或返回其调用者。固定服务缺失时可 `resume()`，不得把等待或伪改 PC/SP 当作已返回。

建议整合只读补充视图，保持既有 `CityRecord` 和 `CityPanelServices` 的完整流程；新字段服务可作为独立字段合同，不应抢占旧控制器的已有服务入口。

武将旧表也已复核：`+5` 在在野、释放等路径具有城市/地点用途，但初始每名武将都是 0，不能把它统一当作任职城市；名册/城主仍是归属证据。兵高六位已有原数值溢出生产者，未得到独立训练/状态旗标名称；状态低二位的 3 仍包含体力归零、移除、君主处置和异常名册处理等不同上下文，不是统一永久死亡；适性编码 3 的正式意义和自然生产者仍未决。详见新 [schema.json](schema.json)，未覆盖修改历史表。
