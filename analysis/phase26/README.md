## 坐标链及源码

全局 `E18B` 的非单挑分支通过 `F237` 的十进制选择器40（十六进制 `$28`）建立代码 bank 8/9，再经 `A003 → B130` 初始化。`0500 == 11` 的单挑后果分支会绕过这条部署链。全局流程抵达 `E066` 属于主循环边界，不能计为返回原调用者的普通 RTS。

`B130` 按两方君主记录的控制字节是否恰为3决定是否自动布阵：第一侧经 `B16B → B1B0 → B2AE`，第二侧经 `B195 → B1B0 → B312`。这些均已有具名源码，`B2AE/B312` 是同一部署 owner 的内部调用，不是两个新发现的缺失服务。

本轮将两个指针构造体整理为更直接的 [DeploymentPointerServices](../../source/recovered/deployment_pointer_services.py)，并通过 [DeploymentPointerGameEngine / SceneCoordinator](../../source/recovered/deployment_pointer_integration.py) 接入最新可读入口。新 owner 仅接管实际代码页8/9的五个入口 `A003/B130/B1B0/B2AE/B312`，保留原调用栈、PC/SP、等待和非局部返回边界。与现有战术AI、商店、君主选择入口集合没有冲突。既有 `B1B0` 策略分配、武力排序及其他场景服务继续继承。

两个构造体的可读含义是：

1. 第一侧用选择器 `$30` 读取 bank16 邻接表；匹配 `$052A` 时通过 `$31` 读取 bank17 阵形模板，否则选0。模板乘32后按八位回绕，再与 bank6 的城市指针表 `$8C52/$8C53` 合成16位坐标指针。
2. 第二侧在 bank16 邻接匹配后读取 `$9E62` 模板，否则选0；模板乘34后按八位回绕，再与 bank6 的 `$8000/$8001` 城市指针表合成16位坐标指针。
3. 两侧均用 `$26` 将数据窗口切换至 bank6，写入四个策略组偏移。`B1B0` 先读取主将的 `(y,x)`，再按策略组分配余下单位；结果写入 `$0614+slot` 和 `$0600+slot`。

**历史文案更正：第二侧是34倍，不是36字节步长。** 原字节执行“四次ASL、加原值、再ASL”，冻结旧源码原本也实现34倍；旧 phase11 README 和 phase25 选链说明中的36B属于解释错误。本轮只补充 [更正证据](context/historical-wording-erratum.json)，不改旧文档，也不把该算法计为首次恢复。

两个体合计涉及92个原指令位置、187字节。这里的新增成果是可读重构、严格调用协议和新的地址/实际调用证据，不是重新发现全部部署算法。

采用 phase11 自然冷流程留下的 `battle-enter-confirm.state`，普通 `A35 + 无键125` 共160帧续行，保留导入存档来源与祖先准备记录；本轮导入不算新的冷启动。固定原核心与本轮独立的被动观察核心分别在新进程运行，并各自再复跑一次。所有观察事件仅归属于新核心。四次正式运行合计640控制帧，完整初始API状态与每帧五类完整buffer均逐字一致；1316个非空复跑产物、320幅PNG和2段完整48kHz WAV通过检查。

自然路线实际经过 `B130/B1B0/B2AE`，第一侧控制 gate 为3，第二侧为0。四个 G107 读取点 `08:B272/B278/B290/B296` 共执行8次，实际指针 `$8D4E`、数据 bank6，形成四单位 `(x,y)` 坐标 `(20,14)、(17,17)、(19,14)、(20,13)`。本次战场城市4按邻接 `2 → 12 → 11` 匹配来源城11后取得方向0，属于正常匹配。该自然路线未走 fallback 和第二侧 `B195/B312`；机制与受控CPU对照不能替代这些自然分支的实际覆盖。

瞬间软件快照与帧末状态分别记录，不能用复用后的帧末零页反推某条读取。完整2KiB RAM、8KiB SRAM、寄存器、实际栈及四PRG页作为新的源码/独立CPU输入；N163瞬时硬件内容没有被采集，软件对照采用明确声明的共同夹具，不能冒称设备瞬时快照。原模拟器音画与独立CPU续行属于不同证据域。

本路线城市辅助字段命中为0，只表示该次观察没有命中，不证明这些字段未使用或属于填充。

## 候选访问与原字节合同

详见 [静态摘要](fields-static/analysis-summary.json)、[完整访问表](fields-static/all-indirect-accesses.json)、[指针后置条件](fields-static/deployment-pointer-postconditions.json) 与 [原CPU合同校核](fields-static/verification.json)。完整主分母保持1526，上一版候选基线339；本轮新增四点条件不交，结果为1191不交、81可能、254未知，剩余335。原CPU合同共36443：1624个完整RTS、34816个构造前缀、3个裸读取反例前缀，另有13模型guards；这些合同的Source案例为0。

四点必须在真实 formation 返回且 mapper/零页合同成立后才能使用新的不相交结论；从裸 `B272/B278/B290/B296` 进入时不会凭空赋予指针。正常城市0..29、两侧全部byte索引读取都在 bank6 ROM。完整 raw 城市、模板字节与 Y0..255 仍保留，非法编号可生成内部RAM镜像指针，第二侧保守域还包括 `$2000..200E` 的潜在PPU端口。后一类只证明有效地址与目标城市辅助字段不交，不承诺硬件读取成功、没有副作用或是合法游戏行为；缺失端口输入时必须在读取前停止。

独立CPU对照不注入中断。逻辑读与派生的跨页 dummy 总线地址分别记载；py65不是总线周期模拟器，不能将其没有发出的 dummy 读取声称为实际观察。原字节入口的未证控制流、裸入口及全局固定点缺口继续保留。

部署子服务2009例（2007普通RTS、2严格缺失F266前缀）与协调器48例（47普通返回、1真实非局部返回）合计2057次Source对照、10个guards通过。子服务和协调器重复使用同3份新被动callee输入，不能计成6个不同Native输入。45个既有协调器fixture只是本轮回归。新生产源码不调用原CPU或IR解释器；独立CPU只作为无中断比较端。
