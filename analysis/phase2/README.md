# 第二轮：武将属性、战斗与 AI 的可读源码

本轮按用户要求继续分析原 ROM，确认了主要武将属性与装备字段，恢复了多段战斗、单挑和战斗 AI 数值/决策流程，整理为可执行 Python 模块及可编译 C11 计算库。原始 ROM SHA-256 仍为 `26c8d921ff5c208191f136480bcd8d7e89c2e4ed40a0ac7b51482bcb52fe2b82`，未修改输入文件。

这是一套**经机器码对照的部分游戏逻辑源码**。仍不能称完整原作者源码或完整游戏引擎；尚未恢复的流程保持显式缺口。

## 12 字节武将记录

记录地址为 `0x022010 + 12*id`；237 个有效 ID。如下字段由读取/显示/修改代码和实际字形支持。

| 字节/位 | 解释 | 确认程度与显示规则 |
|---|---|---|
| 0 | 体 | 确认，战斗减体与界面列对应 |
| 1 | 武 | 确认，单挑/效果计算和升级修改 |
| 2 | 知 | 确认，战术概率和 AI 门槛使用 |
| 3 | 忠 | 确认；100 时原界面显示 `--` |
| 4 | 徳 | 确认；保留原游戏名称，不改称“魅力” |
| 5 | 在野所在地 city ID | 强推断；清归属、写城市/邻接城市、搜索代码支持，初始全0 |
| 6..7 | 経験，LE16 | 确认；列表的“経”显示值为 `raw // 50`，通常受49,999上限约束 |
| 8..9 | 兵，原始 LE16 | 确认；显示/减兵取低10位，部分 AI 比较读取完整 word；byte9 高6位语义未确定 |
| 10 低5位 | 武器 ID | 确认；正常名称表0..23。24..31的异常武器值不命名为正常武器 |
| 10 高3位 | 防具 ID | 确认；名称表对应24..31，共8项；不是马字段 |
| 11 低2位 | 状态编码 | 编码和转移确认；0在野、1剧情待出现、2城市名册、3移除/败退等文字解释部分为强推断；3不等于已证实永久死亡 |
| 11 中2位 | `平 / 山 / 水` 标记 | 字形确认；“地形适性”的含义为强推断，值3未解释 |
| 11 高4位 | 经验档/等级 index | 确认；界面レベル=`index+1`，升级阈值和写回已恢复 |

关羽 ID38：`体97 武97 知84 忠99 徳88`，经验 raw1000→界面20，兵700，武器12、防具1，等级 index1→界面Lv2，标记“水”。此为初始 ROM 记录解码，不是额外修改后的存档。

32 个装备名称记录和像素图保存在 `../officer_fields/`。例如武器字形包括短剣、関王刀、方天画戟、蛇矛；防具字形包括絹巾、兜、鶴氅、竜鱗の鎧。名称图片以每条记录指定的 CHR 页绘制，不靠通用汉字编码猜测。

## 战斗与单挑

已恢复并逐段执行验证的核心包括：

- 格距：`max(abs(dx), abs(dy))`，处理战场 y 坐标跳过的一行。
- 共用策略成功率：正知差、正等级差、格距修正、环境修正；按原 8-bit wrap/sign 运算后限5..95，随机拒绝采样至 `<100`。
- 阵营转换 gate：忠值门槛、知+徳、等级差、距离，再决定是否翻转战场阵营标志。后续全部政治/名册更新仍未完整复原。
- 六段已确认效果数量，用 ROM 入口 `$B070/$B0EB/$B188/$B1E3/$B4C6/$B55C` 标识；未凭游戏常识填入动作名称。
- 饱和减兵、减体、同地址 alias、经验增长/升级、武力增长。经验 helper 实际按**新累积伤兵数/2**发放，保留这条不同于“只按本次损失”的规则。
- 单挑攻击参数、武器/防具修正、随机采样、命中/反噬分支、临时体力更新与消息选择。完整动画及结束后的所有 SRAM 回写尚未恢复。

减兵验证实际经过 `$EE07` 跨银行调用经验函数，再经 `$EE4D` 恢复银行。算术边界和 RNG 游标均有对照，不能用浮点或普通无限精度加法替代。

## 战斗 AI

已恢复 12 个流程，包括敌我符号位、20 槽范围候选、按兵 word 的相邻排序、知阈值、独立 RNG、基本/特殊动作选择、武将白名单、16 个环境适用条件及完整 `$A95C` 候选→排序→逐目标选择。

基本行动优先尝试编号 `6,5,8,9,7`，然后走1/2/3的随机分支、4及0；每步仍受知档位、资源、目标兵和环境 predicate 限制，不能简化成固定优先级列表。高级动作还按21个武将 ID 白名单的不同后缀、等级和资源筛选；动作15有专门的 ID109（諸葛亮）门槛。

特别保留了原代码的：排序轮数来自未在函数内初始化的 scratch byte、相等值交换、距离 ADC 的 carry、多字节兵条件逐字节比较。动作15的兵条件是特定两个 byte 同时比较，不能替换为一般的 `兵>=700`。

环境 predicate 测试以显式 fixture 提供地形 resolver 的返回值；部分优先级测试直接控制 predicate。文档逐项列出替换边界。全局内政 AI、地形 class 的全部名称、所有行动的菜单联接和完整战场 state machine 尚未完成。

## 完整模拟器的动态证据

新增 `scripts/nes_runtime.py`，使用 [Nestopia libretro](https://github.com/libretro/nestopia) 的完整 NES 核心运行原 ROM，按保存的按钮计划进入原始标题、君主选择、世界地图和武器店属性列表。它与第一轮只模拟 CPU 的 py65 trace 是不同的证据类型。

核心版本 `Nestopia 2.0.0 135dfa6`，dylib SHA-256 为 `924191ebb41b863993a96cf461321058b391c507a6fed2f1203df44eaa5a539a`。输入 core 来自 libretro 官方构建站，来源记录在 [runtime README](../runtime/README.md)。为便于像素核对关闭复合视频滤镜/裁切，使用固定核心 palette；这不声称测得真实电视颜色或物理卡带行为。

![原 ROM 的属性列表](../runtime/military-selection.png)

原始属性页中的标签和曹操/于禁/夏侯惇各列可与 SRAM、ROM 记录联接。忠100的 `--`、经验1000显示20均得到动态对照。刘备选择页也与 ID222 的初始记录对应。

从冷启动串接全部输入步骤再次回放，标题、刘备详情、属性列表的像素均与保存状态继续运行结果一致。见 [完整输入计划](../runtime/replay-original-ui.json) 和 [回放验证](../runtime/validation.json)。截图来自原 ROM 模拟器运行，不是拼出的游戏画面；没有为了得到截图修改 ROM/RAM。

重跑需要本地 `.toolchain/nestopia/nestopia_libretro.dylib` 与 Pillow：

```sh
python3 scripts/nes_runtime.py '/Users/paulasmith/Downloads/三国志2超级版.nes' \
  --plan analysis/runtime/replay-original-ui.json --out analysis/runtime/replayed --label officer-list
```
