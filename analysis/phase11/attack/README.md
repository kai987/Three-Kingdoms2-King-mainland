# 阶段11：普通攻击场景的独立可读控制器

`source/recovered/attack_scene_controller.py` 恢复 physical14/15 的普通攻击场景控制。它包含 **11个主态、58个合法展开子入口（56个不同入口）、13张有界分发表的75个合法分派项**，并补入真正 NMI4 使用的 physical14 `$A000 → A00F` 外层调用。生产模块由具名状态、子状态和局部函数组成，使用直接 `if`、自然 `while` 与 generator 保存服务等待位置；运行时不读取 `program.json`、不解释 opcode / IR、不使用 PC→操作字典，也不回退到原 ROM CPU。

这些是根据原机器码恢复的源码，不是游戏的原始源码。寄存器形式保留了实际 flags、scratch、别名和调用栈效应。部分对象字段仍使用中性的地址 / 机械作用名，不据此新增未经确认的正式玩法名称。

## 调用协议

构造 `AttackSceneController(shared_memory, pinned_rom_bytes, services=None)`：

- `tick(registers=None)`：真实 NMI4 场景入口 `$A000`，包含外层参数卡、文本 worker 和 CHR 缓存更新。
- `tick_control(registers=None)`：直接从主分派入口 `$A069` 更新一次控制体。
- `run_entry(entry, registers=..., return_pc=None, seed_return=False, max_blocks=...)`：一次选择证据目录中的具名函数入口，然后执行其结构化正文。默认从**既有调用栈**推导真实返回 PC/SP；生产调用不默认植入返回哨兵。
- `resume()`：继续同一 generator 和同一共享内存，保留暂停的真实外部调用。

`registers` 具有 `a/x/y/p/sp/pc` 属性。`services(call)` 的 `call` 是独立 `BattleNMIServices.ServiceCall`，包含真实 target、return_pc、kind、输入寄存器对象、内存、入口银行和期望返回 SP。服务必须返回字典 `status='returned'`，并真实恢复正确的 PC/SP。缺失服务、`waiting/budget/blocked/failed/error`、只声称返回而未更新 PC/SP 的回调均停在 `dependency`，不会替服务弹栈或制造 RTS。source budget 返回 `budget`；关闭的预算正文不能以 `resume()` 假装结束。

每个普通 JSR 都写入原调用地址，局部 RTS 弹出已有地址。原代码用额外 PLA 产生的非局部返回也保留：调用点检查真实返回 PC，不强制继续原顺序。指令地址用于调用栈、诊断和字节出处；它们不是运行时调度 opcode 的程序计数器。

`seed_return=True` 仅是明确开启的 `$0200` CPU fixture 便利选项。完整 NMI / 上层 scene 调用应传入其实际寄存器和既有调用栈；本轮验证脚本在 fixture 中直接准备原调用地址，不依赖该选项。

## 11个主状态

`$0540` 是主状态、`$0541` 是子状态，`$0542` 是另一个原控制字节。表位于 physical14 `$A06F`，只有11项，不能把某个 mask 的理论范围误当作额外合法入口。

| 主态 | 原入口 | 子入口数 | 具名控制作用 |
|---:|---|---:|---|
| 0 | `$A085` | 5 | 等待切景、初始化控制数组、显示双方信息 |
| 1 | `$A15F` | 3 | 阵列对象轮换、动作类别扫描、回合检查 |
| 2 | `$A4F7` | 11 | 当前对象的行动、碰撞、数值和结果推进 |
| 3 | `$AA23` | 5 | 当前参与方菜单与保存状态的恢复 |
| 4 | `$A3BC` | 7 | 结果确认、体力 / 退出结果及返回战场；子态2与6共用 `$A3F2` |
| 5 | `$CD43` | 3 | 单挑准备、global7交接及结果回读 |
| 6 | `$CE25` | 4 | 第一参与方阵形选择 |
| 7 | `$CF67` | 5 | 第二参与方阵形选择及进入对象准备 |
| 8 | `$ACC5` | 5 | 知力派生参数及对象动作选择 |
| 9 | `$B1EC` | 4 | 对象动画、碰撞和处理推进 |
| 10 | `$D6BA` | 6 | 单挑转移的交互确认；子态2与3共用 RTS `$D72A` |

此外 `$AF17` 有6项对象动作分派，已逐项包含在源和75个分派 CPU 病例中。完整表字节、地址、目标和 SHA256 位于 `evidence.json`。`catalog.json` 保存172个具名 procedure 的入口、节点、源码行数和循环信息，以及全部原指令位置。

真实外层 `$A000 → A00F` 先执行 `$C01B`：按 `$005E` 时钟和 `$0544` 背景选择更新10个 CHR 缓存字节；接着清 `$057B`、进入 `$A030`。主态0/1/2在控制体前调用 selector `$39` / `$A000` 绘制双方参数卡；其余直接进入 `$A069`。控制体返回后，外层保存 `$0081`，临时用 `$057B` 作为输入，调用 selector `$3D` / `$A003` 真实文本 worker，再恢复原 `$0081`。此调用不是默认完成文本或按键。

## 六段单独高层化的算法

初始化 `$A095..A0D2` 仅在真实 `$0087` 符号位就绪后推进：main6/sub0，清 `$0550..0557`、`$0574..0577`、扫描字节 `$0548`，再完整调用 `$C926`。这次不再停在旧的 `$A0CF` 前缀。

`$C926..C990` 分别读取 `$0560/$0561` 的武将记录，生成双方的武力 / 装备参数与 `floor(知力/13)`。生成字段为 `$056A/B,$04C1/2`、防具修正 `$056E/F`、武器修正 `$0570/1`、知力商 `$0572/3`。指针和除法仍遵循各自真实服务的寄存器 / scratch 协议。

`$C991..CA1E` 的武力系数阈值依次为50/65/80/87/92/97，系数45/45/50/55/60/65/70；重复45保留。先乘除计算基数，再真实抽取 RNG 低半字节，拒绝9..15，接受0..8后施加 `+9-draw` 字节偏置。装备来自武将 byte10：低5位查 `$CA1F` 武器修正表，高3位查 `$CA37` 防具修正表。源码保留整数截断、carry、回绕、随机消耗与返回 A/X/Y。

`$C064..C1CC` 根据对象类别、两轴字节距离和随机平局决定先尝试的方向；失败只尝试另一轴，保留 `$0012` 次数和零距离随机符号。它不是完整地图寻路。`$C20F..C30E` 以随机轴和符号依次探测四邻，轴切换才再次抽符号；原 clear-carry 且非零碰撞码决定是否接受。

`$C30F..C826` 在随机轴 / 符号上按距离1..6检查射线。邻接对象和地形可以阻断射线，只有距离2及以上可形成这个目标结果，距离5/6需相应 `$0575` 半字节允许。目标、编码距离和方向写 `$054D/$0548/$0549`。原负水平失败路径 `$C466 JMP C44C` 重新进入自己的失败检查，可能跳过正水平方向；源码明确保留了这个异常，没有改成理想的四向搜索。

其余控制路径也均为直接结构化函数。没有用不透明的原入口描述代替这些正文；但正文调用的共享硬件、渲染、队列、随机与算术服务仍是显式依赖。

## 验证结果与准确边界

当前 **780次原 ROM CPU 对照、11项源 guard、0失败**：

| 原 CPU 对照 | 次数 |
|---|---:|
| 11主态的全部58个合法子入口，buttons0/1/2 | 174完整返回 |
| 同样输入经真实 NMI4 `$A000` 外层 | 174完整返回 |
| 无外部服务的对应控制调用 | 143真实首依赖前缀 + 31无需依赖即返回 |
| fade 和武力阈值边界，完整 `$A095 → C926` | 75完整返回 |
| 13张分发表的所有合法分派项 | 75完整返回 |
| 三个独立轴向 / 射线算法的双侧、类别、目标距离和 RNG 输入 | 108完整返回 |
| **合计** | **637完整返回 + 143严格前缀 = 780** |

每例比较全部 **2,048B RAM（包含完整栈页）**、全部 **8,192B SRAM**、A/X/Y/P/SP/PC、端口写入的完整顺序、最终 PRG 银行。验证 Bus 的 PPU 寄存器 / VRAM 请求镜像也逐例一致；这只是声明的合成硬件输入下的数据镜像，不是实际 NES 画面验证。

验证器执行原 helper 的回调共有 **2,429次**，逐个记录目标 / 银行 / 原返回地址。它们只属于验证适配器，生产源码没有原 CPU fallback。完整返回病例证明独立控制体和真实服务边界组合的等价性，不把外部 helper 本身算作在此文件独立恢复。无服务的143项前缀到相同原 target、PC/SP、全部 RAM/SRAM 和端口边界停下，未使用成功 stub。

基础 fixture 来自旧阶段3原核心准备的普通攻击菜单，其中已有一处明确相邻敌方坐标准备。本轮另外控制主 / 子态、双方武将 / controller、数组、fade、RNG、buttons和原调用地址。PPUSTATUS 是有说明的交替字节输入，APU / 手柄硬件默认0；没有新生成视频帧、PCM、中断周期或自然核心玩法回放。buttons / 文本等待值是病例输入，不是生产代码默认 ack。

静态闭包为 **5,233条原指令、12,301字节指令字节**，包括旧5170条及真实外层新增63条。此次动态实际触及 **3,362条**；其余 **1,871条未动态覆盖**，不能把所有合法状态入口均比较过描述为全部分支验证完毕。源使用直接结构化控制与6段语义重写；静态分析记录和生产代码没有共享一个运行时 opcode executor。

## 字节出处与复现

`original-ranges.asm` 对全部静态指令保存正确的 physical bank、CPU地址、原字节和文件偏移。`evidence.json` 另保存8段重要代码范围、13张分发表与武器 / 防具 / CHR数据表的完整字节和 hash。`$A000..A068` 证明范围中也包含音频等其他 export stub；本控制器恢复的是实际 `$A000` 外层，未把其中 `$A003 → D8D4` 音频 parser 重新并入控制器。

旧 `analysis/attack_fsm/handlers.asm` 的 physical14 文件偏移有 `-0x2000` 误标：例如 `$A069` 写成 `$1A079`，真实为 `$1C079`。旧冻结文件保持不改；本轮字节证据统一按 `16 + physical_bank*8192 + (CPU & $1FFF)` 计算，包含16字节 iNES header，并验证每个旧分析指令的完整原字节。

```sh
.venv-trace/bin/python scripts/analyze_attack_scene_controller.py '/Users/paulasmith/Downloads/三国志2超级版.nes'
.venv-trace/bin/python scripts/verify_attack_scene_controller.py '/Users/paulasmith/Downloads/三国志2超级版.nes'
```

先分析生成可读源码 / 目录，再验证。若最后刷新 `evidence.json` 的回执摘要，可再次运行分析脚本；同一输入不会改变生成的生产源码。`validation.json` 的 source_sha256 字典 pin 源、分析器、验证器及 ServiceCall 依赖；原 ROM 摘要保持不变。
