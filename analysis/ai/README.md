# 战术 AI：可读行为重建与原 ROM 验证

已恢复 PRG bank 8/9 中具体的战术候选筛选、目标排序、动作优先级、特殊武将白名单、相邻单位扫描，以及 16 个动作适用条件。可读代码在 `source/recovered/ai.py`；它表达实际 ROM 行为，不是原作者源代码，也不构成完整游戏或完整战略/内政 AI。

属性名称依据并行字段分析所恢复的详情/列表模板及完整模拟器属性列表：武将 byte1=武、byte2=知、byte3=忠，byte8/9 低 10 位=兵，byte11 高 4 位=经验等级。排序及部分判断直接读取原始 byte9，不自行套用显示时的 `&3` 掩码。

## 入口与调用链

当前静态 CPU 映射：`$A000–$BFFF → physical bank8`，`$C000–$DFFF → bank9`，`$E000–$FFFF → fixed bank31`。本页文件偏移均包含 iNES 的 16 字节头。

- bank8 `$A000` / 文件 `0x010010` 的 JMP 进入 `$A02D` / `0x01003D`。它看 `$6F8B` 控制标记，遍历 20 个槽位，跳过 `$0664[slot]=$FF` 和符号位不属于当前方的单位，把当前槽写 `$6F8C`。
- `$A099` / `0x0100A9` 根据 `$6FA1[slot] & $0F` 选择策略 handler。`$A0A1` 起有 8 个指针，目标为 `A0B1,A105,A166,A210,A2AD,A329,A507,A606`；策略类型的游戏名称仍未确认，未假定所有低 4 位都有效。
- 基础选择 `$A95C` / `0x01096C`：读取当前武将的知 → `$A8D3` 范围候选 → `$AE93` 目标排序 → 对每个目标调用 `$A9CF` → 首次成功写 `$6F8D=动作,$6F8E=目标槽,$6F8F=2`；无可行目标时 `$6F8F=3`。
- 特殊选择 `$AAF8` / `0x010B08`：先要求知≥92、经验等级≥3，再扫描候选并用 `$AB68` 的武将白名单/等级规则选择动作。

`$B517` / `0x011527` 是自定义的内联 dispatch helper，弹掉 JSR 返回地址，从返回地址之后的指针表按 `2*A` 取地址，恢复 Y 并跳转。`$AC7B` 使用它跳到 16 个动作 predicate。直接线性反汇编会把这些指针当成 6502 指令；`routines/strategy_dispatch.asm` 与 `routines/action_suitability.asm` 已把真实指针标记为 `.word`。

REA 对该 bank pair 的伪代码在 `analysis/rea/pairs/pair-08/`；自动结果作为辅助线索。本页的恢复与验证直接依据原 ROM 6502 指令，修正了自定义返回地址/内联指针行为造成的自动分析缺口。

## 候选与目标排序

`$A8D3` / `0x0108E3` 读取 `$0600[20]` 的 X 和 `$0614[20]` 的 Y；Y≥16 先减 1。每个轴的距离都必须≤传入 radius，因此基础战术 radius=5 的范围是方框。`$A944` / `0x010954` 比较 `$0504` 与 `$0628[slot]` 的 bit7，相反时标记 `$80`，相同时标记 0。

精确保留一个 carry 细节：Y 距离与 radius 的 CMP 后，代码直接 ADC X 距离，没有 CLC。所以当 `dy==radius` 时，候选低位权重是 `dx+dy+1`。例如 actor(10,10)、target(11,15)、radius5 的敌方候选是 `0x87`，不是 `0x86`。该权重不改变这段方框的入选条件。

`$AE93` / `0x010EA3` 只保留候选中 bit7=1 的槽，随后按武将 **原始 u16(+8,+9)** 做相邻交换：右值≥左值就交换，形成降序，优先考虑原始兵字段更大的目标。相等也交换，因此不是稳定排序。

还必须保留 `$002F` 输入：该函数没有初始化排序次数。counter0 只走一遍，可能只形成部分顺序；counter 足够大才完全排序。可读代码没有悄悄把它替换成 Python `sorted()`，并验证了 counter0/1/2/128/129/255 等边界。

## 基础动作选择

知值在 `$A965` / `0x010975` 量化为以下 tier：

| 知 | tier |
| --- | --- |
| <40 | 1 |
| 40–59 | 3 |
| 60–74 | 5 |
| 75–84 | 7 |
| ≥85 | 9 |

`$A9CF` / `0x0109DF` 针对一个目标，按以下顺序尝试。`$0505` 是资源/行动余额候选；表中只是**进入判断的门槛**，不能直接当成实际消耗值。

| 顺序 | 动作编号 | tier 门槛 | `$0505` 门槛 | 额外条件 |
| --- | --- | --- | --- | --- |
| 1 | 6 | ≥6 | ≥8 | 目标原始兵字段非零，predicate通过 |
| 2 | 5 | ≥5 | ≥8 | predicate通过 |
| 3 | 8 | ≥8 | ≥10 | predicate通过 |
| 4 | 9 | ≥9 | ≥9 | 目标原始兵字段非零，predicate通过 |
| 5 | 7 | ≥7 | ≥8 | 目标原始兵字段非零，predicate通过 |

之后先检查动作1的 predicate。若可行，从 AI 随机表取低 2 位，拒绝 0；目标无兵时还拒绝 3。随机值1可选动作2（tier≥2、目标 `$0650` 低4位=0、资源≥4）；随机值2可选动作1（资源≥5）；随机值3可选动作3（tier≥3、目标有兵、资源≥6）。

若随机分支不满足门槛，继续动作4（tier≥4、有兵、资源≥7），最后动作0（有兵、资源≥6）。这些都必须通过对应 predicate；全失败则写状态3并返回 carry0。

## 特殊动作与武将白名单

`$AC31` / `0x010C41` 从 `$AC65` / `0x010C75` 的 21 个 ID 中扫描，至 FF 结束：

```text
161,99,167,22,196,219,234,107,206,235,183,24,55,112,213,110,103,197,86,93,109
```

`$AB68` / `0x010B78` 保留真实优先级：

| 动作 | 武将 ID 限制 | 等级 | 资源门槛 | 额外条件 |
| --- | --- | --- | --- | --- |
| 10 | 全21 ID | ≥3 | ≥9 | 目标 `$0650` 低4位=0 |
| 11 | 全21 ID | ≥3 | ≥10 | — |
| 12 | 名单从 index11 开始的10 ID | ≥4 | ≥10 | 目标有兵 |
| 13 | 同上 | ≥4 | ≥8 | 目标有兵 |
| 14 | 名单从 index17 开始的4 ID | ≥5 | ≥12 | 目标有兵 |

所有动作仍须通过 predicate。ID109 的名称原字形是「諸葛亮」，可直接核对 `analysis/assets/names/name-109.png`。这是由代码白名单与名称图形共同支持的限定，动作15的中文名称仍待对应菜单/效果证据，不以三国故事或其他版本规则代填。

## 16 个适用 predicate

`$AC7B` / `0x010C8B` 先查询目标/施术者的地形 class，再通过 `$ACAE` / `0x010CBE` 的 16-entry 指针表分发。地形查询 `$B6E5` 把 raw class≥6 转成2；class 的具体地形中文名尚未建立，因此保留编号。

相邻扫描 `$A837` / `0x010847` 按上、下、左、右返回四个槽；无单位为 FF，有单位时其 bit7 仍相对于 `$0504` 标识对方。下表中“bit7邻居”指非FF且bit7=1的邻居，不擅自把它转换成相对于目标的阵营名称。

| 动作 | predicate CPU / 文件偏移 | 实际条件 |
| --- | --- | --- |
| 0 | `$ACCE` / `0x010CDE` | 目标 class∈{0,2} |
| 1,2,3 | `$ACDB` / `0x010CEB` | 目标 class∈{0,4} |
| 4 | `$ACE8` / `0x010CF8` | 目标 class=3 |
| 5 | `$ACF3` / `0x010D03` | 目标槽为0或10 |
| 6 | `$AD00` / `0x010D10` | 目标 class=5；其四邻居某个低7位等于actor槽 |
| 7 | `$AD22` / `0x010D32` | 目标 class∈{0,4}，且存在bit7邻居 |
| 8 | `$AD45` / `0x010D55` | 目标 class≠5，且目标忠<50 |
| 9 | `$AD65` / `0x010D75` | actor class∈{4,5}；目标与actor相邻且目标class=5 |
| 10,12 | `$AD92` / `0x010DA2` | 目标class=3，且存在class=3的bit7邻居 |
| 11 | `$ADCF` / `0x010DDF` | actor class=0，actor byte9非0或byte8≥100；`$04D8`/`$04DC`（由当前方bit7选择）为FF |
| 13 | `$ADFE` / `0x010E0E` | actor class=5；四邻居某个 `value XOR $80` 等于目标槽 |
| 14 | `$AE20` / `0x010E30` | 目标class≠5，且存在class≠5的bit7邻居 |
| 15 | `$AE5D` / `0x010E6D` | 目标class≠5，武≥85或知≥85；原始byte9≥2 **且** byte8≥188 |

动作15最后条件是逐字节检查，不能改写成“总兵数≥700”：原始兵768对应 `(hi=3,lo=0)`，会被这段代码拒绝。可读重建保留了这一行为。

## RNG 与验证范围

AI `$B5D5` / `0x0115E5` 使用 bank8 `$B5E5` / `0x0115F5` 的 256 字节排列及 `$6F92` 游标，返回当前表值后让游标加1并回绕。表的字节与 fixed-bank `$E8BA` 的排列完全相同，但游标独立。表 SHA-256：

```text
47502bec71a43116f27d80852f9598fa2013745d0aa794c2003046173d9fd09d
```

`validation.json` 中的 py65 oracle 执行**原 ROM 指令**与受控 RAM，逐项对比 Python 的返回状态、候选列表、目标/动作、随机游标及请求顺序。其替换依赖按每条结果明确列出：

- 友敌分类、知分档、范围候选、四邻居、排序、AI RNG、特殊门槛、白名单：没有替换子程序。
- 受控动作选择 fixtures：只替换 `$AC7B` 返回适用与否，以覆盖每个优先级/门槛分支；原始白名单、记录指针和 RNG 继续执行。
- 16 个 predicate 与另组完整 `$A95C` 流程：实际执行 `$AC7B`、自定义 `$B517` dispatch 和 `$A837` 邻居搜索，仅把 bank-backed `$B6E5` 的地形 class 作为外部 fixture 输入。

这证明了所列 CPU 行为与原字节的一致性，没有把地形查表、mapper/NMI时序、中文动作名、整局策略或完整AI游戏体验一起宣称已验证。
