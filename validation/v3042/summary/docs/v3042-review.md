# V3.0.4.2 验收结论

本轮把六处既有河流接岸做成独立河埠，覆盖三条河段、六个方向。每处装卸位 1 个、仓容 16,000 粮、每个装卸日上限 4,000 粮。29 个已发布剧本全部核对，174 条开局方向报价中 47 条可执行。真实地图的涪陵—巴东完成发运、移动、两次出入仓、目的城收粮和合法返程，保留批次与扣账。真实海陆接驳未验证。[地图与逐批实绩](replay-findings.md)

| 交付项 | 结论 |
| --- | --- |
| 技术与实体机制 | 通过真路线交割和原始检查点。仓储、权限、人员、运位、命令书及资源守恒专项通过。关闭设施时，旧规则的逐旬领域状态和随机数一致。 |
| 正式经济候选 | D0、D2＋30412 均未通过 24 个月经济门槛。最终 18 局自然观战没有接驳收粮，组合组对稳定规则另有 22 条警戒。保持默认关闭。 |
| 后续 V3.0.5 开发 | 可独立开展粮道安全专项。3634 的旧城市易主危险状态及 1860 的合法撤离问题继续作为证据，V3.0.4.2 不作为已冻结的经济基准。 |
| Git 代码交付 | 使用独立开发分支和验收归档分支。最新代码通过 GitHub 完整 CI，保留正式战役默认值。 |

在同条件涪陵—巴东样本里，直运、接驳均在原期限前实际收粮 12,603。真实到货为第 20 天和第 29 天，命令书 1 和 3，运输执行期武将日 40 和 49，口粮 672 和 1,008。接驳从源城预付整段口粮，巴东净增运输粮多 417。R03 进一步确认，当第二旬首次出现缺口并且直运在原期限不能交割时，自动接驳可于第 17 天实际送达 786 粮。[配对实绩](../data/controlled-lines.csv) · [真实自动发运](../../raw/mechanism/automatic-gate.json)

## 技术验证

最终引擎与验证工具运行于 `e21704834237279a962ee2109aef505e8f53ffc9`。代码与早期实验身份详见清单。[开发提交](https://github.com/kai987/Three-Kingdoms2-King-mainland/commit/e21704834237279a962ee2109aef505e8f53ffc9) · [独立 GitHub CI](https://github.com/kai987/Three-Kingdoms2-King-mainland/actions/runs/46127526260)

新功能的 Python、Rust 专项各 12 项通过，9 份受控事件日记的解压字节在两个后端完全相同。Node 66 项，Rust crate 16 项，跨 Rust／WASM 对照 24,689 向量。最终 Worker 实跑与 CPython 精确重放 81 次请求，包含实际发运后的部分在仓 839 粮及紧凑存档。桌面及 390×844 触控 Chromium 验证了真实报价、语言切换和实际发运。本地完整 UI 为 116 项，修正后最终源码的两项河埠用例独立复测，最新完整 CI 33 项工作通过。[技术明细](technical-details.md)

性能同背景增量在北方积雪为 +0.43%／−0.27%，在赤壁后期为 +1.03%／+0.52%。赤壁后期整个 D2＋30412＋设施组合相对稳定组的 P95 高 99.82%，因此保留警戒。[性能配对](../data/performance-pairs.csv)
