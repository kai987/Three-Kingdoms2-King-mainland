# 三國・大陸戰役

[日本語（主文件）](README.md) · **繁體中文** · [線上遊玩](https://kai987.github.io/Three-Kingdoms2-King-mainland/)

原版像素風格的 Web 戰略遊戲：29 個劇本（史實23個、假想6個）、最多 115 城、每城歷史武將與文吏合計 99 人、每方出戰 10 人、1,023 名歷史人物，繁體中文／日本語切換。每旬10日，城池與人物按年月登場，開局資源依劇本配置；四種主要場景使用原版配樂。

劇本選擇下拉框只分「史實」「假想」。新增198年3月「呂布討伐戰」、202年6月「河北爭亂」、211年7月「潼關之戰」、215年8月「合淝之戰」；原有同月「入蜀爭奪戰」保留為獨立劇本。原典確定年月與客軍在現有地圖上的代理配置分開記錄，見[追加劇本、史料與配置界線](docs/dlc-scenarios.md)。

新增4篇都在「史實」組。若仍使用讀入舊25篇資料後一直運行的本機8878服務，只重新整理畫面不會更新伺服器內的劇本；先確認已存檔，再使用最新版服務，或另開8879埠確認目前29篇。[舊服務與劇本檢查步驟](docs/island-history.md#追加dlcが選択欄に見当たらないとき)

線上版在每個瀏覽器分頁的 Worker 中執行相同戰役規則，無需開啟本機伺服器。首次需下載 Python／WASM 與劇本；關閉或重新整理前，請明確保存至瀏覽器、JSON 檔案或雲端槽位。新戰役建立、旬末、戰鬥結算及載入後，另在本瀏覽器保留最近3份自動恢復點；空間不足時可能減少份數。「讀取進度」可選擇恢復點，確認後才取代目前戰役。自動恢復點不覆寫手動存檔、不自動傳到雲端，並保留原始JSON存檔格式。靜態建置與部署方式見[線上發布](docs/web-deployment.md)。

靜態Web版顯示實際啟動階段與已讀取的遊戲資料位元組數（不含執行環境），獨立資源並行下載，一時性錯誤採有限重試。只有引擎首次就緒前能以重試按鈕重建Worker；遊玩中的中斷不自動重開戰役或重送寫入命令。

地圖視覺未變時復用SVG與相機，歸屬、日期、城名、路線或高亮等變化仍安全重建。瀏覽器的可選`view_cache`協定不重傳已知且不變的人物與劇本資料；行軍報價按資料集、玩家、月份、有效城池歸屬與發現航路失效，不改規則、亂數或存檔，也不代表所有路線計算均已快取。

地圖支援滑鼠拖曳、滾輪及觸控移動／縮放，倍率為100～400%。上方保留主要存讀操作，語言、勢力內政、人物庫、事件回顧、規則與音樂集中至「更多」；右側按劇本選擇／城池命令分組，小螢幕改為上下排列。陰平西側紅棕山腳與陰平—成都間綠峰的素材、修改範圍及原圖見[地形素材記錄](art/map-western-range-v3/README.md)。

地圖右下「名：主」依序切換主要城池、僅巨大都市、僅大都市、全部、不顯示；都市等級採所選年代的資料。寬螢幕頂部空間足夠時，戰報移到中央，地圖保持比例向下擴大，右側操作欄收窄；空間不足時戰報回到底部，保留地圖倍率與選城。

章陵從222年起顯示義陽，240年以後新開局撤去節點，進行中的既有戰役不刪城。劉表／曹操的開局歸屬、207年「三顧茅廬」保留劉備的使用者例外、臨江／宜都沿革與赤壁荊南四太守按年代配置；使用者指定月界與原典確年分開記錄，IF依劇情處理。詳見[城名、年代與歸屬](docs/city-history-rules.md)；[新增19城核查](docs/city-ownership-audit-20261024.md)逐一對照19個史實劇本共361項，並保留西北、雁門及交接月份的待考範圍。

朱崖、夷洲在全部29篇的開局仍為中立，介面以「島嶼地區（中立）」說明；中立不表示無人島。239年徐聞設郡的後出年記、242年7月朱崖與儋耳遠征、230年1月夷洲渡海，不足以確定本作海南／臺灣代理節點的持續占領月份。都市情報以繁中、日文區分原典時點、地圖映射及待考界線，不虛構守將或按曆年強制歸吳。玩家與AI實際占領後依戰局處理。詳見[兩島史料與本作設定（日文主文件）](docs/island-history.md)。

譙郡固定節點在219年以前顯示「小沛」，219年1月改顯示「譙郡」，221年1月由通常都市升為大都市，兩次切換各有附史實介紹的圖文事件。史實的小沛與譙是不同城池；這是使用者指定的地圖代理切換，不是同城改名。221年規模變更參考譙列曹魏五都的記載，都市等級與收入倍率仍是遊戲設定。長安、江州、吳、山陰為大都市，陳留、濮陽為通常都市，成都為巨大都市。建業在240年1月上旬升為巨大都市並顯示一次圖文事件；切換年份以後新開局直接採當時名稱與規模，不追發事件。開局資源與月收入依規模配置，進行中的升級只影響以後月收入，不補庫存、兵員或改變歸屬。

江夏—長沙可選陸路與內河水路。水路按長江、湘水及洞庭出口水系分段計算；江夏往長沙兩段均逆流，返程均順流。長江逆流20／順流50公里每日，湘水側逆流22.5／順流35公里每日；不套海路季風與暴風雨減員，仍按實際日數耗糧及處理斷糧。速度參考後代《唐六典》的載重船行程，公里換算與兩段模型為本作設定，不冒稱三國實測軍速。詳見[內河水路、流向與速度依據](docs/inland-navigation.md)。

行軍先備至下一座本方城的口糧，依友城實際庫存補給；途中無友城則備全程，空城不供糧。每日按當時兵數、隨行人數及運輸預備兵累計耗糧，等待補給、候城及會合也耗糧；缺糧暫停前進、每日各隊損兵1%向上取整，連續10日於旬末開始實際撤退，不殺武將。可從「前線支援」選本方在途部隊送糧，運輸隊到同一城市實際會合才交糧；押運武將保留原城席位，卸貨後自動返原城，永久增員請用調動。抵達開戰不重收已付出征費。詳見[行軍與兵糧](docs/hazardous-travel.md)。本次使用新的補給及運輸格式，更新後請建立新戰役。

```sh
python3 -B game/build_march_core.py
python3 -I -S -B game/serve.py --port 8878
```

開啟 http://127.0.0.1:8878/ 。需要 Python 3.10+；建置行軍核心需要 Rust 1.93.0 與 wasm32-unknown-unknown。遊戲執行不讀取 ROM 或模擬器。

目前只維護一套戰役資料，不載入舊版劇本或遷移歷史存檔。人物能力、歸城依據、原典與遊戲推定保留；舊版逐級生成器與相容目錄已移除。存檔仍驗證目前劇本、資料 SHA、狀態校驗和及回合版本，失敗不覆寫正在遊玩的戰役。

地方文吏使用 `clerk-000001` 類獨立 ID，不占1,023名歷史人物的 ID；雇用後可編兵、出戰、單挑、轉屬與繼承。玩家與 AI 共用民政官／軍備官委任、自動登用／勧誘、募兵訓練與真實前線運輸，遵守同一城市行動、費用、地形風險與亂數規則。都市情報顯示武、知、德、忠、經及體力；共51類圖文事件包含城名切換、都市成長、內政摘要、行軍補給、缺糧減員與自動撤退。

城池寶庫可儲存0–99份寶，支援搜尋、賣寶、太守任免及賞金／賞寶提升非君主武將的忠誠。玩家的全勢力自動賞賜預設關閉、可自行啟用；AI預設啟用，遵守同一全勢力預算、實際資源及城市行動限制。跨城運寶由實際押運隊沿路運送，抵達才入庫，滿庫等待或帶回，不提供即時轉帳。完整公式、上限與守恆規則見[寶庫與賞賜](docs/treasures-rewards.md)。本版增加寶庫及新版貨物格式，更新後請新建戰役。

城池的「設施與防災」提供醫館、市場、學問所、武器屋及城鎮發展，可治療、求學、買賣兵糧、購置裝備與整備修復。費用及效果範圍在確認前顯示，也可設定全勢力共用預算與自動方針。5、6月洪水及8、9月旱災僅在跨月檢查，災損會降低後續月收入，防災整備可修復；玩家與AI共用實際資源、行動與亂數規則。醫療50金、月份與四設施有官方說明書依據；學知、防災費率與療傷量參考公開FC程式分析，發生率、基礎損失、115城設施布局及城鎮1–3級是本作設定。[公式、來源層級與待考範圍](docs/facilities-disasters.md)均明列；原30城米價／門店只作證據，不直接套用。此版增加設施狀態，更新後請新建戰役。

武／知／德分別參考SAN14武力／知力／魅力，1,000人的德取魅力、23人缺來源設60，原始100保留但本作使用99；舊原版德及歷史評分留作證據，不覆蓋新政策，因此嚴顏目前77、劉備99。原版資料表可核對的223人採其初始體力，其他800人初始80；恢復上限為轉換前本作上限與新初值的較大者，不冒稱原版最大體力。普通武將僅在本局所屬符合來源明列勢力時採原表數字忠，否則80；在野0、君主內部100且顯示`--`。原表君主標記不套成普通將忠100，登用、轉屬、受傷與存讀仍按實際遊戲狀態處理。完整1,023人差異、983筆德變更及未綁定來源見[屬性來源與轉換政策](docs/officer-attribute-sources.md)。本輪不改29篇的日期、城池歸屬或人物配置，更新後請新建戰役。

戰場以1024×960畫布呈現，維持原版256×240的顯示比例。單挑提供12類兵器、13類坐騎外觀，27位具名人物另有來源或本作演繹設定；武器屋購入的兵器／防具會影響單挑攻防；名將兵器與坐騎外觀仍是人物演出，坐騎不另加能力。旗標通常顯示姓名首字，同一陣營有同姓武將時，僅該陣營該姓的旗標改顯示姓名末字；敵我分開判定，名單和情報保留全名。城池「訓練度」是駐軍訓練指標，與原版暫時戰術「士気向上」分開處理。

修改人物時使用穩定 `person_id`。`people.json` 保存共同人物，`scenarios/*.json` 只記錄各劇本差異；`build_campaigns.py` 完全離線，無須先生成任何舊版。共享資料及差異格式見 [建置說明](game/README.md)。

規則、介面夾具、真實WASM、瀏覽器操作與跨年戰役的命令及驗證邊界統一見[遊戲驗證與回放](docs/testing.md)。長期回放以184、217、263年三個劇本、各兩個種子對照Python／Rust後端，每月與繼承後核對存讀、亂數及兵員守恆；經濟成長、前線缺員及運輸停滯屬觀察資料，通過回放不等於已證明玩法平衡。
