# 三國・大陸戰役

**日本語** · [繁體中文](README.zh-TW.md) · [オンラインで遊ぶ](https://kai987.github.io/Three-Kingdoms2-King-mainland/)

原作のドット絵を生かした、ブラウザーで遊べる三国志戦略ゲームです。29本のシナリオ（史実23本・仮想6本）、最大115都市、1,023人の歴史人物を収録。内政と人材登用で国力を整え、陸路や沿岸航路から出陣し、計略や一騎討ちを交えて天下統一を目指します。画面は日本語と繁体字中国語に切り替えられます。

## オンラインで遊ぶ

**[ゲームを開く](https://kai987.github.io/Three-Kingdoms2-King-mainland/)**

シナリオ、難易度、勢力を選んで新しい戦役を開始します。地図上の都市を選ぶと、都市情報や武将の能力、実行できる命令を確認できます。

シナリオの選択欄は「史実」「仮想」の2分類です。「呂布討伐戦」（198年3月）、「河北争乱」（202年6月）、「潼関の戦い」（211年7月）、「合肥の戦い」（215年8月）を追加し、同じ211年7月の「入蜀争奪戦」も別シナリオとして残しています。史料で確認できる年月と、限られた地図で客軍を表すための配置は、[追加シナリオの資料と配置](docs/dlc-scenarios.md)で区別しています。

この4本はすべて「史実」にあります。旧25本版を読み込んだままのローカルサービスでは、画面を再読み込みしても一覧は増えません。現在の戦役を保存し、最新版を別ポートで起動するなどして29本を確認してください。[旧サービスと追加シナリオの確認手順](docs/island-history.md#追加dlcが選択欄に見当たらないとき)

- **地図の操作**：マウスのドラッグや指のスワイプで移動し、ホイールや2本指のピンチで拡大・縮小できます。表示倍率は100〜400％です。シナリオ選択中に所属都市をクリックすると、右側の勢力選択も切り替わります。
- **都市名の表示**：地図右下の「名：主」は、主要都市→巨大都市のみ→大都市のみ→全都市→非表示の順に切り替わります。都市規模は選択したシナリオの年代に従います。
- **上部メニュー**：メニューに戻る、セーブ、ロード、クラウドセーブを表示。「その他」に言語、勢力の内政、武将名鑑、イベント履歴、ルール、音楽設定をまとめています。
- **右側の操作欄**：開始前は勢力ごとの都市・武将・資源を、開始後は選択中の都市の情報と命令を表示します。小さい画面では地図の下に並びます。
- **広い画面**：上部に十分な余白がある場合は報告欄を中央へ移し、地図を下端まで拡大します。地図の縦横比を保ち、右側の操作欄を狭めます。画面が狭くなると報告欄は下部へ戻り、地図の倍率や選択中の都市を保持します。

オンライン版は、Pyodideを使ってPythonの戦役ルールをブラウザーのWorker内で実行します。初回はPython／WASMランタイムとゲームデータのダウンロードが必要です。読み込み中はバージョン情報の確認、データ取得と実行環境の準備、戦役ルールの初期化を表示し、取得できたゲームデータの累計量も確認できます（実行環境の転送量は含みません）。独立したデータは並行して取得し、一時的な失敗に限って回数を制限して再試行します。ゲームエンジンの初回準備完了前だけ「読み込みを再試行」でWorkerを作り直せます。準備完了後は自動で再起動したり、実行済みか不明な命令を再送したりしません。戦役はタブごとに独立しており、同時に開いた別のタブと進行は共有しません。

**ページを閉じたり再読み込みしたりする前に、「セーブ」で保存してください。** ブラウザー内の保存、JSONファイル、アカウント式クラウドセーブを利用できます。クラウドへの保存や読み込みは、プレイヤーが明示的に操作したときに行います。ログインしただけでは進行は保存されません。新しい戦役の開始、旬の終了、戦闘結果の確定、ロード後には、このブラウザーに自動保存の復元ポイントも作成します。復元は「ロード」で選び、確認してから実行します。

## ゲームの特徴

- **年代に応じた戦役**：184年から263年までの史実を参考にしたシナリオとIFシナリオを収録。武将の出生、仕官、退場時期、都市の登場年月、勢力の配置を分けて管理します。全人物が同じ年に登場するわけではありません。
- **都市名と歴史配置**：章陵は222年から義陽と表示し、240年以後の新規開始では節点を省きます。進行中の都市は削除しません。劉表・曹操の初期帰属、207年「三顧茅廬」の劉備例外、臨江から宜都への名称と帰属、赤壁の荊南四太守を年代別に設定。原典の年と本作で指定した月界を区別し、IFの領土はその物語に従います。[都市の年代規則](docs/city-history-rules.md)に説明しています。
- **朱崖・夷洲の史料**：全29本で開始時の中立所属を維持し、「島嶼地域（中立）」と表示します。239年の徐聞設郡、242年7月の朱崖・儋耳遠征、230年1月の夷洲渡海を、地図上の島全域の占領月と見なしません。海南・台湾方面への代理配置と史料の限界を都市情報に両言語で示し、未確認の守将や呉への自動移管は追加しません。[島嶼拠点の出典と扱い](docs/island-history.md)を参照してください。
- **都市名と規模の変化**：固定の譙郡拠点は219年より前は「小沛」、219年1月から「譙郡」と表示し、221年1月に通常都市から大都市へ成長します。両年の切り替えでは史料と本作設定を分けた画像付きイベントを表示します。史実の小沛と譙は別の都市であり、同じ都市が改称されたという意味ではありません。221年の発展は譙が曹魏の五都に数えられた史料を参考にしたゲーム設定です。長安・江州・呉・山陰は大都市、陳留・濮陽は通常都市、成都は巨大都市。建業は240年1月上旬に巨大都市へ成長します。初期資源と月収は規模に応じ、進行中の発展は以後の月収に反映します。在庫、兵員、所属は書き換えません。
- **武将と地方文吏**：都市の定員は歴史武将と雇用済みの地方文吏を合わせて99人。1回の戦闘に参加できるのは各陣営10人、武将1人の兵数は最大999です。地方文吏も編制、出陣、一騎討ち、所属変更、君主の継承に参加できます。
- **能力と開始時の値**：武・知・徳はSAN14の武力・知力・魅力に対応します。1,000人の徳は魅力から換算し、資料のない23人は60、元の100は本作では99として扱います。旧版の原作徳や歴史を参考にした評価は証拠として保存し、現在の換算を優先します。厳顔は徳77、劉備は99です。照合できた原作資料表の223人はその初期体力、残る800人は80で開始します。回復上限は旧本作の上限と初期体力の大きい方を使い、原作の最大体力とは断定しません。配下の忠誠は資料の所属勢力と本局の所属が合う場合だけ元の数値、それ以外は80。在野は0、本局の君主は内部100・表示`--`です。登用後の忠誠、負傷、継承、経は既存の規則で処理し、閲覧やロードで初期化しません。[出典と全1,023人の変更記録](docs/officer-attribute-sources.md)を参照してください。
- **勢力全体の内政委任**：民政官と軍備官を1人ずつ任命し、所属する全都市を管理。勢力共通の方針に従い、各都市の資源と行動回数の範囲で、商業・農業、自動登用・勧誘、募兵・訓練、前線への人員・物資輸送を行います。
- **宝庫と褒賞**：都市ごとに宝を0〜99個保管し、探索・売却、太守による賞金・賞宝で配下の忠誠を上げられます。プレイヤーの自動褒賞は初期無効、AIは初期有効で、同じ勢力共通予算・実際の資源・行動制限を使います。宝の都市間移動は護送隊が実際に運び、到着後に入庫します。[宝庫・褒賞・輸送の規則](docs/treasures-rewards.md)を参照してください。新しい保存形式のため、更新後は新規戦役から開始します。
- **施設と防災**：都市の発展に応じて医館・市場・学問所・武器屋を利用し、治療、学習、兵糧売買、装備購入、防災・被災後の復旧を行えます。費用と結果の範囲を先に確認し、勢力共通の自動方針も設定できます。5・6月の洪水、8・9月の日照りを月替わりに判定し、被災後の損傷は修復まで月収に影響します。公式説明書、公開FCプログラム分析、本作の発生率・115都市向け発展規則を[施設と防災の資料](docs/facilities-disasters.md)で分けています。プレイヤーとAIは同じ費用・行動・乱数の規則を使います。更新後は新規戦役から開始してください。
- **地形と季節を考える行軍**：距離、山地、陸海の経路、季風、陰平道や子午谷の危険が所要日数と損耗に影響します。次の自勢力都市までの兵糧を積み、途中で在庫から補給します。待機中も消費し、行軍部隊へ兵糧を届ける輸送隊も派遣できます。友軍都市への移動では、道路がつながっていれば無主の都市を経由できます。未知の沿岸航路の探索にも対応します。
- **江夏―長沙の水陸交通**：陸路と内河航路を選べます。内河は長江と湘水・洞庭出口の水系を区間別に計算し、江夏→長沙は上り、逆方向は下りです。速度は長江が上り20／下り50 km／日、湘水側が上り22.5／下り35 km／日。海の季風や暴風雨損耗は適用せず、兵糧は実際の日数で消費します。速度は『唐六典』の後代の行程を参考にした本作の換算で、三国時代の実測値ではありません。[根拠と計算](docs/inland-navigation.md)を参照してください。
- **戦闘と一騎討ち**：通常攻撃、16種類の計略、伏兵、一騎討ち、退却を実装。戦場は原作256×240の縦横各4倍にあたる1024×960で描き、表示比率を保ちます。兵士の対陣、12種類の兵器・13種類の馬の外観、攻撃・防御などの動作に対応し、演出はスキップできます。武器屋で購入した武器・防具は一騎討ちの攻撃・防御に反映します。名将の兵器・馬の見た目は人物別の演出設定で、馬の性能加算はありません。
- **3段階の難易度と共通ルールのAI**：初級・中級・上級を用意。難易度で進攻判断や協同攻城、計略評価が変わります。AIだけに資源や攻撃力を上乗せする方式ではなく、プレイヤーと同じ実行・費用・乱数ルールを使用します。
- **音楽と画像付きイベント**：原作の音楽・効果音を優先して使用。登用、継承、都市名の変化、都市の成長、行軍補給、兵糧不足、自動撤退など51種類のイベントを、地図や肖像とともに表示します。音楽は最初のクリックやキー操作後に再生され、BGM・効果音の音量調整と全体ミュートに対応しています。

1ターンは**1旬＝10日**です。各月は30日として、上旬・中旬・下旬の順に進みます。プレイヤーの戦略段階の後、AI勢力が順番に行動し、次の旬へ進みます。月収、回復、登場判定などの月次処理は月が替わるときに行います。

兵糧は日々の `兵数＋100×随行武将数＋輸送予備兵数` に応じ、端数を繰り越して累計で切り上げます。出発時は次の自勢力都市までを積み、途中に補給できる都市がなければ全行程分を積みます。無主の都市では補給できません。満員・補給・合流待ちの日も消費し、兵糧不足時は前進を止めて毎日1%の兵を失います（各隊で切り上げ）。10日連続で不足すると旬末に実際の帰路へ移り、武将本人は消しません。輸送隊は同じ都市で部隊に接触してから引き渡し、護送武将は荷下ろし後に出発都市へ帰還します。恒久的な異動は武将移動を使います。到着後の戦闘で出陣費を重ねて徴収しません。詳しくは[行軍と兵糧](docs/hazardous-travel.md)を参照してください。 新しい補給・輸送形式を使うため、更新後は新規戦役から開始してください。

戦場の旗印は通常、姓名の最初の1文字を表示します。同じ陣営に同姓の武将が複数いる場合、その姓の旗印だけを姓名の最後の1文字に変えます。敵味方は別々に判定し、名簿と情報欄にはフルネームを表示します。都市の「練度」は駐軍訓練の指標で、原作の一時的な戦術「士気向上」とは別に扱います。

肖像は人物IDにひも付けた128×160版を使用し、原画像も保存しています。地方文吏には3種類の共用肖像を用意しています。地図は原作のドット絵に合わせ、陰平西側の赤褐色の山裾と陰平―成都間の緑の山を調整しました。変更範囲と元の素材は[地形素材の記録](art/map-western-range-v3/README.md)で確認できます。

## ローカルで起動する

Python 3.10以降が必要です。以下はリポジトリのルートで実行します。ゲームの起動にROMやエミュレーターは不要です。

```sh
python3 -I -S -B game/serve.py --port 8878
```

ブラウザーで **http://127.0.0.1:8878/** を開きます。Pythonの標準ライブラリーだけで起動でき、Rustのネイティブライブラリーが未ビルドの場合はPythonの参照実装を利用します。オンライン版と同じ戦役ルールを、こちらではローカルのPythonプロセスが実行します。

行軍計算のRustネイティブ版とブラウザー用WASMをビルドする場合は、Rust **1.93.0**と`wasm32-unknown-unknown`ターゲットを用意します。

```sh
rustup toolchain install 1.93.0 --profile minimal --target wasm32-unknown-unknown
RUSTUP_TOOLCHAIN=1.93.0 python3 -B game/build_march_core.py
python3 -I -S -B game/serve.py --port 8878
```

行軍コアは経路・地形・季風・損耗の計算を担当します。戦役の状態、乱数、戦闘、保存はPython側が管理します。詳細は[Rust／WASM行軍コア](docs/marching-rust-wasm.md)を参照してください。

ローカルサービスは`127.0.0.1`だけで待ち受け、1プロセスで1つの戦役を管理します。クラウドにログインしても、複数人で同じ戦役を同時操作するサーバーにはなりません。サービスの境界は[実行環境と安全対策](docs/runtime-safety.md)に記載しています。

## ブラウザー版のビルドと公開

GitHub Pages向けの静的ファイルは、ローカルのPythonサーバーを常時起動せずに動作します。Node.jsとnpmを用意し、次の手順でプレビューできます。

```sh
npm ci --prefix tools/web-runtime --ignore-scripts
python3 -B game/build_web.py
python3 -m http.server 8890 --bind 127.0.0.1 --directory build
```

**http://127.0.0.1:8890/web/** を開きます。`file://`で直接開かず、HTTP経由で確認してください。生成先は`build/web/`です。`main`へのpushでは[共通の検証](.github/workflows/web-checks.yml)で規則、長期戦役、実際のブラウザー操作を確認し、[公開ワークフロー](.github/workflows/pages.yml)が、そのcommitで検証済みの同じ静的ファイルをGitHub Pagesへ配置します。公開ファイルの範囲、実際の配信内容の確認方法は[Web版の公開手順](docs/web-deployment.md)に記載しています。

## 保存とクラウドアカウント

「セーブ」ではブラウザー内への保存とJSONのダウンロードができます。自動保存は手動セーブとは別に直近3件を保持し、保存したゲーム日時と実際の保存時刻を表示します。ブラウザーの空き容量が不足する場合は保持件数を減らし、保存できなければ手動保存を案内します。復元前に確認し、ページを開いただけで現在の戦役や手動セーブを置き換えることはありません。自動保存にクラウドへの送信は含まれません。

「ロード」ではブラウザー内のデータやJSONファイルを選択します。現在のシナリオ、データのSHA、状態チェックサムなどを検証し、不正な保存データでプレイ中の戦役を上書きしません。旧版データの移行には対応していません。

クラウドセーブにはSupabase Authのメールアドレス／パスワードを使用し、1アカウントにつき5つの非公開スロットを用意しています。新規登録後は確認メールの認証が必要です。上書き・読み込み・削除は確認して実行し、複数端末からの古い操作が新しい保存内容を上書きしないよう、保存IDとリビジョンを照合します。

独自に運用する場合は、`supabase/`のテーブルとアクセス制御、`game/config/cloud-save-public.json`の公開設定、認証メールのSMTPと戻り先URLを設定してください。SMTPパスワードやSupabaseの管理用キーをフロントエンドに置かないでください。構成と検証範囲は[クラウドセーブ](docs/cloud-save-options.md)にまとめています。

## 開発と検証

地図は、兵の編制などで見た目が変わらない場合にSVGとカメラを再利用します。所属、年月日、都市名、経路、選択状態などが変われば再描画します。ブラウザー版の任意の`view_cache`通信では、変わらない人物の基本情報とシナリオ資料をタブ内で再利用し、現在の所属・所在・生存状態などを更新します。行軍見積もりの再利用は、カタログ、プレイヤー、月、利用可能な都市と所属、発見済み航路が変わると無効になります。すべての経路計算を省略する仕組みではなく、ルール、乱数、JSONセーブの形式も変更しません。

戦役データの編集元は`game/config/campaigns/`です。`people.json`に共通の人物情報を置き、`scenarios/*.json`にシナリオごとの差分を記録します。都市規模と成長年月は`game/config/city-scale-rules.json`を共通入力にします。人物を編集するときは、名前や配列の順番ではなく、安定した`person_id`を使用してください。

```sh
# 編集元と生成済みの戦役データを照合
python3 -B game/build_campaigns.py --check
```

規則の回帰テスト、画面操作のテスト用データ、実際のWASM実行、ブラウザー操作、複数年にわたる戦役の再現テストは[検証手順](docs/testing.md)にまとめています。長期テストは184年・217年・263年の3シナリオを各2種類の種子で進め、PythonとRustの結果、毎月と君主継承後の保存・復元、乱数、兵員の保存則を照合します。資源の増加、前線の人手不足、輸送の停滞は観察項目として記録し、テスト通過をゲームバランスの証明とはしません。

シナリオデータを変更するとデータのSHAも変わります。保存データは現在のカタログSHAとの一致が必要で、変更前のデータセットの保存は読み込み・移行しません。生成手順は[操作とビルド](game/README.md)、CIの検証項目は[Web campaign checks](.github/workflows/remake.yml)を参照してください。

## 実装範囲と資料

現在のゲームは、原作の表示や調査結果を参考にしながら構築した独立したWeb版のルールで動きます。実行時にNESのCPUやROM、逆解析用の制御IRを動かすものではなく、原作全体の逆解析完了や全挙動の一致を示すものでもありません。

人物の能力・所属・年代は、原作の確認済みデータ、史料、『三國志14』などの参照資料、本作向けの推定を区別して記録しています。史料がない配置や能力を、史実として扱わない方針です。AIは外部の生成AIを呼ばず、保存された戦役状態を基に決定するルール方式です。外交同盟交渉、マス目単位の戦術移動、史実の勝敗を強制する歴史イベントは実装していません。
